## 3. Obeya ของ ESM ควรเป็นอะไร — 3 อย่างที่จอเดิมทำไม่ได้

### 3.1 มองตาม "แกน SQDCM" ไม่ใช่ตาม "ส่วนงาน"
จอที่มีทุกใบตัดตาม**ส่วนงาน/ไลน์** (ใครรับผิดชอบ) · Obeya ตัดตาม **S-Q-D-C-M** (ลูกค้า/ผู้บริหารมองอะไร)
แกนเดียวกันดึงจากหลายส่วนงานมาชนกัน — เช่น "D ส่งมอบพลาด" เห็นพร้อมกันว่าเกิดจาก
เครื่องหยุด (MTN) · ของเสีย (QA) · คนไม่พอ (HR) · ของไม่มา (Store)

### 3.2 เทียบ "เป้า vs จริง vs แนวโน้ม" ในระดับที่ประชุมบริหารใช้ตัดสินใจ
จอเดิมตอบ "ตอนนี้เท่าไหร่" · Obeya ตอบ **"ห่างเป้าเท่าไหร่ · ดีขึ้นหรือแย่ลง · พอไหมถึงสิ้นเดือน"**
ฐานมีแล้ว: `oee_targets` (11 กลุ่ม) + `avgOeeTarget()` + เด็ครายเดือน (.pptx) ที่เพิ่ง**ใส่ Target ครบทุกสไลด์** 10/09

### 3.3 🎯 หัวใจ — ลูปปิด countermeasure ที่ตามได้จริง
> **ถ้าทำได้ข้อเดียว ให้ทำข้อนี้**

จาก "ตัวเลขหลุดเป้า" → **ใครรับ · ทำอะไร · ภายในเมื่อไหร่ · ปิดหรือยัง · แล้วตัวเลขดีขึ้นจริงไหม**
ของที่มีอยู่แล้วและต่อได้ทันที:
- `meeting_action_items` — โครงครบ (`ref_kind`/`ref_id` ผูกที่มา · assignee · due_date · status) **แค่ไม่มีคนใช้**
- `notifications` + `list_mention_users` — แจ้งเข้ากระดิ่งคนที่ถูกมอบหมาย
- `improvements` — วัดผลก่อน/หลังจากข้อมูลจริงอัตโนมัติ (แต่มีแค่ 6 แถว)
- ลูปปิด 8D → PFMEA/PFC/CP (`docs/CLOSED-LOOP-8D-PE.md` เฟส 1-4 ครบแล้ว)

## 4. โครงที่เสนอ — `/obeya` 1 หน้า 5 แผงตาม SQDCM + 1 แถบ action

```
┌──────────────────────────────────────────────────────────────┐
│  OBEYA · <ช่วงเวลา>        [วัน|สัปดาห์|เดือน]  [ส่วนงาน ▾]  │
├──────────────────────────────────────────────────────────────┤
│  S ความปลอดภัย │ Q คุณภาพ │ D ส่งมอบ │ C ต้นทุน │ M คน       │
│  ─ เป้า/จริง/Δ ต่อแกน · ไฟสี · เส้นแนวโน้ม 6-12 งวด ─        │
├──────────────────────────────────────────────────────────────┤
│  🔴 แกนที่หลุดเป้า → "ทำไม" (เจาะ 3 อันดับ) → [➕ ตั้ง action]│
├──────────────────────────────────────────────────────────────┤
│  📋 ACTION BOARD — open / doing / เกินกำหนด / ปิดเดือนนี้      │
│     แต่ละใบ: ที่มา(ลิงก์กลับ) · ผู้รับ · due · ผลลัพธ์ที่วัดได้ │
└──────────────────────────────────────────────────────────────┘
```

**กฎที่ต้องทำตาม (จากบทเรียนในโปรเจคนี้):**
- **อ่านอย่างเดียวยกเว้นแถบ action** — แผง SQDCM ห้ามมีปุ่มแก้ข้อมูล ทุกตัวเลขลิงก์กลับหน้าที่ทำงานจริง
- **ลิงก์ต้องพาไปถึงตัวงาน ไม่ใช่หน้ารวมเปล่า** (กฎเดียวกับ dept-dashboard — เคยโดน user ทักมาแล้ว)
- **ห้ามคำนวณ KPI เอง** — OEE ผ่าน `wavg`/`avgOeeTarget` · DT นับเฉพาะนอกแผน · PPM สูตรเดิม
- **แกนที่ข้อมูลยังไม่พร้อม ต้องเขียนบอกว่า "ยังไม่มีข้อมูล" ห้ามโชว์ 0 หรือซ่อนแผง**
  (กฎเหล็ก: *จอที่ยืนยันสิ่งที่ไม่จริง แย่กว่าจอที่ว่าง*) — S กับ Q จะโดนข้อนี้เต็มๆ
- **`useLiveBoard`** สำหรับ realtime/poll ห้ามประกอบเอง (กฎเหล็ก DB ข้อ 8)

## 6. ลำดับที่แนะนำ (คุ้ม ÷ เสี่ยง)

**เฟส 1 — ทำลูปให้เดินก่อน (ไม่ต้องมีหน้าใหม่)** ⭐ แนะนำเริ่มตรงนี้
ขยาย `meeting_action_items` + เอา Action Board ไปแปะใน `/morning-meeting` และ `/oee-analytics`
ให้หัวหน้าเริ่มบันทึก action จริง · **ถ้า 2 สัปดาห์แล้วยังเป็น 0 แถว = ปัญหาคือ process ไม่ใช่เครื่องมือ**
หน้า Obeya สวยแค่ไหนก็ไม่ช่วย — รู้เร็วดีกว่าสร้างเสร็จแล้วร้าง

**เฟส 2 — `/obeya` แผง D + C + OEE** (ข้อมูล 🟢 พร้อม) + Action Board เต็มรูป

**เฟส 3 — แกน Q** พร้อมกับดัน `defect_logs` ให้ถูกบันทึกครบ (179 แถวยังใช้ตัดสินใจไม่ได้)

**เฟส 4 — แกน S** ต้องสร้างทะเบียนอุบัติเหตุก่อน

**เฟส 5 — โหมด TV / โหมดประชุม** (reuse pattern จาก `/morning-meeting`)

## 7. ก่อนเริ่มลงมือ ต้องตัดสินใจ 3 เรื่อง (ถาม user)

1. **Obeya คือ "ห้องประชุมบริหารรายสัปดาห์/เดือน" หรือ "จอแขวนในห้อง Obeya จริง"** —
   คนละของกัน: อย่างแรกเน้นลูป action + เจาะสาเหตุ · อย่างหลังเน้นฟอนต์ใหญ่ อ่านจากไกล ไม่มีปุ่ม
2. **เริ่มที่เฟส 1 (ลูป action ก่อน) ตามที่แนะนำ หรือข้ามไปทำหน้า `/obeya` เลย**
3. **แกน S (ความปลอดภัย) เอาด้วยไหม** — ถ้าเอา ต้องสร้างทะเบียนอุบัติเหตุ/near-miss ใหม่ทั้งชุด
   (ตอนนี้มีแค่ PPE + BBS ซึ่งเป็น "พฤติกรรม" ไม่ใช่ "เหตุการณ์")
