## 🔴 บั๊กที่ทำให้ต้องมีไฟล์กลาง (26/10)

`/register` **ไม่เคยเขียน `staff_kind` เลย** ตั้งแต่มีคอลัมน์นี้ (21/09) ⇒ ตกไปที่ `default 'shopfloor'`

⇒ QA · วิศวกร · ธุรการ · สโตร์ ที่ถูกลงทะเบียนทางนั้น **ถูกนับเป็นกำลังคนหน้าไลน์เงียบๆ**
(เข้าแผงสกิล · เข้าตัวหาร manpower ของไลน์ · เข้า turnover — ดู `staffKind.js` §แกนที่ 1)
สังเกตไม่ได้จากจอไหนเลย เพราะคอลัมน์ไม่ได้ว่าง มันมีค่าที่ "ดูปกติ"

**บทเรียน:** คอลัมน์ `not null default` + ทางเข้าหลายทาง = คลาสบั๊ก "ค่าเริ่มต้นเงียบ"
ทางที่ลืมเขียนจะไม่ล้ม ไม่เตือน และได้ค่าที่ดูถูกต้อง ⇒ **ต้องบังคับเขียนทุกครั้งผ่านตัวประกอบแถวตัวเดียว**

## กฎ

1. ทุกทางเข้าประกอบแถวด้วย **`newEmployeeRow({...})`** — เพิ่มคอลัมน์ใหม่ = เติมที่นั่นครั้งเดียว
2. `staff_kind` **ต้องอยู่ในแถวเสมอ** ไม่ส่ง = `'shopfloor'` (ตรงกับ default ของคอลัมน์ เจตนาชัด)
3. **สายสนับสนุน = `line_id`/`team`/`group_name` เป็น `null` เสมอ** — `newEmployeeRow()` ตัดให้
   และ**จอต้องปิดช่องนั้นด้วย** ไม่งั้นจอสัญญาอย่าง ฐานเก็บอีกอย่าง
4. ข้อความอธิบายใต้ตัวเลือกประเภท อ่านจาก **`staffKindHint()`** ห้ามเขียนคำอธิบายชุดที่ 2 ในหน้า
5. insert ต้องผ่าน `checkWrite()` (กฎการเขียน DB ข้อ 1) — เดิม `/register` ใช้ `throw` ในก้อน try
   ซึ่งไม่เงียบ แต่ไม่เข้าชุดเดียวกับหน้าอื่น

## ✍️ ลายเซ็นพนักงาน + "รหัสพนักงาน → ผู้เซ็น" (2026-11-03 · ประชุม 02/11 C1)

เจ้าของกฎ **`src/utils/employeeSignature.js`** (มีเทส) — ใช้กับเอกสาร export ที่รู้ "รหัสพนักงาน" ของผู้ตรวจ
(สแกน QR บนบัตร = รหัสล้วน ชุดเดียวกับเช็คชื่อ · ผู้รับเหมาไม่มีบัตร/บัญชี = พิมพ์รหัสเอง)
- `signerFromRows(code, rows)` — จับคู่ **ตรงเป๊ะหลัง `normBadgeCode`** เท่านั้น · สถานะ `ok` / `no_signature` /
  `not_found` / `ambiguous` (รหัสซ้ำ = ไม่เดา) / `no_code` / `unknown` (อ่านไม่ได้/คอลัมน์ยังไม่เปิด) · ทุกสถานะมี `note` ให้จอเขียน
- `loadEmployeeSigners(client, { codes, ids })` — 42703/PGRST204 = ถอยไปโหลดแบบไม่มีลายเซ็น + ธง `sigColumnMissing` · error จริง = คืน `error`
- `signatureOfPerson({ profileSig, employeeSig, stored })` — ลำดับลายเซ็นทั้งระบบ (ห้ามเรียงเองในหน้า)
