## 📱 ส่งแท็บเล็ตวนเซ็น + บีบรูปลายเซ็น (2026-10-28 · คำสั่ง user)

### ทำไมต้องทำ — ของมีอยู่แล้วแต่ไม่มีใครใช้

วัดจากของจริง 28/10: ใบในระบบ **72 ใบ · รายชื่อ 524 คน** แต่ **เซ็นบนจอจริงแค่ 10 คน (2%)**
⇒ หน้างานยังปริ้นใบไปเซ็นมืออยู่ **ปัญหาไม่ใช่ "ไม่มีช่องเซ็น" แต่เป็น flow ช้ากว่ากระดาษ**

ของเดิม: กดเข้าแถว → เปิดโมดัล → เซ็น → **อัปขึ้นเน็ตทันที** → ปิด → กดแถวถัดไป
9 คน = กด 9 รอบ รอเน็ต 9 ครั้งบนแท็บเล็ตหน้างาน · กระดาษส่งต่อกันเซ็นเร็วกว่ามาก

### สิ่งที่ทำ

**โหมดวนเซ็น** (`SignQueueModal` ใน `src/pages/OjtTraining.jsx`)
· ปุ่ม "📱 ส่งแท็บเล็ตวนเซ็น (N คน)" เหนือตารางรายชื่อ — ตั้งต้นที่ **คนที่ยังไม่เซ็น**
· ชื่อขึ้นใหญ่ + รหัสพนักงาน (คนที่รับแท็บเล็ตต่อต้องรู้ทันทีว่าช่องนี้ของตัวเองไหม)
· ตัวนับ "คนที่ 3/9 · เซ็นแล้ว 2" · ปุ่ม **ข้ามคนนี้** (คนไม่อยู่/ลาป่วย)
· 🔴 **เก็บ blob ไว้ในเครื่องก่อน อัปทีเดียวตอนจบ** — เน็ต N รอบ → 1 รอบ
· 🔴 **ปิดกลางคัน = ของที่เซ็นไปแล้วยังถูกอัป** (ปุ่มเขียนว่า "หยุดแล้วบันทึก N ลายเซ็น") ห้ามทิ้งเงียบ
· 🔴 **อัปล้มบางคนต้องบอกเป็นชื่อ** — "บันทึกแล้ว" ทั้งที่ขาด 3 คน = ต้องมาตามหาทีหลังว่าใคร

**โค้ดวาดเส้นมีชุดเดียว** = `SignCanvas` (forwardRef · `getBlob()`/`clear()`/`isDirty()`)
ทั้งเซ็นทีละคนและโหมดวนเซ็นใช้ตัวเดียวกัน — **ห้ามก๊อปไปไว้ในโมดัลใหม่**
`uploadSignatures()` / `applySignUrls()` = ทางเดียวที่คิด path + ตามหาไฟล์เก่า (เดิมฝังอยู่ใน handleSignDone)

### บีบรูปลายเซ็นที่คนถ่าย/สแกนเข้ามา

วัด bucket `signatures` (Main) 28/10:

| ชนิด | ไฟล์ | เฉลี่ย | ใหญ่สุด |
|---|---|---|---|
| วาดบนจอ (OJT) | 12 | **14 KB** | 21 KB |
| อัปรูปเข้ามา (ลายเซ็นประจำตัว) | 90 | **117 KB** | **2.2 MB** |

🔴 **ย่อขนาดอย่างเดียวไม่ลดไฟล์** — PNG เป็นแบบไม่สูญเสีย ⇒ เก็บ noise ของกระดาษ+แสงเงาครบ
⇒ **ตัดพื้นกระดาษให้ขาวสนิทก่อน** แล้ว PNG จะบีบพื้นที่ขาวต่อเนื่องได้แทบฟรี

กฎอยู่ที่ **`src/utils/signatureImage.js`** (ส่วนคำนวณแยกออกมาให้เทสได้โดยไม่ต้องมี canvas):
· `pickPaperCutoff()` — หาค่า "นี่คือพื้นกระดาษ" **จากฮิสโตแกรมของรูปเอง**
  🔴 **ห้ามใช้ค่าคงที่** — กระดาษใต้แสงเหลือง/เงามือสว่างไม่เท่ากัน · รูปมืดทั้งใบ = คืน `null` (ไม่ตัด)
· `clipPaperToWhite()` — พิกเซลสว่างกว่าค่าตัด → ขาวล้วน · ที่เหลือ**คงไว้ตามเดิม** (หัวปากกาไม่แตก)
· `inkRatioOk()` — 🔴 **ตัดแล้วลายเซ็นหาย (< 0.08%) หรือตัดไม่เข้า (> 45%) = ใช้รูปเดิม**
  ไฟล์ใหญ่ยังดีกว่าส่งกระดาษเปล่าขึ้นไปเก็บ
· อ่านพิกเซลไม่ได้ (canvas ปนเปื้อน) = ใช้รูปเดิม ไม่ทำให้บันทึกล้ม
· เทส `src/utils/__tests__/signatureImage.test.mjs` 7 เคส

## 🔴🔴 ช่อง "ระดับจัดการอนุมัติ" = ผู้จัดการเซ็นเอง (2026-11-02 · คำสั่ง user เลือกทาง "ข")

เดิมเป็น `PersonSelect` — **ใครที่แก้ใบได้ เลือกชื่อคนจาก `profiles` แล้วดึง `signature_url`
ของคนนั้นมาแปะ** ⇒ ธุรการแปะลายเซ็นผู้จัดการได้ โดยไม่มีร่องรอยว่าใครแปะ

**วัดจริง 02/11 (74 ใบ):** 62 ใบมีภาพลายเซ็นผู้อนุมัติ · **61 ใบที่ชื่อผู้อนุมัติ ≠ คนสร้างใบ** ·
รู้ว่าใครกดแค่ **7 ใบ** (`approver_uid` มีคอลัมน์อยู่ แต่โค้ดไม่เคยเขียน)

🔑 **กฎของโมดูลนี้ห้ามอยู่แล้ว** (28/10 · คำสั่ง user) — *"เก็บลายเซ็นเป็นรูปต่อครั้ง
ไม่ใช้ลายเซ็นประจำตัวมาแปะ … = ตรายาง ไม่ใช่การลงนาม"* — บังคับใช้กับ**ผู้เข้าอบรม**แล้ว
แต่ **3 ช่องหัวใบยังแปะอยู่** ⇒ รอบนี้ปิดช่องอนุมัติ (ช่องที่เป็น "การตัดสินใจ")

### กติกาใหม่

- ปุ่ม **"✍️ เซ็นอนุมัติ (ในนาม …)"** — เขียน **ชื่อ + `approver_uid` + ลายเซ็น + `approved_at`
  ของคนที่ล็อกอินอยู่** เท่านั้น · เขียนผ่าน **`signApproveOjt()` ที่เดียว**
- 🔴 **`handleSave` ไม่เขียน `approver_*` อีก** — ปล่อยไว้ = ธุรการเขียนได้ตามเดิม ด่านที่ปุ่มก็ไร้ความหมาย
- **ด่าน 3 ชั้น** ① `ojt:record` (RLS ฝั่ง DB — ผู้จัดการถือคีย์นี้อยู่แล้ว **ไม่ต้องแก้ RLS**) ·
  ② ระดับตำแหน่ง ≥ `MANAGER_SIGN_MIN_RANK` (`utils/signRank.js` — **แหล่งเดียวร่วมกับใบ MO**) ·
  ③ ใบนี้เป็นของหน่วยงานเราไหม (`canWriteUnit` — รองรับทั้งแกนส่วนงานและ Cost Center)
- 🔴 **ไม่รู้ตำแหน่ง = ไม่บล็อก แต่จอเขียนว่าไม่ได้ตรวจ** (กติกาเดียวกับขั้น 6/7/8 ของใบ MO)
- 🔴 **ถามยืนยันก่อนเขียน** (`confirmSign` · ของกลาง `utils/signConfirm.js`) + **`checkWriteRows`**
  — RLS ปฏิเสธ UPDATE = "สำเร็จ 0 แถว ไม่มี error" ⇒ ไม่นับแถว = จอขึ้น "เซ็นแล้ว" ทั้งที่ไม่เปลี่ยน
- 🔓 **ปลดลายเซ็น** = ผู้ถือ `ojt:delete` เท่านั้น (เซ็นแล้วเจ้าตัวแก้เองไม่ได้ · หลักเดียวกับใบ MO)
