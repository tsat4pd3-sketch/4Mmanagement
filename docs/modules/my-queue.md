## 🔴 บทเรียนที่เปลี่ยนดีไซน์กลางทาง — "ชื่อในใบ ≠ งานของคนนั้น"

สมมติฐานแรก: *"ใบที่มีชื่อเราอยู่ = งานที่รอเรา"* → **ผิด** พิสูจน์ก่อนเขียนโค้ด:

```
ใบซ่อมรอตรวจรับ 168 ใบ → ชื่อผู้ตรวจรับมีแค่ 10 ชื่อ · อยู่ส่วนงานเดียวทั้งหมด
```

= คิวของแผนก ที่บังเอิญมีใครสักคนถูกพิมพ์ชื่อไว้ ไม่ใช่ภาระของคนนั้นคนเดียว
ถ้าทำเป็น "งานที่รอคุณ" ตรงๆ จะมีคนเปิดมาเจอ 40–50 ใบที่ไม่ใช่ของตัวเอง แล้วเลิกเชื่อแผงทันที

**แต่** พอไล่ตาม `MTN_STEPS[4].byReporter` (ไม่ใช่เดาจากช่องชื่อ) ได้ภาพที่ถูก:

```
ขั้นตรวจรับงานรอ "ผู้เปิดใบ" ไม่ใช่ "ผู้ตรวจรับ"
168 ใบ → ผู้เปิด 14 คน · 9 ไลน์ · 148/168 ใบมี uid ของผู้เปิดแล้ว · ค้างเฉลี่ย 9.3 วัน
```

⇒ ชั้น "รอเราตรงๆ" ใช้ได้จริง **เพราะงาน uid เมื่อ 16-17/09 ทำ coverage ไว้ 88%**

## 3 ชั้น (`TIER`) — ห้ามยุบรวมกัน

| ชั้น | คืออะไร | ตัวอย่างจริง |
|---|---|---|
| `mine` **รอคุณโดยตรง** | ขั้นนี้ผูกกับ *ตัวบุคคล* และคนนั้นคือเรา | ใบซ่อมรอเราตรวจรับ (เราเป็นผู้เปิด) · ใบที่เราเป็นช่างผู้รับงาน · งานติดตามที่มอบหมายชื่อเรา |
| `unit` **คิวของหน่วยงานคุณ** | อยู่ในส่วนงานที่เราดูแล แต่ไม่ได้ระบุเป็นเรา | 4M รออนุมัติ · คำขอปิดกะ · ใบซ่อมขั้นที่รอ "ตำแหน่ง" (จ่ายงาน/QA/ผจก.) |
| `floor` **ค้างทั้งโรงงาน** | ไม่มีเจ้าภาพ — **สรุปบรรทัดเดียว ห้ามแตกรายตัว** | ใบขอซื้อรอกดสั่งซื้อ **6,743 รายการ** (ตัวระเบิดความต้องการสร้างเอง) |

**ทำไม `floor` ต้องเป็นบรรทัดเดียว:** แตกรายตัว = คิวมี 6,743 แถว + เลขบนไอคอนเป็นหลักพัน
⇒ ไม่มีใครกดดูอีกเลย = **พังแบบเดียวกับกระดิ่งเป๊ะ**

## กฎเหล็กของแผงนี้

1. **`badgeCount()` นับเฉพาะ `mine`** · คืน 0 = **ไม่วาด badge เลย** (ไม่ใช่วาดวงกลมที่มีเลข 0)
   · **โหลดไม่ครบ (`partial`) ก็คืน 0** — ตัวเลขที่อาจผิดแย่กว่าไม่มีตัวเลข (รายการข้างในยังโชว์พร้อมคำเตือน)
2. **ว่างต้องขึ้น "✅ ไม่มีงานค้าง" เสมอ ห้ามซ่อนแผง** — กฎเดียวกับคิวงานค้างใน `DeptDashboard`
   ผู้ใช้ต้องแยก *"เคลียร์หมดแล้ว"* ออกจาก *"คิวรีล่ม"* ให้ได้ (คำถาม user: *"ถ้าไม่มี ตัวนี้ก็ไม่โชว์รึป่าว"*)
3. **โหลดไม่สำเร็จต้องติด `partial` + เขียนบนจอว่าไม่ครบ** — ผู้เรียกส่ง `undefined` ให้ `buildQueue`
   เมื่อก้อนนั้นล่ม **ห้ามกลืนเป็น `[]`** (นั่นคือจอที่บอกว่า "ไม่มีงาน" ทั้งที่ไม่รู้)
4. **"ขั้นนี้รอใคร" อ่านจาก `stepMeta()` เท่านั้น — ห้ามเขียน `step === 4`**
   เลขขั้นคนละความหมายระหว่างฟอร์ม JIG/DIE กับ MTN (มีด่าน `mo-step-branch-via-stage`)
5. **เทียบตัวตนด้วย uid ก่อนชื่อเสมอ** (`isMe`) · ไม่มีทั้ง uid และชื่อ = `false` (ไม่รู้ ≠ ใช่)
6. **`sections: []` = ไม่จำกัด** (ตามกติกา `effectiveSections`) · ใบที่ไม่ระบุส่วนงาน **ไม่นับเป็นของเรา**
7. **เกินเพดานต้องบอกว่าซ่อนไปกี่รายการ** (`capped()`) ห้ามตัดเงียบ
8. เรียง**เก่าสุดขึ้นก่อน** · อายุ ≥ `OLD_DAYS` (7) ติดธงแดง
