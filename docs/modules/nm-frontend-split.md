## 2. ทำไมไม่ก๊อปโครงแอปไปอีกตัว

`App.jsx` (~2,650 บรรทัด) ถือ auth · โหลดโปรไฟล์ · โหมดจำลอง role · ออโต้ล็อกเอาต์ · กระดิ่ง ·
version-guard · ตาข่ายกันจอขาว — ก๊อปไปตัวที่ 2 = **2 ชุดที่ต้องแก้ให้ตรงกันตลอดไป**
(คลาสเดียวกับ *"ห้ามก๊อปสูตรไปไว้ในหน้า"* ใน CLAUDE.md · และเป็นเหตุผลที่ user ไม่เลือก "แยกรีโป")

⇒ **ใช้โปรแกรมตัวเดียวกัน แล้วสลับ "รายชื่อหน้าที่เว็บนี้มี" ตอน build**

## 3. กลไก — 3 ชิ้น

| ชิ้น | ไฟล์ | หน้าที่ |
|---|---|---|
| โมดูล edition | `src/appEdition.js` (เต็ม) · `src/appEdition.nm.js` (NM) | `EDITION` · `EDITION_LABEL` · `EDITION_HOME` · `EDITION_PAGES` · `inEdition()` |
| ด่าน | `src/utils/permissions.js` → `canAccessPage()` | บรรทัดแรกสุด: `if (!inEdition(path)) return false` |
| build | `vite.nm.config.js` + `nm.html` + `npm run build:nm` | alias `appEdition` → `appEdition.nm` · ออกที่ `dist-nm/` |

**ทำไมด่านอยู่ที่ `canAccessPage` ที่เดียวพอ** — ทั้งระบบเรียกตัวนี้อยู่แล้ว:
`RoleRoute` (ทุก route) · `Sidebar` · `navItemsForGroups` · `CommandPalette` · `MobileNavBar` ·
`DisplayRotator` · ปลายทางของกระดิ่ง ⇒ แก้จุดเดียว หน้า/เมนู/ค้นหา/จอวน หายพร้อมกันหมด

### 🔴 กฎที่ห้ามพัง

1. **`edition` ≠ `สิทธิ์` — คนละด่าน ต้องผ่านทั้งคู่**
   · edition = *"เว็บนี้มีหน้านี้ไหม"* (ตายตัวตอน build · **admin ก็ข้ามไม่ได้**)
   · `role_permissions` = *"คนนี้เข้าได้ไหม"* (เปลี่ยนที่ `/permissions` เหมือนเดิม)
   ⇒ เอาหน้าเข้า `EDITION_PAGES` **ไม่ได้แจกสิทธิ์ให้ใครเพิ่มแม้แต่คนเดียว**
2. 🔴 **ด่าน edition ต้องอยู่ "ก่อน" admin bypass** — ถ้าให้ admin ข้าม = เว็บ IEC เปิดจอระบบแมสได้
   = หมดเหตุผลที่แยกเว็บ (มีด่านเทสเช็คลำดับบรรทัด)
3. 🔴 **edition อยู่ฝั่ง client ล้วน ไม่มีผลกับ RLS** — ห้ามเอาไปใช้แทนสิทธิ์
4. 🔴 **`inEdition` ของรุ่นเต็มต้องคืน `true` เสมอ** (มีเทส) — เผลอใส่ allowlist ที่นั่น = หน้าหายจากระบบแมสทั้งระบบ
5. 🔴 **`nm.html` ต้องมีตาข่ายกันจอขาวชุดเดียวกับ `index.html`** (มีเทสเทียบทั้งบล็อก) —
   chunk โหลดไม่ได้ = React ไม่เคยขึ้น = ErrorBoundary ไม่ทำงาน ⇒ จอ IEC ขาวสนิทโดยไม่มีอะไรบอกคนหน้างาน
6. 🔴 **`vite.nm.config.js` ต้องมี `__BUILD_ID__` + `version.json` + ปลั๊กอินชุดเดียวกับ `vite.config.js`**
   (มีเทส) — ขาดไป = จอ IEC ค้างเวอร์ชันเก่าทั้งที่ deploy แล้ว (เคยเกิดกับจอ TV)
7. 🔴 **build ของ NM ออกที่ `dist-nm/` เท่านั้น ห้ามแตะ `dist/`**
8. 🔴 **ปลายทางของลิงก์ในหน้า NM ต้องอยู่ใน `EDITION_PAGES`** (มีเทสสแกนซอร์สจริง) —
   ไม่งั้นกดแล้วเด้งกลับหน้าแรกเงียบๆ คนใช้จะนึกว่าระบบพัง

## 5. ขั้นตอนฝั่ง Render (ต้องมีคนกดใน dashboard ครั้งแรก)

`render.yaml` มี service ที่ 2 แล้ว: **`4mmanagement-nm`** (`npm run build:nm` → `dist-nm/`)

1. Render dashboard → **New → Blueprint** (หรือ Sync blueprint ของรีโปนี้) → จะเห็น service ใหม่
2. ตั้ง env 2 ตัวใน service ใหม่ (`sync: false` = ไฟล์ไม่ส่งให้): `VITE_SUPABASE_URL` · `VITE_SUPABASE_ANON_KEY`
   🔴 **ใช้ค่าเดียวกับ service หลัก** (Supabase Main ตัวเดิม — user เลือกไม่แยก project)
3. `autoDeploy: false` เหมือนตัวหลัก ⇒ ต้องมี **Deploy Hook ของ service ใหม่**
   แล้วเติมใน `.github/workflows/scheduled-deploy.yml` ถ้าอยากให้ deploy รอบเดียวกัน

## 6. ผลกระทบกับเว็บแมส — วัดแล้ว

เทียบ `dist/` ก่อน-หลัง (ตัด `__BUILD_ID__` + hash ในชื่อไฟล์ออกก่อน) · **356 ไฟล์**

| สิ่งที่ต่าง | จำนวน | เป็นอะไร |
|---|---|---|
| ลำดับสมาชิกใน array ของ `__vitePreload` | 8 ไฟล์ | ลำดับ dependency ไม่มีผลกับการทำงาน |
| ชื่อย่อ export ของ minifier (`{L as n}` → `{R as n}`) | 22 ไฟล์ | chunk มี export เพิ่ม 1 ตัว ชื่อย่อเลยเลื่อน |

🔴 **ไม่ใช่ byte-identical และเป็นไปไม่ได้ที่จะเป็น** — เพิ่ม import 1 บรรทัดใน `permissions.js`
ย่อมทำให้ bundler เรียงใหม่ · สิ่งที่พิสูจน์ได้คือ **ไม่มีการเปลี่ยนตรรกะ**:
โค้ดที่เพิ่มในรุ่นเต็มคือ `if (!inEdition(path)) return false` ซึ่ง `inEdition` คืน `true` เสมอ ·
`EDITION_HOME === '/'` ⇒ บรรทัดเด้งหน้าแรกไม่เคยทำงาน · `EDITION_LABEL` = ข้อความเดิมเป๊ะ

## 7. ข้อแลกที่รับไว้ (ยังไม่แก้ — ห้ามแก้เองโดยไม่ถาม user)

- **`dist-nm/` ยังมี chunk ของทุกหน้า** (~340 ไฟล์) เพราะ `App.jsx` ประกาศ `lazy()` ของทุก route ไว้คงที่
  · หน้าพวกนั้น**เปิดไม่ได้** (ด่าน edition) และ**ไม่ถูกโหลด** (lazy) — เปลือง storage ของ static host เฉยๆ
  · จะตัดจริงต้องทำ route registry แบบ data-driven = แก้ `App.jsx` ก้อนใหญ่ **ยังไม่คุ้มกับความเสี่ยง**
- **ไม่มี manifest/PWA ของเว็บ NM** — `nm.html` ถอด `<link rel="manifest">` ออก (ของเดิมเป็นชื่อ ESM)
  · อยากให้ IEC กด "เพิ่มลงหน้าจอโฮม" ได้ ต้องทำ `manifest-nm.webmanifest` เพิ่ม
- **sidebar ของเว็บ NM ยังเป็นโครงเดิม** (rail + หมวด) — เหลือหมวดเดียวเพราะหน้าถูกกรอง
  ถ้าอยากได้หน้าตาเฉพาะของ IEC ต้องสั่งเพิ่ม

## 8. เพิ่มหน้าใหม่ให้เว็บ NM ยังไง

1. เติม path ใน `EDITION_PAGES` (`src/appEdition.nm.js`) — **แค่นี้ไม่ได้แจกสิทธิ์**
   (ทางเดียวกันกับหน้าของ **Marketing** ที่จะมาพ่วง — ดู §4 · ห้ามแตก edition ใหม่)
2. ถ้าทีม IEC ต้องเข้าถึงด้วย → เพิ่มคีย์ `page:/<path>` ให้ role `engineer_nm` ที่ `/permissions`
3. `npm run build:nm` ต้องผ่าน (ด่านชุดเดียวกับ build หลัก)
