## 🔴 กฎที่ต้องรักษา (กฎความซื่อสัตย์ของจอ)

- **ข้อมูลไม่พอ = คืน `{ ok:false, reason }` แล้ววาดกล่อง `<NotEnough>` พร้อมเหตุผล**
  ห้ามคืน 0 · ห้ามวาดกราฟเปล่า · ห้ามซ่อนแผง (0 = "วัดแล้วได้ศูนย์" คนละเรื่องกับ "ยังวัดไม่ได้")
- **KPI ที่ยังวัดไม่ได้ขึ้น `—` + "ยังไม่มีข้อมูลพอ"** ไม่ใช่ 0 ที่อ่านแล้วนึกว่าดีเยี่ยม
- **ค่าที่ไม่ถูกนับต้องบอกจำนวน** — "⚠️ 12 รายการยังไม่มีเวลา — ไม่ถูกนับ" (ไม่ตีเป็น 0 นาที)
- **ตัดหางต้องบอกว่าซ่อนไปเท่าไหร่** (`hiddenRows`/`hiddenCols`/`hidden`) — ตัดเงียบ = ตารางโกหกยอดรวม
- **`LCL` ของกราฟควบคุมที่คำนวณได้ติดลบ ต้อง clamp เป็น 0 + เขียนบนจอว่า clamp**
  (ค่า "นาที"/"จำนวนครั้ง" ติดลบไม่ได้ — ไม่บอก = คนอ่านว่า "ยังลดได้อีก −30 นาที")
- **ค่าสุดโต่งของฮิสโตแกรมไปอยู่ "ถังล้น" สีม่วงที่มองเห็น ห้ามกลบรวมถังปกติ ห้ามทิ้ง**
  (เคสจริง: ใบเดียวรอ supplier 313 ชม. ท่ามกลางใบปกติ 10-20 นาที)
- **`r` ของผังกระจายไม่ใช่เหตุผล** — จอเขียนกำกับเสมอว่า "ไปด้วยกัน ≠ ทำให้เกิด"
- **ช่วงเวลาที่ไม่มีเหตุการณ์ = 0 จริง ต้องอยู่บนกราฟ** ⇒ ผู้เรียกต้องส่ง `keys` (ทุกสัปดาห์ในช่วง)
  ให้ `runChart`/`controlChart` ไม่งั้นสัปดาห์ที่เงียบหายไป แล้วแนวโน้มเพี้ยน

## ⚠️ ก้างปลาส่วนใหญ่ "เดา" มา — ต้องบอกบนจอ

วัดจริง 22/09: `mtn_orders.cause_category` มีค่าแค่ **5 จาก 473 ใบ (1%)**
⇒ ผังก้างปลาที่ปั้นจากช่องนั้นอย่างเดียวจะ**ว่างเปล่าทั้งผัง** = จอโกหกว่า "ไม่มีปัญหา"

ลำดับตัดสินใน `boneOf(category, text)`:
1. **ค่าที่คนเลือกไว้จริงชนะเสมอ** (`man` / `method` / `part_life`→material)
2. ไม่มี (หรือเลือก `other` ซึ่งยังไม่บอกว่าอะไร) → เดาจากคำใน `root_cause`/`cause_other`/อาการ/หมายเหตุ
3. เดาไม่ออก → แกน `unknown` **ที่ต้องโชว์บนผัง ห้ามซ่อน**

จอแสดงแถบเหลือง "⚠️ X% ของรายการ ระบบเดาแกนให้จากข้อความ" + ชิป "เดา" รายบรรทัด
และชี้ทางแก้: *ให้ช่างเลือก "สาเหตุเกิดจาก" ตอนบันทึกขั้นลงมือซ่อม แล้วผังนี้จะแม่นขึ้นเอง*

**ลำดับคำเดาใน `BONE_WORDS` สำคัญ** (measure → man → method → material → env → machine):
คำกว้างของแกนหลังจะกลืนประโยคของแกนหน้า — `"ขาด"` (material) กลืน `"ขาดทักษะ"` (man) ·
`"ช่าง"` อยู่ท้ายสุดใน machine (ประโยคที่พูดถึงช่างมักกำลังเล่าอาการเครื่อง)
