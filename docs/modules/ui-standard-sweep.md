## ต้นเหตุเชิงระบบ (แก้ที่ต้นทาง ไม่ใช่รายหน้า)
1. **ไม่มีกรอบหน้ากลาง** → `<Page>` + `.page-content` (มีอยู่แล้วแต่ใช้แค่ 14 หน้า)
2. **ธีมตั้ง `select{width:100%}`** → select ที่ไม่ใส่ width ในแถว flex ยืดเต็มแถว → `.filter-bar select{width:auto}`
3. **TimeRangeBar ใช้ขนาดของตัวเอง (29px)** ต่างจากช่องของหน้า → ย้ายไปใช้ token `--ctl-*` เดียวกัน
4. **ไม่มีทะเบียนคำ** → `filterLabels.js`

## ตัดสินใจระหว่างทาง
- **มุมการ์ด 8 กับ 12 ไม่ใช่ความไม่สม่ำเสมอ** — เป็น token `--r-md` / `--r-lg` ที่ตั้งใจ (คอมเมนต์ index.css 22/09 ห้าม sweep มุมทั้งระบบ) ⇒ ไม่กวาด
- **แท็บเกิน 7 ไม่ตัดทิ้ง/ไม่แยกหน้า** — พับเข้า "⋯ เพิ่มเติม" ใน PageHeader (URL เดิมใช้ได้หมด)
- **ชิป "ส่วนงาน:" ในแท็บงานค้างของ OBEYA** = เลือกมุมมองของฝ่าย (?dept=) ไม่ใช่ขอบเขตองค์กร ⇒ เปลี่ยนคำเป็น "มุมมอง:" (คำว่าส่วนงานในระบบ = PD1–PD4)
- ฟอร์มบันทึก (ใน modal) ยังใช้ขนาดตั้งต้นของธีม (~39px = Carbon medium) — มาตรฐาน 34px ใช้กับ **แถบกรอง** เท่านั้น

## ของที่เปลี่ยนหน้าตาที่ผู้ใช้จะสังเกต
- หน้าฟอร์ม/ตั้งค่าที่เคยจัดกลางจอ (NotificationConfig · ProcessSetup · StorageMaintenance · RemoteControl · Register) **ชิดซ้าย** ตำแหน่งเดียวกับหน้าอื่น
- ปุ่มเลือก (Segmented) ใช้สี accent สีเดียว — ชิปที่เคยมีสีประจำหมวด (EventLog หมวด CQI · QrLabels ชนิดป้าย) เหลือสีเดียว
- Daily Report ความกว้างสูงสุด 2000 → 1800 · Product Master แท็บ ลูกค้า/Supplier/ทบทวน CT/Export อยู่ใต้ "⋯ เพิ่มเติม"
- แท็บ 📍 Log จุดงาน ใน /report: **ช่องเลือกวันที่หายไปตั้งแต่ commit 3d7fa14** (มี useTimeRange แต่ไม่ได้วาด TimeRangeBar) — ใส่กลับแล้ว
- RackCenter แท็บผูก `?tab=` แล้ว (เดิม state ในหน้า)

## หนี้ที่เหลือ (ตั้งใจไม่ทำรอบนี้)
- ใน `<TimeRangeBar>` ตัวกรองของหน้าอยู่ **หลัง** ช่วงเวลา (ตำแหน่ง children) — ยอมรับเป็นมาตรฐาน: แถบเวลา = เวลาก่อน · FilterBar ทั่วไป = ขอบเขตก่อน
- uxsweep (ไล่เฉด/เงา) — คนละเรื่องกับรอบนี้ ตัวเลขเท่าเดิม

## รอบ 2 — ลำดับแนวตั้ง (24/09 · user ส่งภาพ OBEYA 3 แท็บ: "ลำดับยังโดดไปมา")
