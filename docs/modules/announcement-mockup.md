# 📢 ประกาศ / ชี้แจงบริษัท — MOCKUP workflow (`/announcements` · 2026-10-29)

ที่มา: โน้ตลายมือ user "Workflow การรับประกาศของบริษัท" — `Issue → Approve → Publish` ·
ช่อง Topic / Detail / Who's receive / Effective date + คำอธิบายเพิ่ม: ผู้แจ้งเลือกส่วนงานผ่านผังองค์กร ·
submit แจ้งเตือนหัวหน้า (สมมติ EVP) · อนุมัติแล้วแจ้งกลับ · ถึงวันมีผลระบบประกาศหา user ในส่วนงานนั้น

**ไฟล์:** `src/pages/AnnouncementMockup.jsx` · เมนูหมวด "ผู้บริหาร & เดโม"

## สิ่งที่หน้านี้เป็น / ไม่เป็น
- **ตัวอย่างหน้าจอเท่านั้น — ไม่เขียน DB ใดๆ** ประกาศ/แจ้งเตือนอยู่ใน state ของหน้า (รีเฟรช = เริ่มใหม่) · ป้าย 🧪 MOCKUP ที่หัวเพจห้ามถอด
- ของจริงที่อ่าน: ผังองค์กรผ่าน `useOrgScope` + `<OrgScopePicker>` (อ่านอย่างเดียว)
- 3 แท็บ = 3 มุมมองคน (`?tab=issue|approve|board`): ผู้แจ้ง · EVP · พนักงาน
- สถานะ: `pending` → `approved` / `rejected` (ตีกลับต้องมีเหตุผล) · **"ประกาศแล้ว/รอวันมีผล" คิดจาก approved + effective date เทียบ "วันที่จำลอง"** ไม่เก็บเป็นสถานะ
- ผู้รับเห็นไหม = `scopeCovers()` (`utils/orgScope.js`) — เลือกหน่วยแม่ = ครอบหน่วยลูก · เลือกได้หลายหน่วย · เลือก "ทั้งโรงงาน" แล้วตัวอื่นถูกยุบทิ้ง
- **แถบสถานะ 4 ขั้น "เอกสารถึงไหน"** (29/10 · โน้ต user): Step 1 Issue → 2 Approve → 3 Announce → 4 Feedback · วงทึบ ✓ = ผ่าน · วงขอบหนา = ถึงขั้นนี้ (`aria-current="step"`) · ตีกลับ = ขั้น 2 แดง ✕ · **ขั้น Feedback ยังไม่มีกลไกใน mockup** ⇒ ประกาศแล้วจะค้างที่ "ถึงขั้นนี้" ของขั้น 4 (ยังไม่ได้นิยามว่า feedback คืออะไร)
- สิทธิ์: มีแถว `page:/announcements` ใน `/permissions` แต่ **ยังไม่ seed** ⇒ admin เท่านั้นจนกว่าจะเปิดให้ role อื่น

## ถ้าจะทำเป็นระบบจริง (ยังไม่ได้ทำ · รอ user สั่ง)
ตารางประกาศฝั่ง Main + RLS `has_perm()` + audit · แจ้งเตือนในแอปผ่าน `notification_rules` → `notifications` (ห้ามเพิ่ม Telegram) ·
ผู้อนุมัติจริงมาจากไหน (role/ตำแหน่ง) · ต้องมี "รับทราบ" หรือไม่ · เอกสารพิมพ์ต้อง register `/doc-forms`
