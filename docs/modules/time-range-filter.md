## โครง 3 ชั้น — แยกกันชัดๆ ห้ามปนกัน

1. **ถัง (`scale`)** = **ขนาดแท่งในกราฟ** — `hour` / `day` / `week` / `month` / `year`
2. **กรอบเวลา (`from`–`to`)** = ช่วงที่ดึงข้อมูล — แก้เองได้เสมอ · **ชั้นนี้เท่านั้นที่ตัดสินว่าดึงอะไร**
3. **ปุ่มลัด** 2 ชุด = เติม `from`–`to` ให้เร็วๆ
   · **ช่วง**: วันนี้ / สัปดาห์นี้ / เดือนนี้ / ปีนี้ / หลายปี (ล็อก) — ล็อกขนาดแท่งมาด้วย
   · **ย้อนหลัง**: 30 / 60 / 90 / 120 วัน — ขนาดแท่งไล่ตามจำนวนวัน

### 🔴 กฎของบันได
1. **เลือกเองแล้วห้ามออโต้มาทับ** — `nextBucket()` ตามให้เฉพาะตอนที่ค่าปัจจุบัน "ยังเป็นค่าออโต้ของช่วงเดิม"
   ⇒ คนที่กด "หยาบลง" ไว้ แล้วขยับวันปลาย 1 วัน **ต้องไม่ถูกดีดกลับ** (ตรรกะเดียวกับปุ่มย้อนหลัง)
2. **จอต้องเขียนว่าตอนนี้ "แท่งละ 1 วัน"** — ไม่งั้นคนอ่านกราฟผิดโดยไม่รู้ตัว (กฎความซื่อสัตย์ของจอ)
3. **แต่ละจอมีเพดานความละเอียดของตัวเอง** (`finest`) — ข้อมูลบางชุดไม่มีเวลา:

   | ทำแท่งชั่วโมงได้ | ละเอียดสุดได้แค่... |
   |---|---|
   | `downtime_logs.started_at` · `defect_logs.logged_at` · `prod_orders.opened_at/confirmed_at` · `kanban_scans.scanned_at` · ใบ MO | **OEE = วัน** (`production_sessions` มีแค่ `work_date` + เวลาเริ่ม-จบกะ **ไม่มียอดผลิตรายชั่วโมง** ⇒ %P รายชั่วโมงจะเป็นตัวเลขที่เดาเอา) |
   | | **เช็คชื่อ/PPE = วัน** (`daily_production_logs` มีแค่ `work_date`) |
   | | **KPI / พลังงาน = เดือน** (กรอกรายเดือน) |

   ⇒ จอที่ทำชั่วโมงไม่ได้ **ซ่อนปุ่ม "วันนี้"** (กดแล้วได้แท่งเดียว = กราฟหลอก) + เขียนบนจอว่าเพดานอยู่ตรงไหน
4. 🔴 **"24 ชั่วโมงของโรงงาน" ไม่ใช่ 00:00–23:59** — วันทำงานตัดที่ **08:00** และกะดึกข้ามเที่ยงคืน
   ⇒ วันงาน 23/09 = `08:00 ของ 23` → `07:59 ของ 24` (`hourAxis`) · แบ่งตามปฏิทิน = **ผ่ากะดึกครึ่งหนึ่ง
   ไปอยู่คนละวัน** · `bkkHourKey()` บวก 7 ชม. จาก epoch เอง **ห้ามพึ่ง timezone ของเครื่อง**
   (คอนเทนเนอร์เทสเป็น UTC — พึ่ง `getHours()` แล้วเทสจะผ่านบนเครื่องไทยแต่ตกบน CI)
5. 🔴 **`bucketKey(date,'hour')` คืน `null` โดยตั้งใจ** — หาถังชั่วโมงจาก "วันที่" เปล่าๆ ไม่ได้ ต้องมี
   timestamp จริง ⇒ ใช้ `bkkHourKey(ts)` · ถ้าเดาเป็นรายวันแทน จอที่ลืมแปลงจะ**โชว์เลขผิดเงียบๆ**
6. 🔴 **ปุ่ม "หลายปี" ล็อกไว้ (`multiYear={false}` เป็น default)** — กฎเหล็ก CLAUDE.md *โหมดปีห้ามโหลดแถวดิบ*
   · downtime 3 ปี = แสนแถวลงเบราว์เซอร์ = egress ระเบิด (เคยทำ Supabase ล็อกทั้ง organization
   จนทั้งโรงงาน login ไม่ได้) ⇒ เปิดได้**เฉพาะจอที่มี RPC rollup ฝั่งเซิร์ฟเวอร์แล้ว**
   · **โชว์เป็นปุ่มเทา + บอกเหตุผล ไม่ใช่ซ่อน** (คนจะได้รู้ว่าความสามารถนี้มีอยู่ แค่ยังไม่เปิด)
7. **`onView` ไม่ส่ง = ปุ่มช่วง/ขนาดแท่งไม่โผล่** — ต้องเขียน URL ทีเดียวทั้ง `from`+`to`+`scale`

## 🔴 กฎที่ฝังไว้ อย่าไปรื้อ

1. **ปุ่มย้อนหลังไม่ใช่ "โหมด"** — กดแล้วเติมวันลงช่อง จากนั้นคนแก้วันต่อได้ทันที ·
   ไฮไลต์ปุ่มเฉพาะตอนช่วงตรงเป๊ะ (`matchPreset`) ⇒ แก้วันเองแล้วปุ่มเลิกไฮไลต์เอง
   **ห้ามทำเป็น state แยก** (จะเกิดคำถาม "ทำไมกดวันแล้วเด้งกลับ")
2. **สเกลไม่เข้ากับช่วง = เตือน ไม่บล็อก** (`scaleWarning`) — รายปี บน 30 วัน = แท่งเดียว ·
   รายวัน บน 2 ปี = 730 แท่ง · **ห้ามวาดกราฟแท่งเดียวเฉยๆ แล้วปล่อยให้เข้าใจว่านั่นคือแนวโน้ม**
3. **ส่วนที่หน้านั้นไม่ได้ใช้ ให้ซ่อน** (`scales={null}` / `presets={[]}`) — ปุ่มตายแย่กว่าไม่มีปุ่ม
4. **`rangeDays` / `presetRange` นับหัวนับท้าย** — "ย้อนหลัง 30 วัน" ต้องได้ **30 วันเป๊ะ**
   (บั๊กคลาสสิกคือลืม `-1` แล้วได้ 31 · มีเทสล็อกทุกปุ่ม)
5. **คีย์สัปดาห์ = "วันที่ของวันจันทร์" ไม่ใช่ `2026-W39`** โดยตั้งใจ — เอาไปบวกวันต่อได้ตรงๆ
   (โค้ดเติมช่องว่างบนแกนเดินทีละ 7 วันจากคีย์) และป้ายบอกช่วงวันจริง ("21–27/9")
   ซึ่งหน้างานอ่านรู้เรื่องกว่าเลขสัปดาห์ · ต้องการเลขสัปดาห์ ISO ใช้ `isoWeek()`
6. **ตัวแบ่งถัง/ป้ายแกนเวลา อยู่ใน `timeRange.js` ที่เดียว — ห้ามเขียนกลับมาในหน้า**
   (ไม่งั้นกลายเป็นสูตรคนละชุดอีกรอบ ซึ่งคือปัญหาที่งานนี้มาแก้)

## กับดักที่เจอจริงตอนทำ (อย่าพลาดซ้ำ)

- 🔴 **`isoWeek` เพี้ยนไป 1 สัปดาห์** — ใส่ออฟเซ็ต `+4` แทน `+3`
  (**1970-01-01 เป็นวันพฤหัส ไม่ใช่ศุกร์**) ⇒ วันจันทร์ถูกนับเป็นสัปดาห์ก่อนหน้าทั้งระบบ
  · เทสจับได้ทันที · ยืนยันซ้ำด้วยการเทียบกับอัลกอริทึมอ้างอิงครบทุกวัน **2019–2031 = ตรง 4,748/4,748**
- **`<input type="date">` ต้องกำหนด `width` เอง** — `index.css` ตั้ง `input{width:100%}` ทั้งแอป
  ไม่กำหนดแล้วมันกินเต็มแถวแล้วดันปุ่มแตกบรรทัด

**ไม่ใช่ "ขนาดถัง"** แบบหน้าอื่น ⇒ แปลงตรงๆ = เปลี่ยนความหมายของจอที่หน้างานคุ้นอยู่แล้ว
user เคาะ 23/09: **เอาทั้งสองอย่าง** ⇒ เก็บปุ่มเดิม + เพิ่ม `custom` range ทับได้
- แก้วันเอง / กดปุ่มย้อนหลัง → `custom` ชนะ · ป้ายบนจอเปลี่ยนเป็น **"กำหนดเอง (N วัน)"**
- กดปุ่ม สัปดาห์/เดือน/ปี → ล้าง `custom` กลับโหมดเดิมทันที
- **ช่วงเทียบ (prev) ของกรอบกำหนดเอง = ช่วงยาวเท่ากันที่ติดกันข้างหน้า** (เทียบ "สัปดาห์ก่อน" ไม่ได้ เพราะกรอบเองไม่ใช่หน่วยปฏิทิน)
- **ไม่ผูก URL** ต่างจากหน้าอื่นโดยตั้งใจ — จอนี้เปิดค้างบน TV ด้วยลิงก์ `?tab=sqdcm`
  ถ้าเขียน `?from=&to=` ลงไปด้วย ลิงก์ที่แปะไว้บนจอจะค้างอยู่ช่วงเก่าตลอดไป
- แถบไม่โชว์ในโหมดจอ TV (ไม่มีคนกด)

> ทดสอบจริงด้วย Playwright: ค่าเริ่มต้น `รายเดือน` + `90` ไฮไลต์ · กด `60` แล้ววันที่เปลี่ยนเป็น
> 60 วันเป๊ะและปุ่มสลับไฮไลต์ · กด `รายปี` บนช่วง 60 วัน แล้วคำเตือนขึ้นจริง · ไม่ crash ไม่มี pageerror
> ⚠️ harness ใช้ `MemoryRouter` ⇒ **ตรวจ URL sync ในนั้นไม่ได้** (`window.location` ไม่ขยับ) —
> เส้นทางเดียวกับ `useTabParam` ที่ใช้งานจริงอยู่แล้วทั้งระบบ

## ⛔ ที่ **ไม่แปลง** — และทำไม (ตรวจของจริงแล้ว ไม่ใช่ตกหล่น)

การสำรวจรอบแรกใช้ grep จึงนับเกินมา 4 ไฟล์ · เปิดดูของจริงแล้วพบว่า**ไม่มีตัวกรองช่วงเวลา**:

| ไฟล์ | ของจริงคืออะไร |
|---|---|
| `/energy` | **ตัวเลือกเดือนเดียว** (`month_key`) ไม่ใช่ช่วง · ที่ grep เจอเป็นช่อง "มีผลตั้งแต่" ของค่า Emission Factor = **ฟิลด์ในฟอร์ม** · แปลงเป็น from–to = เปลี่ยนโครงคิวรีทั้งหน้า (ฟีเจอร์ใหม่ ไม่ใช่การจัดมาตรฐาน) |
| `/planner-sales` · `/production-plan` | "รายวัน/รายเดือน" ของมันคือ **แท็บ `useTabParam`** (ระยะเวลาที่วางแผนไปข้างหน้า) ไม่ใช่กรองข้อมูลย้อนหลัง |
| `/lpa` | วันที่ทั้งหมดเป็น **ช่องในฟอร์ม** (วันตรวจ · ช่วงเฝ้าระวัง Issue Date) ไม่ใช่ตัวกรองมุมมอง |

> **กฎ:** ตัวกรองที่หน้าไม่ได้ใช้จริง **ห้ามยัดแถบมาตรฐานลงไป** — ปุ่มตายแย่กว่าไม่มีปุ่ม
> (กติกาข้อ 3 ด้านบน) · ถ้าวันหลังอยากให้ `/energy` ดูข้ามเดือนได้ = งานฟีเจอร์ ต้องสั่งแยก
