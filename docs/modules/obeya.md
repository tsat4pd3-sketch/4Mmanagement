## 1. หน้านี้มีไว้ทำอะไร (และ "ไม่ใช่" อะไร)

ESM มีจอภาพรวมอยู่แล้ว 9 ใบ — Obeya จะคุ้มค่าก็ต่อเมื่อทำ **3 อย่างที่จอเดิมทำไม่ได้**:

| # | สิ่งที่จอเดิมทำไม่ได้ | หน้านี้ทำยังไง |
|---|---|---|
| 1 | จอเดิมตัดตาม**ส่วนงาน/ไลน์** (ใครรับผิดชอบ) | Obeya ตัดตาม **แกน S-Q-D-C-M** (ลูกค้า/ผู้บริหารมองอะไร) — แกนเดียวดึงข้ามส่วนงานมาชนกัน |
| 2 | จอเดิมตอบ "ตอนนี้เท่าไหร่" | Obeya ตอบ **"ห่างเป้าเท่าไหร่ · ดีขึ้นหรือแย่ลงจากงวดก่อน"** (ทุกแผ่นมีเป้า + Δ + เทียบ `prevRange`) |
| 3 | จอเดิม**ไม่มีที่บันทึกสิ่งที่ตกลงกันว่าจะแก้** | **ACTION BOARD** = ที่เดียวของหน้าที่เขียนข้อมูลได้ (ผูก `kpi_key` กับแกนที่จะไปแก้) |

**ไม่ใช่:** หน้าแก้ข้อมูลผลิต · ไม่ใช่หน้าวิเคราะห์ลึก (ลึกไปที่ `/oee-analytics`) · ไม่ใช่จอ Andon หน้าไลน์ (`/tv`)

## 2. 🖼️ ผัง "กระดาษ A4 ปูเต็มจอ" (คำสั่ง user 2026-09-15)

> *"เปิดจอทีวี 70 นิ้ว ให้เหมือนมีกระดาษไซส A4 ติดเต็มหน้าจอ"* + *"หน้ารวมใน 1 หน้าที่มอนิเตอร์ทุกด้าน ลักษณะกราฟ"*

**คณิตที่ทำให้มันลงตัวพอดี:**
```
A4 แนวตั้ง 210×297  ⇒ กว้าง/สูง = 0.7071
จอ 16:9 (สูง = 1)   ⇒ แบ่ง 2 แถว ⇒ แผ่นสูง 0.5 ⇒ แผ่นกว้าง 0.354
                      1.778 ÷ 0.354 = 5.03  ⇒ **5 คอลัมน์ × 2 แถว = 10 แผ่น เต็มจอพอดี**
```
- แผ่นแนวตั้ง 1 ช่อง = S · Q · D · C · M (แถวบน)
- แผ่นแนวนอน (A4 landscape) = 2 ช่องติดกัน = **OEE** และ **ACTION BOARD** (แถวล่าง) · ตรงกลางแถวล่าง = Pareto "ทำไมหลุดเป้า"
- รวม **8 component / 10 ช่อง**

**วัดจริง (Playwright 2026-09-15 · โหมดจอ TV):**

| จอ | ขนาดแผ่น | อัตราส่วน | ตกขอบ? |
|---|---|---|---|
| 3840×2160 (4K TV) | 740×1046 | **0.707** | ไม่ |
| 1920×1080 (70" FHD) | 358×506 | **0.707** | ไม่ |
| 1366×768 (โน้ตบุ๊ก) | 247×350 | **0.707** | ไม่ |
| 1280×1024 (4:3) | 245×346 | **0.707** | ไม่ |
| 820×1180 / 390×844 (แนวตั้ง) | — | 0.707 | สลับเป็น **โหมดเลื่อน 1-2 คอลัมน์** อัตโนมัติ |

### ⚠️ กับดัก 2 ข้อที่เจอตอนทำ (ทั้งคู่ "พังเงียบ" — build/lint/เทสผ่านหมด)

1. **`clientHeight` รวม padding เสมอ** → เดิมวัดกล่องที่มี `padding: 8` แล้วเอาไปคิดความสูงแผ่น
   ⇒ แถวล่างสูงเกินกรอบ 16px แล้วถูก `overflow: clip` **ตัดหายเงียบ** (ปุ่ม "เจาะ OEE" หายทั้งปุ่ม)
   **กฎ: กล่องนอก = ใส่ padding · กล่องใน (ที่ถูก ResizeObserver วัด) = ห้ามมี padding**
2. **`height: 100vh` ไม่ได้แปลว่าเต็มจอ** — หน้านี้อยู่ใน `<main>` ที่มี sidebar + padding
   ⇒ 100vh ล้นออกนอกจอ · โหมดจอ TV ต้องใช้ **`position: fixed; inset: 0`** (+ `requestFullscreen()` best-effort)

### กฎของผังนี้ (ถ้าจะเอา pattern ไปใช้จอ TV ใบอื่น)
- วัดขนาดจาก **container จริงด้วย ResizeObserver** ห้าม hardcode / ห้ามใช้ media query
  (จอ TV แต่ละรุ่น devicePixelRatio + overscan ไม่เท่ากัน — hardcode แล้วมี scrollbar โผล่บางเครื่อง)
- **ห้ามใช้ `dvh/svh` (Cr 108) · `@container` (105) · `color-mix()` (111) · CSS nesting (112)** — เพดานจอ TV = **Chromium 94** (webOS 23)
- ฟอนต์ต่ำสุด 11px เสมอ (`fs()` ใน `Sheet`) — แผ่นเล็กจนฟอนต์จะต่ำกว่านั้น ให้**ลดจำนวนคอลัมน์** ไม่ใช่ลดฟอนต์

## 4. 🎯 ACTION BOARD — เหตุผลหลักที่หน้านี้มีอยู่

**ข้อค้นพบที่ชี้ขาดทั้งดีไซน์ (วัด 2026-09-15):** `meeting_action_items` มี **0 แถว**
ตั้งแต่สร้าง 13/07 ทั้งที่ downtime ถูกกรอก 8,627 แถว และใบ 4M 1,213 ใบในช่วงเดียวกัน
⇒ ระบบเก็บ "สิ่งที่เกิดขึ้น" ได้ดีมาก แต่ **"สิ่งที่ตัดสินใจจะทำ" ยังอยู่นอกระบบ** (ในหัวหัวหน้า / ไลน์แชท / กระดาษ)

หน้านี้จึงทำให้ลูปเดินได้:
```
ตัวเลขหลุดเป้า → [➕ ตั้ง Action] (ผูก kpi_key กับแกน) → ใครรับ · ภายในเมื่อไหร่
   → แจ้งเข้ากระดิ่ง (notifyEvent) → บอร์ดโชว์ "เกินกำหนด" ขึ้นก่อนเพื่อน → กดปิด → วัดผล
```
- **บอร์ดว่าง = ขึ้นคำเตือนสีแดง ไม่ใช่ "0 ใบ" เฉยๆ** — 0 ใบไม่ได้แปลว่าไม่มีปัญหา แปลว่าไม่มีใครบันทึก
- "เกินกำหนด" คำนวณจาก `due_date` เทียบวันนี้ **ไม่ใช่ `status` ดิบ** (`actionBuckets`)
- ใช้ตารางเดิมร่วมกับ `/morning-meeting` — **ห้ามสร้างตารางใหม่** · แยกที่มาด้วย `source = 'obeya' | 'morning'`

### คอลัมน์ที่เพิ่ม (migration `20260915_obeya_action_loop.sql`)
| คอลัมน์ | ใช้ทำอะไร |
|---|---|
| `source` | `'obeya'` / `'morning'` / null(=ของเดิม) — รู้ว่าใบนี้ตั้งจากที่ประชุมไหน |
| `kpi_key` | `'S'|'Q'|'D'|'C'|'M'|'OEE'` — ใบนี้จะไปแก้ตัวเลขตัวไหน (**ไม่มี check constraint ตั้งใจ** — เพิ่มแกนใหม่ไม่ควรต้องรอ migration · client คุมตัวเลือกผ่าน `OBEYA_AXES`) |
| `target_value` / `result_value` | เป้าที่ตกลงกัน / ผลจริงตอนปิด — มีทั้งคู่ถึงจะพิสูจน์ได้ว่า countermeasure ได้ผล |

### 🔴 RLS — เปลี่ยนจาก `using(true)` เป็น `has_perm()` (Phase 3 ที่ policy เดิมเขียนคอมเมนต์ค้างไว้เอง)
เดิม `for all to authenticated using(true) with check(true)` = ใครที่ login ก็เขียนได้ แม้ `/permissions` ปิดปุ่มแล้ว
ตอนนี้แยกครบ 4 cmd: `select` เปิดทุกคนที่ login (จอ TV/ผู้บริหารต้องอ่านได้) ·
`insert`/`update`/`delete` = `has_perm('morning_meeting:record') or has_perm('obeya:record')`
> ผลกระทบ = 0 (ตารางมี 0 แถว · ทางเขียนเดียวคือปุ่มใน `/morning-meeting` ที่ gate ด้วย `can('morning_meeting','record')` อยู่แล้ว)
> ⚠️ RLS ปฏิเสธ UPDATE = "สำเร็จ 0 แถว ไม่มี error" ⇒ ปุ่ม "ปิด" บนบอร์ด `.select('id')` แล้ว**นับแถว** ห้ามเชื่อ `!error`

1. **ถอด `borderTop: 4px solid <สีประจำแกน>` ออกทุกแผ่น** — บนบอร์ด สีต้องมีความหมายเดียวคือ *สถานะ*
   แถบสีประจำแกน (S แดง · Q ม่วง · D ฟ้า …) เป็นสี "ประจำตัว" ที่ไม่เปลี่ยนตามผล ⇒ แผ่นที่ปกติกับ
   แผ่นที่มีปัญหาเด่นเท่ากัน และแถบแดงของ S ยังอ่านผิดเป็น "มีปัญหา" ได้ทั้งที่ S เขียว
   · สีประจำแกนยังใช้อยู่ที่ **เส้น/แท่งในกราฟ** เหมือนเดิม (`axisSheet(k).color`) ไม่ได้ถอดทิ้ง
2. **เพิ่ม `<StatusLamp>` บนหัวแผ่นครบทั้ง 8 ใบ** — วงกลมสี + คำบอกสถานะ + `↗` กดเจาะเข้าหน้าจริง
   (ปลายทางเดียวกับปุ่มลิงก์ท้ายแผ่น) · tooltip บอกเหตุผลเต็มว่า "ทำไมเป็นสีนี้"

**ที่มาของสี — `statusWhy()` ใน `src/utils/obeyaKpi.js` เท่านั้น ห้ามหน้าคิดคำ/เกณฑ์เอง**

| แผ่น | ที่มาของไฟ |
|---|---|
| S · Q · D · M · OEE | `statusWhy(value, target, ทิศทาง, หน่วย)` ตรงๆ (ใช้ `statusOf` เดิม เกณฑ์ไม่เปลี่ยน) |
| C ต้นทุนที่เสียไป | เขียนเอง — **ยังไม่มีใครตั้งเพดานค่าความสูญเสีย** ⇒ แดงนี้แปลว่า *"มีเงินหายไป"* ไม่ใช่ *"เกินเป้า"* (เขียนไว้ใน tooltip ตรงๆ) |
| 🔎 ทำไมถึงหลุดเป้า | แผ่นนี้ตอบ *"ทำไม"* ไม่ใช่ KPI ของตัวเอง ⇒ มีเวลาหยุด = **เทา "ไม่มีเป้า"** · 0 นาที = เขียว |
| ACTION BOARD | ใบเกินกำหนด = แดง · ยังไม่มีใบเลย = เทา · ที่เหลือ = เขียว · **ไฟไม่กดได้** (รายละเอียดอยู่บนแผ่นแล้ว — ลิงก์ไป `/morning-meeting` ไม่ได้ ตารางเดียวกันแต่คนละ `source`) |

**กับดักที่เจอตอนทำ (วัดด้วย Playwright ทั้งคู่ — ตาเปล่าไม่เห็น):**
- วางไฟไว้ **แถวเดียวกับชื่อแผ่น** → ที่ 900px ชื่อ "S ความปลอดภัย" ถูก clip เหลือ 72px
  ⇒ ย้ายไปท้าย **แถวตัวเลขใหญ่** (แถวนั้นที่ว่างเยอะ + ไฟอยู่ติดเลขที่มันตัดสินพอดี)
- ย้ายแล้วไฟยังไปบีบ **ตัวเลขพาดหัว** (98.4% เหลือ 34px) ⇒ บล็อก `flexShrink: 0` ที่ตัวเลข
  \+ ย่อไฟเหลือดวงเปล่าเมื่อแผ่นแคบ
- 🔴 **ย่อไฟโดยดู `k` ไม่ได้** — `k = clamp(cw/330, 0.72, 2.4)` ชน floor ⇒ แผ่น 172px (จอ 900)
  กับ 217px (จอ 1280) ได้ `k` เท่ากันเป๊ะ แยกไม่ออก · ต้องส่ง **ความกว้างจริง** (`cw × span`) ลงไป
  แล้วย่อเมื่อ `< 200px` — ผลลัพธ์: 1920/1280 เห็นคำเต็ม · 900 เหลือดวงเปล่า (แตะอ่าน tooltip ได้)
