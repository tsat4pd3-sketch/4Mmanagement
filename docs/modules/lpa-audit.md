### 🔴 กฎที่พลาดแล้วเจ็บที่สุด
1. **"ไม่รู้" ห้ามกลายเป็น "ไม่ได้ผลิต"** — คิวรี DR ล้มครั้งเดียว แล้วบีบเป็น `false`
   = **วันขาดตรวจทั้งเดือนหายเกลี้ยง จอดูสะอาดขึ้นตอนระบบพัง** · ด่าน `daily-check-unknown-not-false`
2. **ตัวหาร % = `done + missed` เท่านั้น** — รวมวันหยุด/วันไม่ผลิตเข้าไป = % ขยับตามปฏิทิน ไม่ใช่ตามงาน
   · ไม่มีวันที่ต้องตรวจเลย ⇒ `pct = null` **ห้ามคืน 0% หรือ 100%**
3. **LPA: เดือนที่ยังไม่มีแผน ⇒ `not_planned` ทั้งเดือน + ขึ้นแถบบอก** — เดาเป็น "ต้องตรวจทุกวัน"
   = ทาแดงทั้งเดือนให้ไลน์ที่ยังไม่ได้วางแผน ⇒ คนเลิกเชื่อสีแดงทั้งจอ
4. **สัญลักษณ์สถานะวันห้ามชนพจนานุกรมคำตอบ** (ดูหัวข้อข้างบน) — ชนแล้วจอรายงาน
   "ตรวจแล้วเจอผิดปกติ" ทั้งที่ยังไม่มีใครไปตรวจ
5. **`mark` อยู่หัวตารางแถวเดียว** — ขาดตรวจคือ "วันนั้น" ไม่ใช่ความผิดของทุกข้อในเช็คลิสต์
   ⇒ ห้ามเขียนตัวอักษรลงในช่องคำถาม · `tint` **ทาได้** เพราะเป็นพื้นจาง 12% = "คอลัมน์นี้ไม่มีข้อมูล"
   ไม่ใช่คำตัดสินรายข้อ (13/10 — เดิมห้ามทาทั้งคอลัมน์ เปลี่ยนเพราะเป็นชั้นกันอ่านสลับที่แข็งที่สุด)

### อาการ

คำถามชั้น **`common` (`line_name = null`) ใช้ `question_id` ร่วมกันทุกไลน์**
⇒ ใบร่างของไลน์ A ที่มาช้าทับจอที่เลือกไลน์ B แล้วกดบันทึก:

|---|---|
| ข้อ `common` (ใช้ id ร่วม) | 🔴 **คำตอบของไลน์ A ไปลงเป็นของไลน์ B — ไม่มี error ไม่มีใครรู้** |

## 🔐 ด่านชั้นที่ 3 ของใบตรวจ/แผน (20/10/2026 · QC audit)

เดิมหน้านี้มีด่านขอบเขตเฉพาะ **ทะเบียนคำถาม** (`qWrite`/`qGuard` · `lpa_questions`)
`lpa_audits`/`lpa_plans` ไม่มีเลย ⇒ เปิด `?line=` ของส่วนงานอื่นแล้วบันทึก/ลบเอกสาร ISO ของเขาได้

- `lineWrite = canWriteLine(qCtx, selLine, lines)` (ประกาศถัดจาก `selLine`) · `lineGuard(what)` ใช้ซ้ำทุกทางเขียน
- คุม 6 จุด: `savePlan` · `saveQuarter` · `saveAudit` · `deleteAudit` · `handleSignDone` · `fillStationsFromWorkstations`
- ไลน์นอกขอบเขต = **เขียนบนจอ** (แถบ 🔒 ใต้แถบตัวเลือก) ไม่ใช่เด้ง toast ตอนกดอย่างเดียว
- 🔴 ไลน์ที่ไล่ส่วนงานไม่ได้ = ไม่บล็อก (ตัดสินไม่ได้ ≠ ปฏิเสธ) · ผู้ถือ `scope:all_units` ผ่านหมดเหมือนเดิม
- 📊 วัดก่อนปิด: 843 ใบในฐานจริง **ไม่มีใบไหนถูกบล็อก** (745+92 ส่วนงานตรงกับไลน์ · 6 ใบคนเขียนถือใบผ่าน)
- ด่าน `regressionGuards` (`🛡️ /lpa: ทุกฟังก์ชันที่เขียนใบตรวจ/แผน…`) — ถอดออก = เทสแดง


## 🔴 อ่านไม่สำเร็จ ≠ "ขาดตรวจ" และ ≠ "ยังไม่มีใบ" (2026-10-20 · QC audit · ด่าน `lpa-read-fail-not-missed`)

หน้านี้ระวังฝั่ง DR ไว้ดีแล้ว (`loadRunDays` คืน `unknown`) แต่**คิวรีฝั่ง Main ที่ตอบว่า "ตรวจแล้วหรือยัง"
เดิมแกะแต่ `{ data }` ทิ้ง `error` ทั้ง 3 จุด** ⇒ คิวรีล้มครั้งเดียวกลายเป็นคำกล่าวหา:

| จุด | เดิมพังเป็น | ตอนนี้ |
|---|---|---|
| `loadMonth` (ตารางเดือน) | ทั้งเดือนขึ้น "ขาดตรวจ" + ตัวหาร % คิดจากใบ 0 ใบ | `monthErr` ⇒ ส่ง `planned`/`ran` เป็น `null` เข้า `checkDayState` = **`unknown` ทั้งเดือน** + แถบแดงบอกเหตุ |
| `loadQuarter` (ใบไตรมาส FM-QMR-008) | ช่องที่วางแผนไว้ขึ้น `⊗ เลยกำหนด` **บนกระดาษที่พิมพ์ไปเซ็น** | `qErr` ⇒ ช่องนั้นเป็น `?` + แถบเตือน "อย่าเพิ่งพิมพ์ใบนี้ไปเซ็น" |
| effect โหลดใบที่กำลังกรอก | ได้ใบร่างเปล่า `answers:{}` ⇒ กดบันทึก = `upsert` → `delete` คำตอบทั้งใบ → insert ชุดใหม่ = **คำตอบหายถาวร** | `draftErr` ⇒ **ไม่ตั้ง `draft` เลย** (`draftMismatch()` บล็อกการบันทึกอยู่แล้ว) + แถบแดงบอกว่าบันทึกไม่ได้ |

🔴 ด่านเดิม `daily-check-unknown-not-false` จับเฉพาะรูป `ranOn(…) ?? false` ⇒ **มองไม่เห็นทั้ง 3 เคส**
(ต้นทางคือ "ไม่อ่าน error" ไม่ใช่ "บีบ null เป็น false") — ด่านใหม่ตรวจว่าก้อนที่ดึง `lpa_audits`
ไม่แกะ `{ data }` ทิ้ง error และมี `monthErr`/`draftErr` + ส่ง `null` เข้า `checkDayState`
