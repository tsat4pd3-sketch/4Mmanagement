## 🎯 แถบ "ไปที่จุด" ในโมดัลตั้งค่าจุดตรวจ (2026-10-13)

**ที่มา — feedback ทีม MTN/JIG:** *"จุดเยอะแล้ว ทำงานยาก ต้อง scroll เลื่อนจนเมื่อยนิ้ว
ถ้ามีระบบ jump ไปหาจุดนั้นได้จะดีมาก"*

- โชว์เมื่อมี **≥ 6 จุด** (`JUMP_MIN` ใน `PMSetup.jsx`) — ช่อง `<SearchInput>` + ชิปทุกจุด (เลข `1.3` + ชื่อ)
  · พิมพ์เลขจุด / เลข Item (`2` = ทั้งกลุ่ม) / ชื่อจุด / ชื่อกลุ่ม แล้ว **Enter = ไปจุดแรกที่ตรง**
  · กติกาจับคู่/เรียง = **`cpJumpMatches()` (`src/utils/cpJump.js` · มีเทส)** ห้ามเขียนซ้ำในหน้า
- ชิปจุดที่ **ยังไม่มีชื่อ = กรอบประแดง** · กดบันทึกแล้วติด "ใส่ชื่อทุกจุด" ⇒ **พาไปจุดว่างแรกให้เอง** + บอกว่าว่างกี่จุด
- กด **+ เพิ่มจุดตรวจ** ⇒ เลื่อนไปการ์ดใหม่ท้ายลิสต์ให้เอง (เดิมเกิดนอกจอ ต้องเลื่อนหาเอง)
- จอกว้าง/โหมดรายการ: หัวคอลัมน์ "จุดตรวจสอบ (N)" + แถบ **ตรึงบนสุด** (มีปุ่ม ⤒ บนสุด / ⤓ ท้ายสุด) ·
  จอแคบ + โหมดรูป: แถบเป็น **แถวเดียวเลื่อนแนวนอน ใต้รูปที่ตรึงอยู่** (รูปกินหัวจอมือถืออยู่แล้ว)
- 🔴 เลื่อนด้วย `modalBody.scrollTo()` **ห้าม `scrollIntoView`** (เลื่อนหน้าหลังโมดัลไปด้วย) และต้องหัก
  **padding บนของ modalBody + `top` ของแถบที่ตรึง + ความสูงแถบ** ไม่งั้นการ์ดไปจมใต้แถบ ·
  เรืองกรอบ 2.5 วิ (UI §6.23 ข้อ 3)
- ⚠️ การ์ดถูกห่อด้วย `<div ref>` เพื่อวัดตำแหน่ง — **`key` อยู่ที่ div ห่อ** (ย้ายไปไว้ที่ `CheckpointCard` = React เตือน key)
- **แตะหมุดบนรูป = ไปที่การ์ดจุดนั้น** (13/10 · `SpinAnnotator` prop `onPinClick`) — **ถอดหมุดย้ายไปปุ่ม "✕ ถอดหมุด" บนการ์ด**
  · `SpinAnnotator` ที่ไม่ส่ง `onPinClick` (เช่น `/equipment?tab=jig`) ยังเป็นพฤติกรรมเดิม แตะ = ลบ
  · กระโดดไปการ์ดที่ปักหมุดบนเฟรมอื่น ⇒ หมุนรูปไปเฟรมนั้นด้วย + หมุดเรือง (`selected`) คู่กับการ์ด

## 🗂️ ลิสต์อุปกรณ์ = ตาราง + ตัวกรอง (2026-10-13 · feedback ทีม JIG MTN · UI §6.25)

*"ข้อมูลเยอะจนเลื่อนหาไม่เจอ ช่างรู้ว่าอุปกรณ์นี้อยู่ไลน์ 297 ของ PD4 แต่ไม่มีระบบให้กรอง"*
(วัดจริง 13/10: JIG MTN 106 ตัว · 18 ไลน์ — เดิมการ์ด 6 ใบ/แถว ไม่มีตัวกรองเลย)

- **แถบกรอง (ลำดับตายตัว):** ทีม (`<Segmented>` — เดิมปุ่มทีมอยู่ใต้แถบกรอง ผิดลำดับ) → ขอบเขต
  `<LineScopeSelect>` (ส่วนงาน → กลุ่มไลน์ → ไลน์ **รวมไลน์ลูก**) → สถานะ → `<SearchInput>` (ชื่อ/No./เครื่อง/ไลน์/พาร์ท)
  · ตัวกรองค้างไว้ตอนสลับทีม · `แสดง N จาก M` + ปุ่มล้างตัวกรอง
- **ตาราง `.rec-list` จัดกลุ่มตามไลน์** (ลำดับทะเบียน ส่วนงาน→แม่→ลูก) · แถวกด = เปิดแก้ไข (เฉพาะสิทธิ์ `pm:setup`)
- กติกาสถานะ/กรอง/จัดกลุ่ม = **`src/utils/pmEquipList.js` (มีเทส)** ห้ามคิดซ้ำในหน้า
- 🔴 **อุปกรณ์ที่ไลน์ว่าง/ไม่ตรงทะเบียน ห้ามหาย** — ไม่กรองไลน์ = กลุ่มท้ายตาราง (ป้าย "ไม่อยู่ในทะเบียนไลน์") ·
  กรองไลน์อยู่ = หลุดจากผล **จอต้องเขียนว่าหลุดกี่ตัว** + ตัวเลือกสถานะ "ไลน์นอกทะเบียน" ให้เปิดดู
- ⚠️ **ไม่มีสถานะ "ยังไม่ปักหมุด" โดยตั้งใจ** — `layout_type` (รูป+หมุด / รายการ) **ไม่ได้ถูกเก็บลงฐาน**
  (ไม่มีคอลัมน์ใน `jigs` — โมดัลเปิดใหม่ทุกครั้งเป็น image_pin) ⇒ แยกไม่ออกว่าลืมปัก หรือเป็นแบบรายการ = ธงเตือนผิด
- 🔴 โหลดข้อมูล (13/10): เดิม `select('*')` + ไม่เช็ค error + `.in(checklist ids)` ยาว + ไม่มี paging ⇒ ล้ม = จอบอก
  "ยังไม่มีอุปกรณ์" · ตอนนี้ `fetchAllPages`/`fetchByIds` + เลือกคอลัมน์ + **ล้ม = แถบแดงบนจอพร้อมปุ่มลองใหม่** ·
  `reqRef` กันคำตอบเก่าทับเมื่อสลับทีมเร็ว

และมีไว้ให้ช่าง *"ตรวจค้างไว้ก่อน แล้วกลับมาทำต่อ"* (เครื่องยังเดินอยู่ ตรวจบางจุดไม่ได้)
บล็อกปุ่ม = ช่างเสียงานที่กรอกมาแล้วทั้งหมด แล้วหันไปกรอกส่งเดชให้ครบ = ข้อมูลแย่กว่าเดิม

⇒ ทำตามที่ทีม MTN เสนอเองเป๊ะ: **เปลี่ยนสี + ถามยืนยัน ไม่บล็อก**

### กฎ

- 🔴 **เกณฑ์ "ครบ" มีสูตรเดียว = `cpFilled(cp)`** — ห้ามเขียนเงื่อนไขซ้ำที่อื่นในหน้า
  (เคยมี 3 ชุดคนละเกณฑ์: progress bar · `isFormReady` · นิพจน์ในปุ่ม — `isFormReady` ใช้
  `r.attr !== ''` ซึ่งนับ `undefined` ว่า "กรอกแล้ว" ⇒ **แถบความคืบหน้ากับปุ่มขัดกันเองได้**)
- ครบ → ปุ่ม `var(--accent)` (เขียว) · ไม่ครบ → `var(--accent2)` (เหลือง/ส้ม) +
  ป้ายบอก **จำนวนจุดที่ยังไม่กรอก** ("⚠️ บันทึก (ยังไม่ครบ N จุด)") — ตัวเลข ไม่ใช่คำว่า "ไม่ครบ"
- ไม่ครบ → `confirm()` ก่อนบันทึก (กันกดพลาด) · ยืนยันแล้วบันทึกได้ตามเดิม

## 📋 คัดลอกแผน PM จากเครื่องอื่น (2026-10-07)

**ที่มา — คอมเมนต์ทีม MTN ข้อ 2 (06/10):**

> แต่ชนิดซ้ำๆกัน จุดการ PM เหมือนกันหมด"*

### 🧰 เครื่องมือคัดลอก/ย้าย = พับไว้เป็นค่าเริ่มต้น (2026-10-14 · user: *"เปิดมาเจอแบบนี้คนไม่งงหรอ"*)
เดิมเปิด "แก้ไขอุปกรณ์" แล้วลิสต์ติ๊ก 177 เครื่องกางทันที — ดันจุดตรวจ (งานหลักของโมดัล) ลงไปล่างสุด
และอ่านไม่ออกว่าเป็นของคัดลอก "ไป" หรือ "มา" ⇒ ตอนนี้เหลือ 2 ปุ่มที่ป้าย**บอกทิศ**:
`📋 คัดลอก N จุดตรวจนี้ ไปเครื่องอื่น… ▼` · `↔ ลงผิดแผนก? ย้าย/คัดลอกไปแผนกอื่น… ▼` — กดค่อยกาง (เปิดได้ทีละอัน · state `toolOpen`)
· **ห้ามกลับไปกางเป็นค่าเริ่มต้น** · เครื่องมือใหม่ในโมดัลนี้ให้เข้าแถวปุ่มเดียวกัน
· ไม่มีทิศกลับ "ดึงจุดตรวจ**จาก**เครื่องอื่น" โดยตั้งใจ (user 14/10) — เครื่องใหม่ = บันทึกก่อน แล้วส่งจากเครื่องต้นแบบ

### 🔴 กฎที่ห้ามแก้ให้ง่ายขึ้น (ข้อ 5-8 เพิ่มจาก QC audit 08/10)

1. **กฎทั้งหมดอยู่ใน `copyCheckpointsInto()` (`src/lib/pmChecklists.js`) ที่เดียว**
   `copyChecklistToDept` (คัดลอกข้ามแผนก · ของเดิม) และ `copyChecklistToEquipment`
   (คัดลอกข้ามเครื่อง · ของใหม่) **เรียกตัวเดียวกัน** — ห้ามก๊อปกฎไปไว้ในหน้า
2. 🔴 **เครื่องที่มีผลตรวจแล้ว ต้องถูกข้าม ห้ามทับ** — `inspection_results.checkpoint_id`
   เป็น `ON DELETE CASCADE` ⇒ ลบจุดตรวจเดิมเพื่อทับ = **ประวัติผลตรวจของเครื่องนั้นหายถาวร**
   ตัวตรวจคืน `{ copied: false, reason: 'target_has_history', history }` (**ไม่ throw** —
   ก้อนที่ล้มทีละเครื่องต้องไม่ทำให้ทั้งชุดหยุด) · `copyChecklistToDept` แปลงกลับเป็น throw
   เพื่อคงพฤติกรรมเดิมของจอนั้นไว้
3. 🔴 **เครื่องหนึ่งล้ม ห้ามหยุดทั้งก้อน** — `copyChecklistToEquipment` คืน `{ results }`
   **รายเครื่อง** แล้วจอต้องเขียนว่าสำเร็จกี่เครื่อง · ข้ามกี่เครื่อง · **เพราะอะไรรายตัว**
   (คัดลอก 20 เครื่องแล้วขึ้น toast เดียวว่า "สำเร็จ" = ไม่มีใครรู้ว่า 3 เครื่องไม่ได้ลง)
4. คัดลอกเฉพาะ **นิยามจุดตรวจ** — รอบเวลา/วันครบกำหนดของแต่ละเครื่องตั้งแยกกันเหมือนเดิม
5. 🔴 **รูปจุดตรวจถูก "แชร์ path" ไม่ได้ก๊อปไฟล์** (QC audit 08/10 · เกือบทำข้อมูลเสียถาวร)
   `copyCheckpointsInto()` ก๊อปเฉพาะแถว — `image_path` ชี้ไฟล์เดิมของเครื่องต้นแบบ
   ⇒ **ลบเครื่องต้นแบบ = รูปจุดตรวจของทุกเครื่องที่ก๊อปไป หายถาวร กู้ไม่ได้ ไม่มี error ฟ้อง**
   · ลบไฟล์ใน bucket `jig-images` ใต้ `jigs/` ต้องผ่าน **`orphanImagePaths()`**
     (`src/utils/jigImageRefs.js`) ซึ่งนับผู้อ้างจาก **3 ตาราง** — `jig_images` · `jigs` · `jig_checkpoints`
     (ขาดตารางไหน = รูปหายจากจอนั้น · ชุดเดียวกับที่ `recompressLayouts.js` §4 ใช้)
   · 🔴 **นับไม่ได้ = ไม่ลบ (fail-closed)** + เขียนบนจอว่าทำไมไม่ลบ · มีด่าน `jig-image-delete-needs-ref-count`
   · ของเดิมที่ทำถูกอยู่แล้ว: เส้นทาง *แก้ไข* จิ๊ก — แต่เดิมเช็คแค่ `jig_checkpoints` ตารางเดียว
     และกลืน error ⇒ 08/10 ย้ายมาใช้ของกลางตัวเดียวกันทั้ง 2 เส้นทาง
6. 🔴 **ล้มกลางทาง ต้องไม่เหลือ checklist เปล่าค้าง** — `withFreshChecklist()` ลบคืนเฉพาะแถวที่
   *เพิ่งสร้างเองและยังไม่มีจุดตรวจ* (คลาสเดียวกับที่ migration `20260805_pm_dept_ownership_cleanup`
   ต้องล้าง 24 แถว) · คัดลอกทีละหลายร้อยเครื่อง = ขยะหลายสิบแถวต่อการกดครั้งเดียว
7. **ลิสต์ปลายทางต้องบอกจำนวนที่ซ่อนเสมอ** (`แสดง N จาก M · ซ่อนชนิดอื่น K`) — ไม่บอก =
   ตัวกรองที่มองไม่เห็น (ฐานจริง 325 เครื่อง) · ช่องค้น = `<SearchInput>` (ตัวกรองลิสต์ติ๊กหลายตัว
   **ไม่ใช่** `MachineSelect` ซึ่งเลือกได้ตัวเดียว) · รหัสเครื่องห้ามถูก ellipsis ตัด (UI §6.21)
8. 🔴 **โหลดรายชื่อเครื่องล้ม = เขียนบนจอ** ห้ามปล่อยลิสต์ว่างแล้วอ่านว่า "ไม่มีเครื่องชนิดเดียวกัน"
   (เดิมกลืน error + ไม่มี paging ⇒ ชนเพดาน 1000 แถวเงียบ) — ผ่าน `fetchAllPages`
9. 🔴 **คัดลอกข้ามเครื่อง = ล้างตำแหน่งหมุด + `jig_id` = เครื่องปลายทาง** (14/10) — หมุด (`x_pos`/`y_pos`/
   `label_dx`/`label_dy`/`image_id`) ผูกกับ**รูปของเครื่องต้นทาง** · เดิมก๊อปไปด้วย ⇒ จอตั้งค่าโชว์หมุดบนรูปแรกของ
   เครื่องใหม่ผิดที่ · จอตรวจหาเฟรมไม่เจอ = หมุดหาย · กฎอยู่ **`checkpointCopyRow()` (`src/utils/pmCheckpointCopy.js` · มีเทส
   + ด่าน `pm-checkpoint-copy-via-util`)** · ข้ามแผนกบนเครื่องเดิม (`samePhotos`) = เก็บหมุดไว้ (รูปชุดเดียวกัน)
   · ข้อมูลเดิมที่ผูกผิดรูป 9 จุด (RB-121) ล้างหมุดแล้ว — migration `20261014c_pm_checkpoint_foreign_pins_dr.sql`
     (สำรองใน `archive.jig_cp_foreign_pins_20261014` · ช่างต้องปักใหม่)
   · ทิศ "ดึงจุดตรวจจากเครื่องอื่นมาใส่" **ไม่ทำ** (user 14/10: ใช้แบบส่งออกเดิม ช่างคุ้นแล้ว)
5. ลิสต์ปลายทาง **ตั้งต้นด้วยเครื่อง `equipment_kind` เดียวกัน** (โจทย์จริงคือ "ชนิดซ้ำๆกัน")
   แต่ค้นหาข้ามชนิดได้ — ไม่ใช่ล็อกตาย
