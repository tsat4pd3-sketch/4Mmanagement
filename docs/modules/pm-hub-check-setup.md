## 🎯 แถบ "ไปที่จุด" ในโมดัลตั้งค่าจุดตรวจ (2026-10-13)

- กด **+ เพิ่มจุดตรวจ** ⇒ เลื่อนไปการ์ดใหม่ท้ายลิสต์ให้เอง (เดิมเกิดนอกจอ ต้องเลื่อนหาเอง)

- 🔴 เลื่อนด้วย `modalBody.scrollTo()` **ห้าม `scrollIntoView`** (เลื่อนหน้าหลังโมดัลไปด้วย) และต้องหัก
  **padding บนของ modalBody + `top` ของแถบที่ตรึง + ความสูงแถบ** ไม่งั้นการ์ดไปจมใต้แถบ ·

- ⚠️ การ์ดถูกห่อด้วย `<div ref>` เพื่อวัดตำแหน่ง — **`key` อยู่ที่ div ห่อ** (ย้ายไปไว้ที่ `CheckpointCard` = React เตือน key)

### 🔴 ทำไม "ปุ่มเทากดไม่ได้" ผิด — บันทึกไม่ครบคือฟีเจอร์ ไม่ใช่บั๊ก

ตอนทำตัวอย่างให้ user ดู เคยเสนอว่า *"ทำปุ่มเทากดไม่ได้"* — **อ่านโค้ดจริงแล้วแบบนั้นผิด**
ใบตรวจที่ยังไม่ครบบันทึกเป็นสถานะ `'pending'` ซึ่ง **ไม่นับว่าทำ PM จบ ⇒ ไม่เลื่อนรอบ**
และมีไว้ให้ช่าง *"ตรวจค้างไว้ก่อน แล้วกลับมาทำต่อ"* (เครื่องยังเดินอยู่ ตรวจบางจุดไม่ได้)
บล็อกปุ่ม = ช่างเสียงานที่กรอกมาแล้วทั้งหมด แล้วหันไปกรอกส่งเดชให้ครบ = ข้อมูลแย่กว่าเดิม

⇒ ทำตามที่ทีม MTN เสนอเองเป๊ะ: **เปลี่ยนสี + ถามยืนยัน ไม่บล็อก**

### กฎ

- 🔴 **เกณฑ์ "ครบ" มีสูตรเดียว = `cpFilled(cp)`** — ห้ามเขียนเงื่อนไขซ้ำที่อื่นในหน้า

  ป้ายบอก **จำนวนจุดที่ยังไม่กรอก** ("⚠️ บันทึก (ยังไม่ครบ N จุด)") — ตัวเลข ไม่ใช่คำว่า "ไม่ครบ"

## 🧩 จอตรวจ `/pm-check-data` — แพทเทินเดียวกันทุกเครื่อง + รูปของจุดตรวจขึ้นจอใหญ่ (2026-11-10 · feedback หน้างาน)

> user: *"รูปที่ควรขยายใหญ่จากรูปเล็กๆ ในช่อง ทำไมไม่เอามาใช้ ตอนนี้ค้างที่รูปแรก · ทำไมแพทเทินไม่เหมือนกัน
> · จากทั้ง 2 ปัญหา ทำให้มันเห็นปนกันไปหมดเลย"*

**ต้นเหตุเดียวกันทั้ง 3 อาการ — ของ 3 อย่างถูกผูกไว้กับ "การปักหมุดบนรูป" (`jig_checkpoints.x_pos`) ทั้งที่ไม่เกี่ยวกัน**

| ผูกผิด | อาการที่หน้างานเจอ |
|---|---|
| รูปใหญ่เปลี่ยนตามข้อที่เลือก — เอฟเฟกต์ใน `JigSpinCheck` `return` ทิ้งเมื่อ `x_pos == null` | เลือกข้อไหนรูปก็ **ค้างที่เฟรมแรกของเครื่อง** · รูปของจุดตรวจ (`image_path`) เห็นได้ทางเดียวคือกดรูปเล็กให้เด้ง overlay |
| โหมดตรวจทีละข้อ `focusOn = … && allPinned` | เครื่องที่ยังปักไม่ครบ (RB-109 = 0/11) ตกไปใช้**ลิสต์ยาวทุกข้อ** = คนละหน้าตากับเครื่องข้างๆ |
| เลขข้อในแถว `{cp.x_pos != null && <span>{idx+1}</span>}` | เครื่องที่ยังไม่ปักหมุด **ทุกแถวไม่มีเลขเลย** ทั้งที่ชิป "ยังไม่ตรวจ" · สูตร `ข้อ N` · ปุ่มข้อก่อน/ถัดไป อ้างเลขนี้หมด ⇒ จับคู่ไม่ได้ว่าแถวไหนคือข้อไหน |

### กฎหลังแก้ (ทุก session ที่แตะจอนี้ต้องรู้)

- 🔴 **การปักหมุดจำเป็นแค่กับ "แตะหมุดบนรูปเพื่อเลือกข้อ"** — ไม่ใช่กับเลขข้อ ไม่ใช่กับตัวโหมดทีละข้อ
  · ปักไม่ครบ = ยังใช้โหมดทีละข้อได้ (เลือกข้อด้วยชิปเลข / ข้อก่อน-ข้อถัดไป) แค่แตะหมุดไม่ได้ — **จอต้องเขียนบอกว่าปักแล้วกี่/กี่** ห้ามบล็อกเงียบ
  · ป้ายปุ่ม: ปักครบ = `เฉพาะจุดที่แตะ` ↔ `ทุกข้อ` · ปักไม่ครบ = `ทีละข้อ` ↔ `ทุกข้อ`
- 🔴 **เลขข้อขึ้นเสมอ** ทุกชนิดแถว (`AttrRow` · `MeasureRow` · `VariableRow`)
- 🔴 **รูปของจุดตรวจขึ้นจอใหญ่ได้ แต่ห้ามวาดหมุดทับ** — พิกัดหมุดเป็น % ของ **รูปเครื่อง** (ผูก `image_id`)
  คนละรูปกับ `checkpoints.image_path` ⇒ วาดทับ = หมุดชี้ผิดจุด (กฎ §5.1 `docs/UI-CONVENTIONS.md`)
  · ตัวคุม = `onCpPhoto` ใน `JigSpinCheck` · ชั้นหมุดเงื่อนไข `imgBox && !onCpPhoto` · ลากหมุนเฟรมก็ปิดด้วย
  · **ค่าเริ่มต้น:** จุดที่ปักหมุดแล้ว = โชว์รูปเครื่องก่อน (ให้เห็นว่าจุดอยู่ตรงไหน) · จุดที่ยังไม่ปัก = โชว์รูปของจุดเลย
    (ไม่งั้นรูปใหญ่ไม่เกี่ยวกับข้อที่กำลังตรวจ) · มีปุ่มสลับ 2 ทางเสมอ + ป้ายบอกว่ากำลังดูรูปอะไร
- ด่าน `cp-number-not-tied-to-pin` ใน `regressionGuards` คุมทั้ง 3 ข้อ (พิสูจน์ 2 ทาง)

**ที่ยังไม่แตะ:** `layout_type === 'list'` (เครื่องที่ตั้งใจไม่มีรูป) ยังเป็นลิสต์ล้วนเหมือนเดิม —
ไม่มีรูปก็ไม่มีอะไรให้โฟกัส · เครื่องที่ยังไม่มีรูปเลย (`frames.length === 0`) เช่นกัน
