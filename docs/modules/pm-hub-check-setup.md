## 🟡 ปุ่มบันทึกใบตรวจ PM — ตรวจไม่ครบต้อง "เตือน" ไม่ใช่ "บล็อก" (2026-10-07)

**ที่มา — คอมเมนต์ทีม MTN ข้อ 3 (06/10):**
> *"Mode PM Check — ถ้ากรอกรายละเอียดไม่ครบทุกจุดให้ปุ่มบันทึกขึ้นเป็นสีแดงหรือสีเหลืองไว้ก่อน
> ได้มั้ยครับ ตอนนี้เป็นสีเขียว ถ้าพนักงานกดข้าม จะสามารถบันทึกได้ถึงข้อมูลจะไม่ครบครับ"*

### 🔴 ทำไม "ปุ่มเทากดไม่ได้" ผิด — บันทึกไม่ครบคือฟีเจอร์ ไม่ใช่บั๊ก

ตอนทำตัวอย่างให้ user ดู เคยเสนอว่า *"ทำปุ่มเทากดไม่ได้"* — **อ่านโค้ดจริงแล้วแบบนั้นผิด**
ใบตรวจที่ยังไม่ครบบันทึกเป็นสถานะ `'pending'` ซึ่ง **ไม่นับว่าทำ PM จบ ⇒ ไม่เลื่อนรอบ**
และมีไว้ให้ช่าง *"ตรวจค้างไว้ก่อน แล้วกลับมาทำต่อ"* (เครื่องยังเดินอยู่ ตรวจบางจุดไม่ได้)
บล็อกปุ่ม = ช่างเสียงานที่กรอกมาแล้วทั้งหมด แล้วหันไปกรอกส่งเดชให้ครบ = ข้อมูลแย่กว่าเดิม

⇒ ทำตามที่ทีม MTN เสนอเองเป๊ะ: **เปลี่ยนสี + ถามยืนยัน ไม่บล็อก**

### กฎ

- 🔴 **เกณฑ์ "ครบ" มีสูตรเดียว = `cpFilled(cp)`** — ห้ามเขียนเงื่อนไขซ้ำที่อื่นในหน้า
  (เคยมี 3 ชุดคนละเกณฑ์: progress bar · `isFormReady` · นิพจน์ในปุ่ม — `isFormReady` ใช้
  `r.attr !== ''` ซึ่งนับ `undefined` ว่า "กรอกแล้ว" ⇒ **แถบความคืบหน้ากับปุ่มขัดกันเองได้**)
- ครบ → ปุ่ม `var(--accent)` (เขียว) · ไม่ครบ → `var(--accent2)` (เหลือง/ส้ม) +
  ป้ายบอก **จำนวนจุดที่ยังไม่กรอก** ("⚠️ บันทึก (ยังไม่ครบ N จุด)") — ตัวเลข ไม่ใช่คำว่า "ไม่ครบ"
- ไม่ครบ → `confirm()` ก่อนบันทึก (กันกดพลาด) · ยืนยันแล้วบันทึกได้ตามเดิม

## 📋 คัดลอกแผน PM จากเครื่องอื่น (2026-10-07)

**ที่มา — คอมเมนต์ทีม MTN ข้อ 2 (06/10):**
> *"ถ้าสามารถ Copy แผน PM จากอีกเครื่องได้จะดีมาก เนื่องจาก MTN มีเครื่องจักรหลายตัว (325 Pc)
> แต่ชนิดซ้ำๆกัน จุดการ PM เหมือนกันหมด"*

### 🔴 กฎที่ห้ามแก้ให้ง่ายขึ้น

1. **กฎทั้งหมดอยู่ใน `copyCheckpointsInto()` (`src/lib/pmChecklists.js`) ที่เดียว**
   `copyChecklistToDept` (คัดลอกข้ามแผนก · ของเดิม) และ `copyChecklistToEquipment`
   (คัดลอกข้ามเครื่อง · ของใหม่) **เรียกตัวเดียวกัน** — ห้ามก๊อปกฎไปไว้ในหน้า
2. 🔴 **เครื่องที่มีผลตรวจแล้ว ต้องถูกข้าม ห้ามทับ** — `inspection_results.checkpoint_id`
   เป็น `ON DELETE CASCADE` ⇒ ลบจุดตรวจเดิมเพื่อทับ = **ประวัติผลตรวจของเครื่องนั้นหายถาวร**
   ตัวตรวจคืน `{ copied: false, reason: 'target_has_history', history }` (**ไม่ throw** —
   ก้อนที่ล้มทีละเครื่องต้องไม่ทำให้ทั้งชุดหยุด) · `copyChecklistToDept` แปลงกลับเป็น throw
   เพื่อคงพฤติกรรมเดิมของจอนั้นไว้
3. 🔴 **เครื่องหนึ่งล้ม ห้ามหยุดทั้งก้อน** — `copyChecklistToEquipment` คืน `{ results }`
   **รายเครื่อง** แล้วจอต้องเขียนว่าสำเร็จกี่เครื่อง · ข้ามกี่เครื่อง · **เพราะอะไรรายตัว**
   (คัดลอก 20 เครื่องแล้วขึ้น toast เดียวว่า "สำเร็จ" = ไม่มีใครรู้ว่า 3 เครื่องไม่ได้ลง)
4. คัดลอกเฉพาะ **นิยามจุดตรวจ** — รอบเวลา/วันครบกำหนดของแต่ละเครื่องตั้งแยกกันเหมือนเดิม
5. ลิสต์ปลายทาง **ตั้งต้นด้วยเครื่อง `equipment_kind` เดียวกัน** (โจทย์จริงคือ "ชนิดซ้ำๆกัน")
   แต่ค้นหาข้ามชนิดได้ — ไม่ใช่ล็อกตาย

### โครงข้อมูล

`jigs` (ทะเบียนอุปกรณ์ · `module='mtn'`) → `checklists` → `jig_checkpoints` → `inspection_results`
⚠️ ชื่อตาราง `jigs` เป็นชื่อเดิมตั้งแต่ตอนมีแต่จิ๊ก — **ตอนนี้เก็บเครื่องจักรด้วย** ห้ามอ่านจากชื่อ
