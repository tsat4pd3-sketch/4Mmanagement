# 🔔 แจ้งเตือนในแอป — สภาพจริง (audit 2026-09-24)

> **บริบท:** user สั่ง 24/09 *"เราไม่คุยเรื่อง telegram ละ ปล่อยค้างไว้ เราเน้นการแจ้งเตือนผ่านตัวแอพเองละ"*
> ⇒ กระดิ่งในแอป (+ Web Push) กลายเป็น **ช่องทางเดียว** ที่ถือว่า "ถึงคนจริง"
> เอกสารนี้ = ตัวเลขที่วัดได้ ณ วันนั้น เพื่อให้ session ถัดไปไม่ต้องเดา

## 1. 🔴 กระดิ่งท่วมจนคนเลิกอ่าน — นี่คือปัญหาใหญ่ที่สุด

| ตัวชี้วัด (7 วันล่าสุด) | ค่า |
|---|---:|

> 🔴 **อ่าน 7% = กระดิ่งตายไปแล้วในทางปฏิบัติ**
> **การเติม event ใหม่เข้าช่องที่คนไม่อ่าน ไม่ได้ทำให้ข่าวถึงคน — ทำให้แย่ลง**
> ⇒ ลำดับที่ถูก: **ลดเสียงรบกวนก่อน แล้วค่อยอุด event ที่ขาด**

ต้องเจาะด้วยขอบเขต (ส่วนงาน/ไลน์/ทีม) หรือยิงถึง "ผู้รับผิดชอบคนเดียว" แล้วค่อยขยายเมื่อเกินเวลา

## 4. ✅ กฎที่ตกผลึกจาก audit นี้ (ใช้กับทุก event ใหม่)

1. 🔴 **`inapp_roles` ว่าง = ไม่ถึงใคร** — ไม่ใช่ "opt-in เงียบตามเดิม" อีกต่อไป
   ⇒ **event ใหม่ต้องตั้งผู้รับในแอปตั้งแต่ migration** (ตัวอย่าง: `mtn_accept_pending` 24/09)
2. 🔴 **ยิงตาม role เฉยๆ = fan-out ทั้งโรงงาน** — ต้องเจาะขอบเขตเสมอ
   (`inapp_match_section` / `inapp_match_line` / `inapp_scope_strict`)
3. 🔴 **ตัดสินก่อนว่า "เหตุการณ์นี้ควรเด้งไหม" ก่อนจะถามว่า "ส่งถึงใคร"** —
   ของปกติที่เกิดทุกวันไม่ต้องเด้ง (ดูเกณฑ์ `!stuck && list.length < 3` ใน `mtn-daily-summary`)
4. **วัดผลด้วย % อ่าน ไม่ใช่จำนวนที่ส่ง** — ส่งเยอะแต่ไม่มีใครอ่าน = ไม่ได้แจ้งเตือน

## 6. 🟠 #2 แจ้งซ่อมใหม่ — **รากคือทะเบียนผู้ใช้ไม่ครบ ไม่ใช่โค้ด**

**วัดจริง 7 วัน: 101 ใบ → 3,196 กระดิ่ง = 31.6 คน/ใบ · อ่าน 8.8%** (14.5% ของทั้งระบบ)

โค้ดกับทะเบียนถูกแล้วทั้งคู่:
- `send-mtn-notification` ส่ง `p_section` + `p_team` + `p_line` ครบ (แก้ไปแล้ว 23/09)
- กฎ `mtn_reported` ตั้ง `match_section` + `match_line` + `scope_strict` = true ครบ

**แต่ตัวกรองไม่กัดใครเลย เพราะทะเบียนว่าง** — `notify_recipients` ปล่อยผ่านเมื่อค่าว่าง (by design):

| role | คน | `mtn_teams` ว่าง | ไม่มี section | ไม่มี line |
|---|---:|---:|---:|---:|
| leader | 19 | **19 (100%)** | 0 | 0 |
| mtn | 15 | 0 | **9 (60%)** | **15 (100%)** |

⇒ leader ผ่านแกนทีมทุกคน · ช่างผ่านแกนส่วนงาน/ไลน์เกือบทุกคน ⇒ 34 คน เหลือ 31.6 คน/ใบ

> 🔑 **บทเรียน: ตั้งค่ากฎให้ถูกไม่พอ — ถ้าทะเบียนคนว่าง ตัวกรองจะ "ผ่านหมด" แบบเงียบๆ**
> และมันเงียบเพราะ "ค่าว่าง = ไม่กรอง" เป็นพฤติกรรมที่ตั้งใจ (กัน fail-closed จนไม่มีใครได้รับ)

**ทางแก้มี 2 ทาง — เป็น product decision ต้องให้ user เคาะ (ดู §7)**

## 7. 📌 ยังไม่ได้ทำ — รอ user เคาะ
- **#2 แจ้งซ่อมใหม่** — เลือก 1 ใน 2 ทาง:
  (ก) **กรอกทะเบียนให้ครบ** (`mtn_teams` ของ leader 19 คน · section/line ของช่าง) — ไม่ต้องแก้โค้ด
      ตัวกรองที่มีอยู่จะเริ่มทำงานเอง · **ปลอดภัยกว่า** เพราะไม่เปลี่ยนกติกา
  (ข) **เปลี่ยนกติกาเป็น "ไม่ผูกทะเบียน = ไม่ได้รับ"** — ได้ผลทันทีแต่ **เสี่ยง**:
      คนที่ควรรู้แต่ยังไม่ได้ตั้งทะเบียน จะหยุดได้รับแจ้งเตือนเงียบๆ
- เติมผู้รับในแอปให้ 13 event ที่พึ่ง Telegram ล้วน (**เป็น product decision — ใครควรได้รู้**)
- ดัน Web Push จาก 24% ขึ้น (ต้องมีคนพาพนักงานกดอนุญาต — ไม่ใช่งานโค้ดล้วน)
