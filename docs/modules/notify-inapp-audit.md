# 🔔 แจ้งเตือนในแอป — สภาพจริง (audit 2026-09-24)

> **บริบท:** user สั่ง 24/09 *"เราไม่คุยเรื่อง telegram ละ ปล่อยค้างไว้ เราเน้นการแจ้งเตือนผ่านตัวแอพเองละ"*
> ⇒ กระดิ่งในแอป (+ Web Push) กลายเป็น **ช่องทางเดียว** ที่ถือว่า "ถึงคนจริง"
> เอกสารนี้ = ตัวเลขที่วัดได้ ณ วันนั้น เพื่อให้ session ถัดไปไม่ต้องเดา

---

## 1. 🔴 กระดิ่งท่วมจนคนเลิกอ่าน — นี่คือปัญหาใหญ่ที่สุด

| ตัวชี้วัด (7 วันล่าสุด) | ค่า |
|---|---:|
| กระดิ่งที่ส่งออก | **22,029 ใบ** |
| ผู้รับ | 94 คน (จากทั้งหมด 97) |
| เฉลี่ย | **~33 ใบ/คน/วัน** |
| **อ่านแล้ว** | **1,523 ใบ = 6.9%** |

> 🔴 **อ่าน 7% = กระดิ่งตายไปแล้วในทางปฏิบัติ**
> **การเติม event ใหม่เข้าช่องที่คนไม่อ่าน ไม่ได้ทำให้ข่าวถึงคน — ทำให้แย่ลง**
> ⇒ ลำดับที่ถูก: **ลดเสียงรบกวนก่อน แล้วค่อยอุด event ที่ขาด**

### ต้นเหตุ = fan-out กว้างเกิน (ไม่ใช่ยิงซ้ำ)

| เรื่อง | ใบ/7 วัน | ผู้รับ | อ่าน |
|---|---:|---:|---:|
| 📊 ขออนุมัติอัพระดับทักษะ | **1,247** | 29 | **2.2%** |
| เตือนรอบ PM (30/14/3 วัน) | 782 | 24 | 7.0% |
| หลุดเฟสงานส่ง (walkback) | 768 | 14 | 7.9% |
| 🛠️ แจ้งซ่อมใหม่ (รวมทุกไลน์) | **~2,100+** | 32–40 **ต่อใบ** | 5–11% |
| พบผลตรวจไม่ผ่าน (NG) | 164 | 82 | 4.9% |

**พิสูจน์ว่าเป็น fan-out ไม่ใช่ repeat:** อันดับ 1 เกิดขึ้น**วันเดียว (21/09)** · เนื้อความต่างกัน 43 แบบ ·
ผู้รับ 29 คน → **43 × 29 = 1,247 เป๊ะ** ⇒ **1 คำขออนุมัติ = เด้ง 29 คน** (ไม่ได้ยิงซ้ำทุกคืน)
เช่นเดียวกับใบแจ้งซ่อม: **1 ใบ = เด้ง 32–40 คน**

🔑 **บทเรียน: ยิงตาม "role" = ยิงทุกคนที่มี role นั้น ไม่ใช่คนที่ต้องกด**
ต้องเจาะด้วยขอบเขต (ส่วนงาน/ไลน์/ทีม) หรือยิงถึง "ผู้รับผิดชอบคนเดียว" แล้วค่อยขยายเมื่อเกินเวลา

⇒ เรื่องด่วนที่ส่งตอนคนไม่ได้เปิดแอป **ไปไม่ถึง**

## 4. ✅ กฎที่ตกผลึกจาก audit นี้ (ใช้กับทุก event ใหม่)

1. 🔴 **`inapp_roles` ว่าง = ไม่ถึงใคร** — ไม่ใช่ "opt-in เงียบตามเดิม" อีกต่อไป
   ⇒ **event ใหม่ต้องตั้งผู้รับในแอปตั้งแต่ migration** (ตัวอย่าง: `mtn_accept_pending` 24/09)
2. 🔴 **ยิงตาม role เฉยๆ = fan-out ทั้งโรงงาน** — ต้องเจาะขอบเขตเสมอ
   (`inapp_match_section` / `inapp_match_line` / `inapp_scope_strict`)
3. 🔴 **ตัดสินก่อนว่า "เหตุการณ์นี้ควรเด้งไหม" ก่อนจะถามว่า "ส่งถึงใคร"** —
   ของปกติที่เกิดทุกวันไม่ต้องเด้ง (ดูเกณฑ์ `!stuck && list.length < 3` ใน `mtn-daily-summary`)
4. **วัดผลด้วย % อ่าน ไม่ใช่จำนวนที่ส่ง** — ส่งเยอะแต่ไม่มีใครอ่าน = ไม่ได้แจ้งเตือน
