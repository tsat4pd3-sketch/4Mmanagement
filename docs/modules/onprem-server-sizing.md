## 5. สเปคที่ขอ (ฉากทัศน์ B · 10 ปี · โรงงานนี้)

### 💾 ดิสก์ — **1 TB NVMe** (ใช้จริง ~450 GB · ที่เหลือเผื่อ 15 ปี)

| รายการ | ขอ | ที่มา |
|---|---:|---|
| ฐานข้อมูล | 150 GB | 94 GB × 1.6 (WAL + bloat + temp + index ที่โตตาม) |
| ไฟล์/รูป | 100 GB | 90 GB × 1.1 |
| พื้นที่ backup ในเครื่อง (WAL archive + base backup) | 150 GB | ~1.5× ฐานข้อมูล |
| OS + แอป + log + monitoring | 50 GB | |
| **ใช้จริง** | **~450 GB** | |

🔴 **NVMe ที่มี power-loss protection** — Postgres พึ่ง `fsync` ถ้าดิสก์โกหกว่าเขียนลงแล้ว
ไฟดับ = ฐานข้อมูลเสียหาย · **ห้ามใช้ SAN/NAS ที่แชร์กับงานอื่น** (Postgres แพ้ noisy neighbour)
🔴 **ห้ามใช้ thin provisioning ที่ over-commit** — ดิสก์เต็มระดับ host = Postgres พังแบบกู้ยาก

### 🧠 RAM — **64 GB**

- ที่ 10 ปีฐานข้อมูล ~94 GB แต่ **ชุดข้อมูลร้อนไม่ใช่ทั้งก้อน** — คิวรีเกือบทั้งหมดกรองด้วยช่วงวันที่
  (`work_date` · `created_at` ย้อนหลัง 30–90 วัน) ⇒ ชุดร้อนประมาณ **10–15 GB**
- ต้องรัน **Postgres 2 ชุด** (Main + DR) — 🔴 **ห้ามยุบเป็นชุดเดียว** เพราะฝั่ง DR เป็น `anon`
  ทั้งโปรเจค (📄 `CLAUDE.md` §Supabase Projects) + GoTrue · PostgREST ×2 · Realtime ×2 ·
  Storage API · Kong · Edge runtime (Deno) ≈ 4–8 GB
- จัดสรรคร่าวๆ: `shared_buffers` รวม ~16 GB · OS page cache ~35 GB · services ~8 GB
- **32 GB พอถึงปีที่ 5 · 64 GB ครอบ 10 ปี** และราคาต่างกันไม่มากพอที่จะเสี่ยง

### ⚙️ CPU — **16 cores** (x86-64 หรือ ARM64 ก็ได้)

- วันนี้ 2 vCPU เอาอยู่ (56 connections · 15.5M transactions)
- ที่ 10 ปี: ผู้ใช้ ×2 · แถว QA ×12.5 · realtime subscription เพิ่มตามจอ
- **8 cores น่าจะพอ แต่ขอ 16** เพราะต้องมีหัวให้ **backup + `vacuum` + report หนัก
  รันพร้อมหน้างานได้โดยไม่สะดุด** (บทเรียน `vacuum full` 17/11: งานบำรุงรักษาแย่ง I/O กับหน้างานจริง)

### 🔌 Connection pooling — **บังคับมี (ห้ามข้าม)**

🔴 วันนี้ **56 จาก 90 connections** แล้วฝั่ง DR ทั้งที่ยังใช้แค่ 8 พาร์ท / 81 คน
⇒ self-host ต้องมี **Supavisor หรือ PgBouncer โหมด transaction** หน้า Postgres
ไม่มี = ผู้ใช้เพิ่ม 2 เท่าแล้ว connection เต็ม ⇒ **เปิดกะไม่ได้** (อาการเดียวกับที่เคยเจอ ก.ย.)

### 🌐 เครือข่าย

- ใน LAN: 1 Gbps พอเหลือ
- 🔴 **ต้องเข้าจากนอกโรงงานได้** — คนใช้มือถือ 4G/5G จริง (วัดได้ 679 IP แยกกัน 13/10)
  ⇒ reverse proxy + TLS + firewall (หรือ VPN) · ต้องมี public DNS + ใบรับรองที่ต่ออายุอัตโนมัติ
- ปริมาณ: วันนี้ ~17 GB/เดือน · เต็มโรงงานคาด 50–100 GB/เดือน (เล็กสำหรับเน็ตองค์กร
  แต่ต้องเปิดทางให้ผ่าน ไม่ใช่โดน proxy บริษัทบล็อก)

### 💽 Backup — 🔴 **เครื่องเดียวไม่ใช่แผนเก็บ 10 ปี**

ข้อบังคับคือ **เก็บ 7–15 ปี** ⇒ server ตัวเดียวพัง = บันทึกคุณภาพหายทั้งหมด **ผิดข้อกำหนดลูกค้า**
ต้องมีครบ 3 ชั้น:
1. **WAL archiving + base backup (PITR)** — `pgBackRest` หรือ `Barman`
   · repo อยู่ **เครื่องอื่น** ห้ามอยู่ดิสก์เดียวกับฐานข้อมูล
2. **สำเนานอกสถานที่** (NAS คนละอาคาร / cloud object storage) — ไฟไหม้/น้ำท่วมห้อง server
3. **archive รายปีแบบเขียนทับไม่ได้** สำหรับภาระ 10 ปี (ไม่ใช่ backup หมุนเวียน
   เพราะ backup หมุนเวียนทับของเก่าทิ้ง)
🔴 **ซ้อมกู้คืนสำเร็จจริงอย่างน้อย 1 ครั้งก่อนย้าย** (เป็นเงื่อนไขอยู่แล้วใน `deploy.md`)

### 🔁 เครื่องสำรอง — **ควรขอ 2 เครื่อง**

เงื่อนไขใน `deploy.md` ข้อ 4 คือ *"แผนตอน server ล่มตี 2"* · ตอนนี้ **ทั้งโรงงานพึ่งระบบนี้แล้ว
ล่ม = เปิดกะไม่ได้ = เสียหายจริง** ⇒ เครื่องเดียวคือรับความเสี่ยงนั้นไว้เต็มๆ
- ทางที่ควรเป็น: **primary + standby (streaming replication)** สลับมือได้
- ถ้างบได้เครื่องเดียว → **ต้องมีแผนสำรองที่เขียนไว้และซ้อมแล้ว** ว่าหน้างานทำงานต่อยังไงระหว่าง
  server ล่ม (ฟอร์มกระดาษชุดไหน · ใครคีย์ย้อนหลัง) **ห้ามปล่อยให้ "ค่อยคิดตอนล่ม"**

## 7. 🔴 สิ่งที่สเปคเครื่องแก้ไม่ได้ — อย่าขอเครื่องแล้วคิดว่าจบ

เงื่อนไข 4 ข้อใน `deploy.md` §ขั้น 2 **ยังอยู่ครบ** เครื่องแรงไม่ได้แทนข้อไหนเลย:
1. **คนดูแลจริง** (ไม่ใช่ AI session) — patch · ต่ออายุใบรับรอง · ดู log
2. **backup + ซ้อมกู้คืนสำเร็จจริง**
3. **ทางเข้าจากมือถือนอกเครือข่ายที่ปลอดภัย**
4. **แผนตอน server ล่มตี 2**

🔴 **และข้อที่ใหญ่สุด: ฝั่ง DR เป็น `anon` ทั้งโปรเจค**
เปิดออกอินเทอร์เน็ตโดยไม่มีด่านหน้า = ใครก็อ่านข้อมูลผลิตทั้งโรงงานได้
⇒ **ต้องปิดช่องนี้ก่อนย้าย** (Edge Function ที่ validate ฝั่ง server — ยังเป็น known gap)
ไม่ใช่เรื่องสเปคเครื่อง แต่เป็นเรื่องที่ต้องเสร็จก่อนเปิดใช้จริง

🔑 **ย้าย hosting ไม่ลด egress ของ Supabase แม้แต่ไบต์เดียว** — ถ้ายังไม่ย้ายฐานข้อมูลตามไป
(📄 `deploy.md` §แยกให้ออกก่อน) · ห้ามใช้เหตุผลนี้ในใบขอ
