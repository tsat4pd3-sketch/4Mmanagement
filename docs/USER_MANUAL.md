## 1. การเข้าสู่ระบบและสิทธิ์ผู้ใช้

เข้าเว็บ → กรอก Email + Password ที่ Admin สร้างให้ → เข้าสู่ระบบ
เปลี่ยนรหัสผ่านได้จากเมนูโปรไฟล์มุมขวาบน

### บทบาท (Role) ทั้ง 5 แบบ

| Role | สิทธิ์ |
|------|-------|
| **Admin** | ทุกอย่าง รวมถึงสร้าง/แก้ไขผู้ใช้ระบบ |
| **Manager** | ดูและแก้ไขได้ทุกหน้า ยกเว้น Add User |
| **Supervisor** | จัดการเฉพาะ section ตัวเอง, ลงทะเบียนพนักงาน, อนุมัติ 4M ขั้นแรก, เปิด-ปิดกะผลิต |
| **Leader** | เห็นเฉพาะไลน์/ทีมตัวเอง, เช็คชื่อ, สแกน Order |
| **QA** | ดู Dashboard + Report, อนุมัติ 4M ขั้น QA |

## 2. Dashboard

**เส้นทาง:** `/` · **เข้าได้:** ทุก role

หน้าแรกแสดงภาพรวมโรงงานแบบ real-time

### 2.1 KPI Cards (แถวบน)
- **👥 พนักงานทั้งหมด** — กำลังคนของกะที่เลือก
- **✅ อัตรามาทำงาน** — (มาทำงาน ÷ กำลังคน) × 100%
- **🦺 PPE ครบ** — % ของคนที่มาและสวมหมวก+รองเท้า+ถุงมือครบ
- **⏰ OT** — จำนวนคนที่ทำ OT วันนี้
- **🚨 4M Alerts** — จำนวนการเปลี่ยนแปลง 4M วันนี้

### 2.2 ตัวกรอง
- **สลับกะ:** ☀️ กะเช้า / 🌙 กะดึก / ทั้งหมด — ระบบสลับให้อัตโนมัติตามเวลาจริง (20:00 เปลี่ยนเป็นกะดึก)
- **เลือกวันที่:** ดูข้อมูลย้อนหลังได้ — ก่อน 08:00 น. ระบบนับเป็นวันทำงานก่อนหน้า

### 2.3 สถานะการผลิต (Production Status)
แสดงทุกกะผลิตที่เปิดอยู่วันนี้ (ข้อมูลจาก Daily Report):
- ยอดผลิตจริง / ยอดตามแผน (Kanban) พร้อม progress bar
- **OEE แบบ real-time** ของกะที่ยังเปิดอยู่ — แสดง A (Availability), P (Performance), Q (Quality) และ OEE รวม
- สี: 🟢 ≥85% · 🟡 65–84% · 🔴 <65%
- อัปเดตทันทีเมื่อมีการสแกน Order / บันทึก Downtime / บันทึกงานเสีย

### 2.4 สถานะไลน์ (Line Status Grid)
การ์ดแต่ละไลน์แสดงอัตรามาทำงาน + badge "🚨 N Alerts" ถ้ามี 4M change

### 2.5 ผังไลน์ (Floor Maps)
- คลิกการ์ดไลน์เพื่อขยายดูผังเต็มจอ
- เห็นพนักงานที่ถูก assign แต่ละสถานี พร้อมสีบอกระดับทักษะ
- ช่วง OT พิเศษ (20:00–23:00) พนักงานกะเช้าที่ทำ OT+ ยังแสดงบนผังกะดึก

### 2.6 4M Activity Feed
รายการ 4M ล่าสุดของวัน แยกสีตามหมวด: 👤 Man (น้ำเงิน) / ⚙️ Machine (ส้ม) / 📦 Material (ม่วง) / 📋 Method (เขียว)

## 3. Check-in

**เส้นทาง:** `/checkin` · **เข้าได้:** ทุก role (Leader เห็นเฉพาะไลน์ตัวเอง)

ใช้เช็คชื่อ ตรวจ PPE และบันทึกการลา **ทุกวัน ก่อนเริ่มงาน**

### 3.1 วิธีเช็คชื่อ
1. (Admin/Manager) เลือก Section → ไลน์ จากแถบกรองด้านบน
2. แต่ละแถวพนักงาน ติ๊ก:
   - **มางาน** — ถ้ามาทำงาน
   - **หมวก / รองเท้า / ถุงมือ** — PPE ที่สวมครบ (ติ๊กได้เมื่อมางานเท่านั้น)
   - **OT** — ทำ OT ปกติ (กะเช้า 17:30–20:00)
   - **OT+23** — OT พิเศษถึง 23:00
3. กด **💾 บันทึก** ด้านบน

### 3.2 การลางาน
ในคอลัมน์ "ลา" เลือกประเภท: **ลากิจ / ลาป่วย / ลาพักร้อน** แล้วเลือกระยะ:
- **เต็มวัน** → ระบบติ๊ก "ไม่มางาน" ให้อัตโนมัติ
- **ครึ่งวัน** → เลือก 🌅 เช้า หรือ 🌇 บ่าย (ยังนับว่ามางาน)
- **ระบุชั่วโมง** → กรอกจำนวนชั่วโมง (0.5–8)

### 3.3 สรุปสถานะ (Pills ด้านบน)
🟢 พร้อม (มา+PPE ครบ) · 🟡 PPE ไม่ครบ · 🔴 ขาดงาน · 🟣 ลาเต็มวัน · 🔵 ลาช่วง

### 3.4 ระบบสะสมทักษะอัตโนมัติ (Skill Farming)
ทุกวันที่พนักงานถูก assign ที่สถานีที่ต้องใช้ทักษะ คะแนนทักษะนั้นจะ **+1 อัตโนมัติ** เมื่อบันทึกเช็คชื่อ — พนักงานเก่งขึ้นตามจริงโดยไม่ต้องกรอกมือ

## 4. Line Management

**เส้นทาง:** `/management` · **เข้าได้:** ทุก role (Leader ล็อกที่ไลน์ตัวเอง)

หัวใจของระบบ — จัดพนักงานลงสถานีงานบนผังไลน์จริง พร้อมตรวจทักษะและสร้าง 4M log อัตโนมัติ

### 4.1 ส่วนประกอบหน้าจอ
- **ซ้าย — Pool พนักงาน:**
  - 🔵 พร้อมทำงาน: มางาน + PPE ครบ + ยังไม่ถูก assign
  - 🟡 งานนอกไลน์: ทำงานพิเศษ (5ส, คัดงาน ฯลฯ)
- **กลาง — ผังไลน์:** สถานีทั้งหมด พร้อมพนักงานที่ assign แล้ว
- **บน — แถบสถานะผลิต:** ยอดผลิต/แผน + OEE ของกะที่เปิดอยู่ (real-time)

### 4.2 วิธี Assign พนักงาน
- **Desktop:** ลากการ์ดพนักงานจาก pool ไปวางที่สถานี
- **Mobile:** แตะเลือกพนักงาน → แตะสถานีปลายทาง

ระบบจะแสดง **% ความเหมาะสม (Skill Fit)** ทันที:
| Fit % | สี | ความหมาย |
|-------|-----|----------|
| 100+ | 🟣 ม่วง | ผู้เชี่ยวชาญ |
| 75–99 | 🟢 เขียว | แก้ปัญหาได้ |
| 50–74 | 🟢 เขียวอ่อน | มาตรฐาน |
| 25–49 | 🟡 เหลือง | ต้องดูแล |
| <25 | 🔴 แดง | ยังไม่ผ่าน OJT |

Fit = (จำนวนทักษะที่ผ่านเกณฑ์ขั้นต่ำ ÷ ทักษะที่สถานีต้องการ) × 100

### 4.3 ระบบ 4M อัตโนมัติ (หมวด Man)
เมื่อย้ายคน ระบบจะวิเคราะห์และสร้าง 4M log ให้เองตาม 3 กรณี:

| กรณี | เงื่อนไข | ผลลัพธ์ |
|------|---------|---------|
| 1 | ไลน์เดิม + ทักษะผ่าน + มีประวัติเคยทำ | ✅ อนุมัติอัตโนมัติ เงียบๆ |
| 2 | ข้ามไลน์ + ทักษะผ่าน | SV อนุมัติ + แนบรูป OJT |
| 3 | ข้ามไลน์ + ทักษะไม่ผ่าน/ไม่มีประวัติ | SV + **QA** อนุมัติ + แนบรูป OJT |

### 4.4 บันทึก 4M หมวดอื่น (Machine / Material / Method)
กดปุ่มหมวดที่ต้องการ → กรอกรายละเอียด → แนบรูป (ถ้ามี) → ส่งเข้า approval workflow:
```
pending → SV อนุมัติ → pending_qa (ถ้าต้อง QA) → QA อนุมัติ → approved
                                              ↘ reject → rejected + เหตุผล
```
ทุกการเปลี่ยนสถานะแจ้งเตือนเข้า **Telegram Group + กระดิ่งในแอพ** ทันที

### 4.5 งานนอกไลน์ (Special Tasks)
ลากพนักงานไปที่โซน "งานนอกไลน์" → เลือกประเภท: 5ส / คัดงาน / แก้ไขปัญหาคุณภาพ / งานปรับปรุงไลน์ / อื่นๆ
เมื่อลากกลับมาลงสถานีผลิต งานพิเศษจะถูกล้างอัตโนมัติ

## 5. Daily Report

**เส้นทาง:** `/daily-report` · **เข้าได้:** ทุก role (ตั้งค่าได้เฉพาะ Admin/Manager/SV)

ระบบบันทึกการผลิตรายกะแบบครบวงจร: เปิดกะ → สแกน Order → บันทึก Downtime/งานเสีย → ปิดกะพร้อม OEE

### 5.1 โครงสร้าง 3 แท็บ
- **⚡ Live กะนี้** — งานประจำวัน
- **📋 ประวัติ** — กะที่ปิดแล้วทั้งหมด + OEE + รายละเอียด
- **⚙️ ตั้งค่า** — master data (เฉพาะ Admin/Manager/SV)

### 5.2 เปิดกะ (SV/Manager/Admin)
1. กด **+ เปิดกะใหม่**
2. เลือก: วันที่ / ไลน์ / กะ (เช้า-ดึก) / **สินค้าที่ผลิต** (กรองตามไลน์อัตโนมัติ) / เวลาเริ่ม
3. กดเปิดกะ — ถ้ามีกะเก่ายังไม่ปิด ระบบจะเตือน ⚠️ ให้ปิดก่อน

> ⚠️ ต้องเลือกสินค้าเสมอ เพราะ cycle time ของสินค้าใช้คำนวณ OEE

### 5.3 สแกนเปิด Order (📥)
ใช้เมื่อรับ Tag Card / Kanban มาเริ่มผลิต:
1. กด **📥 Scan เปิด Order**
2. ยิงบาร์โค้ด **PROD.NO** → ยิง **MAT.NO** → ระบบดึงชื่องาน, ลูกค้า, จำนวน/kanban จาก Kanban Standard ให้อัตโนมัติ
3. กดเปิด — Modal ไม่ปิด สแกนใบถัดไปต่อได้ทันที
4. ระบบกัน PROD.NO ซ้ำในกะเดียวกัน

### 5.4 สแกนปิด Order (📤 Confirm)
เมื่อผลิตครบจำนวน:
1. กด **📤 Scan ปิด / Confirm**
2. ยิง PROD.NO → ระบบแสดงข้อมูล Order ที่ตรงกัน
3. กด Confirm — Order เปลี่ยนเป็น ✓ ปิดแล้ว (นับยอดเต็มจำนวน)

> การปิด Order = ยืนยันว่าผลิต **ครบเต็มจำนวน** เท่านั้น — งานเสียบันทึกแยกต่างหาก (ข้อ 5.6)

### 5.5 บันทึก Downtime (⏱)
บันทึกทุกครั้งที่ไลน์หยุด:
1. กด **+ บันทึก Downtime**
2. เลือกประเภท (เครื่องเสีย, รอวัตถุดิบ, ประชุม ฯลฯ — แยก "ในแผน/นอกแผน")
3. เลือกวิธีกรอกเวลา 1 ใน 3 แบบ:
   - **เริ่ม → จบ:** กรอกเวลาหยุด + เวลากลับมา (คำนวณนาทีให้)
   - **เริ่ม + นาที:** กรอกเวลาเริ่ม + จำนวนนาที
   - **จบ + นาที:** กรอกเวลากลับมา + จำนวนนาที
4. ระบุเครื่องจักร (ถ้ามี) + รายละเอียด → บันทึก

กะดึกข้ามเที่ยงคืน ระบบจัดการวันที่ให้อัตโนมัติ (เวลาก่อน 08:00 = วันถัดไป)

### 5.6 บันทึกงานเสีย (🔴)
บันทึกได้ตลอดกะ ไม่ต้องรอปิด Order:
1. กด **🔴 บันทึกงานเสีย**
2. เลือก **ประเภทงานเสีย** (จาก master ที่ตั้งค่าไว้)
3. กรอกจำนวน 3 ช่อง (กรอกเฉพาะที่มี):
   - 🔴 **NG / เสีย** — ทิ้ง ใช้ไม่ได้
   - 🟡 **ต้องสงสัย** — รอตัดสิน
   - 🔧 **ซ่อม / Rework** — แก้ไขได้
4. ใส่สาเหตุ → บันทึก

NG + ต้องสงสัย จะถูกหักออกจาก Quality ใน OEE

### 5.7 ปิดกะ (🔒) + ยกยอดต่อกะ
1. กด **🔒 ปิดกะ**
2. ถ้ามี Order ที่ยังไม่ปิด ระบบบังคับตัดสินใจทุกใบ:
   - **➡ ยกยอด (Carry Over):** กรอก **"ยอดที่ทำได้"** เช่น Order 10 ชิ้น ทำได้ 7
     → กะถัดไปจะรับต่อแค่ **3 ชิ้นที่เหลือ**
   - **✕ ยกเลิก:** ตัดทิ้ง ไม่ส่งต่อ
3. ระบบคำนวณและบันทึก: ยอดผลิตรวม (รวมยอดที่ทำได้ของใบยกยอด), NG/สงสัย/ซ่อม, OEE (A×P×Q)
4. กะถัดไปเปิดกะ → เห็นแบนเนอร์ม่วง **"➡ มียอดค้างจากกะก่อน"** → กด **📥 รับยอดต่อ**
   Order จะเข้ามาด้วยจำนวนที่เหลือ พร้อมโน้ตว่ายกมาจากกะไหน

### 5.8 สูตร OEE
```
เวลากะทั้งหมด (เปิดกะ → ปิดกะ)
 − พักตามนโยบาย (break policies ที่ทับซ้อนช่วงกะ)
 − Downtime ในแผน          = เวลาพร้อมผลิตสุทธิ (Net Available)
 − Downtime นอกแผน          = เวลาเดินเครื่องจริง (Run Time)

A (Availability) = Run Time ÷ Net Available
P (Performance)  = (ยอดผลิต × Cycle Time ÷ 60) ÷ Run Time
Q (Quality)      = (ยอดผลิต − NG − สงสัย) ÷ ยอดผลิต
OEE = A × P × Q
```

### 5.9 แท็บประวัติ
- กรองตามวันที่ / ไลน์
- แต่ละกะแสดง: ยอดผลิต, NG%, Downtime รวม, **OEE**
- คลิกขยายดู: A/P/Q breakdown, รายการงานเสียทุกรายการ, รายการ Downtime ทุกรายการ

### 5.10 แท็บตั้งค่า (Master Data)
| แท็บย่อย | ตั้งค่าอะไร |
|---------|------------|
| 🔩 สินค้า / Model | ชื่อ, ไลน์, **cycle time (วินาที)**, เป้าต่อกะ, ประเภท process |
| 📦 Kanban Standard | MAT.NO → ชื่องาน, P/No, ลูกค้า, จำนวน/kanban (auto-fill ตอนสแกน) |
| ⚙️ เครื่องจักร | รายชื่อเครื่องต่อไลน์ (ใช้เลือกตอนบันทึก Downtime) |
| ⏱ ประเภท Downtime | ชื่อ, สี, หมวด **ในแผน/นอกแผน** (กระทบ OEE-A) |
| 🔴 ประเภทงานเสีย | ชื่อ, สี, ลำดับ |
| ☕ นโยบายหยุดพัก | เวลาเริ่ม + นาที + กะ + ประเภท process — ระบบหักจาก OEE อัตโนมัติ |

## 6. Line Setup

**เส้นทาง:** `/linesetup` · **เข้าได้:** Admin, Manager, SV

### 6.1 จัดการไลน์
- เพิ่มไลน์ใหม่: ใส่ชื่อ + เลือก section
- ลบไลน์ (ระวัง: สถานี/ผังของไลน์หายด้วย)

### 6.2 อัปโหลดผังไลน์
กดอัปโหลดรูป (ภาพถ่าย/แผนผัง layout) — ระบบย่อขนาดให้อัตโนมัติ

### 6.3 วางสถานีงาน
1. **คลิกบนรูปผัง** ตรงตำแหน่งสถานีจริง
2. ตั้งชื่อสถานี (เช่น OP10)
3. เลือก **ทักษะที่ต้องการ** + คะแนนขั้นต่ำ (default 70) — แยกหมวด Hard skill / Machine / Product / Soft
4. เปิด 💰 "จุดงานได้ค่าฝีมือ" ถ้าสถานีนี้มีเบี้ยทักษะ
5. บันทึก — มี collision warning ถ้าวางใกล้สถานีเดิมเกินไป

### 6.4 กำลังคนมาตรฐาน
กรอกจำนวนคน ☀️ กะเช้า / 🌙 กะดึก ต่อไลน์ — ใช้คำนวณอัตรามาทำงานบน Dashboard

## 8. Operator

**เส้นทาง:** `/operator` · **เข้าได้:** Admin, Manager, SV, Leader

### 8.1 Skill Matrix (📊)
- ตาราง พนักงาน × ทักษะ ทุกตัว สีตามคะแนน
- กรองตาม ไลน์ / section / ทีม / หมวดทักษะ
- คลิกช่องเพื่อแก้คะแนน (0–100)

### 8.2 รายชื่อพนักงาน (👥)
- ค้นหา/กรอง ดูโปรไฟล์ แก้ไขข้อมูล ปิดสถานะ (ลาออก) — ข้อมูลเก่ายังอยู่ครบ

### 8.3 เกณฑ์คะแนนทักษะ
| คะแนน | ระดับ |
|-------|------|
| 100+ | ผู้เชี่ยวชาญ — สอนคนอื่นได้ |
| 75–99 | แก้ปัญหาเองได้ |
| 50–74 | ทำงานได้มาตรฐาน |
| 25–49 | ต้องมีคนดูแล |
| 0–24 | ยังไม่ผ่าน OJT |

## 9. Shift Organize

**เส้นทาง:** `/shift-organize` · **เข้าได้:** Admin, Manager, SV

### 9.1 ตารางกะรายสัปดาห์
- เลื่อนดูสัปดาห์ด้วยปุ่ม ‹ › / กลับ "วันนี้"
- แต่ละไลน์: กำหนดทีมไหนอยู่กะเช้า (อีกทีมอยู่กะดึกอัตโนมัติ)
- กด **⇄ สลับ** เพื่อสลับกะ แล้ว **💾 บันทึก** — ใช้กับทั้งสัปดาห์ (จันทร์–อาทิตย์)

### 9.2 Override รายบุคคล
พนักงานบางคนต้องสลับกะชั่วคราว: กด ➕ → เลือกวันที่ + พนักงาน + กะ + เหตุผล

### 9.3 ยุบกะ (Merge Events)
ช่วงงานน้อย/วันหยุดยาว ยุบทั้ง section หรือทั้งไลน์มากะเดียว:
กด ➕ → เลือกขอบเขต (section/ไลน์) + ช่วงวันที่ + กะปลายทาง + เหตุผล

### 9.4 ลำดับความสำคัญ
**Override รายบุคคล > ยุบกะ > ตารางกะปกติ** · Team C ไม่ได้รับผลจากการหมุนกะ

## 12. แนวคิดสำคัญของระบบ

### วันทำงาน (Work Date)
**ก่อน 08:00 น. = นับเป็นวันก่อนหน้า** — กะดึก (20:00–07:59) ทั้งกะนับเป็นวันเดียวกับตอนเริ่มกะ

### เวลากะ
| กะ | เวลางาน | OT |
|----|---------|-----|
| ☀️ กะเช้า | 08:00–17:30 | 17:30–20:00 (+OT พิเศษถึง 23:00) |
| 🌙 กะดึก | 20:00–07:59 | 20:00–22:30 |

### Flow งานประจำวันที่แนะนำ
```
ก่อนเริ่มกะ:  Leader เช็คชื่อ + PPE (Checkin)
            → SV จัดคนลงสถานี (Management) → 4M อัตโนมัติถ้ามีย้ายคน
เริ่มกะ:     SV เปิดกะ (Daily Report) → รับยอดค้างจากกะก่อน (ถ้ามี)
ระหว่างกะ:   สแกนเปิด Order ทุกใบที่เริ่ม → สแกนปิดเมื่อครบจำนวน
            → บันทึก Downtime ทุกครั้งที่ไลน์หยุด → บันทึกงานเสียเมื่อพบ
จบกะ:       SV ปิดกะ → ตัดสินใจ Order ค้าง (ยกยอด/ยกเลิก) → ได้ OEE ทันที
ผู้บริหาร:   ดูภาพรวมที่ Dashboard ตลอดเวลา / Export รายงานจากหน้า Report
```

### การแจ้งเตือน
- **Telegram Group:** ทุกการเปลี่ยนสถานะ 4M (สร้าง/อนุมัติ/reject)
- **กระดิ่งในแอพ:** แจ้งรายบุคคลตาม role ที่เกี่ยวข้อง
