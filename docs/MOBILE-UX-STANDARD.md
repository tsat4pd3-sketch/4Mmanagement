## 2. หลักการ 10 ข้อ (ใช้ทุกหน้า)

1. **งานของฉันมาก่อน ตกแต่งทีหลัง** — จอแรกต้องมีสิ่งที่ user มาทำ ไม่ใช่โลโก้/สโลแกน/นาฬิกา (มือถือมีนาฬิกาอยู่แล้ว)
2. **ปุ่มหลักหนึ่งปุ่มต่อจอ** — เด่นที่สุด กว้างเต็มแถว อยู่ในระยะนิ้วโป้ง · ปุ่มรองเป็นปุ่มขอบ (ghost)
3. **ตัวกรองพับไว้** — โชว์ "สรุปว่ากรองอะไรอยู่" 1 บรรทัด แตะแล้วค่อยกาง (`<TimeRangeBar>`/`<FilterBar>` ทำให้เองบนมือถือ)
4. **การ์ด ไม่ใช่ตาราง** สำหรับรายการที่ต้อง "แตะเพื่อทำงาน" · ตารางเก็บไว้ให้ข้อมูลเปรียบเทียบที่ต้องอ่านแนวนอน
   (ตารางกว้างต้องเลื่อนในกล่องตัวเอง + **คอลัมน์แรกตรึง**)
5. **ห้ามเลื่อนซ้อนเลื่อน** — กล่องเลื่อนในหน้าที่เลื่อนอยู่แล้ว = ปัดแล้วไม่รู้อะไรขยับ · ให้พับ/เลือกแทน
6. **เป้ากด ≥ 44px** (`::before` ใน index.css ขยายปุ่มเล็กให้แล้ว · checkbox ≥ 20px + ห่อ `<label>`)
   · **ช่องติ๊กใช่/ไม่ใช่ที่สำคัญ ให้เป็นปุ่มใหญ่ 2 ปุ่ม** (✅ ผ่าน / ❌ ไม่ผ่าน) ไม่ใช่ checkbox
7. **ช่องกรอกตัว 16px** (กันมือถือซูมจอเอง) · ใช้ keyboard ให้ตรงชนิด (`inputMode="numeric"` สำหรับตัวเลข)
8. **ค่าเริ่มต้นจากบริบท** — ไลน์ของฉัน · กะนี้ · วันนี้ · ชื่อฉัน — คนหน้างานไม่ควรต้องเลือกสิ่งที่ระบบรู้อยู่แล้ว
9. **บอกผลทันทีและชัด** — บันทึกสำเร็จ/ล้มเหลวด้วย toast + เปลี่ยนสถานะบนการ์ด · ปุ่มระหว่างบันทึกต้อง disabled + "กำลังบันทึก…"
10. **คำอธิบายยาวพับไว้** — แบนเนอร์อธิบายระบบ/กติกา บนมือถือเหลือ 1 บรรทัด + "อ่านต่อ"

## 3. โครงแอปบนมือถือ (ทำครั้งเดียวได้ทุกหน้า)

- **แถบล่าง (bottom bar) 4 ช่อง** `components/MobileNavBar.jsx` — 🏠 หน้าหลัก · 📷 สแกน · 🔎 ค้นหาเมนู · ☰ เมนู
  · เหตุผล: ปุ่ม ☰ มุมซ้ายบนนิ้วโป้งไม่ถึง (NN/g: thumb zone) และลอยทับเนื้อหาตอนเลื่อน ·
    แอปมือถือมาตรฐาน (Material/iOS tab bar) วางปลายทางหลัก 3–5 ช่องไว้ล่างจอ
  · ความสูงอยู่ในตัวแปร `--mnav-h` (**0 บนจอคอม**) · ของ `position: fixed` ชิดล่าง (toast · ไซเรน · ชิปเลื่อน) ต้องบวก `var(--mnav-h, 0px)`
    · 🔴 **`position: sticky; bottom` ห้ามบวก** — `<body>` (ตัวเลื่อน) มี padding-bottom เท่าแถบ กรอบ sticky หดให้เองแล้ว (บวก = ลอยสูงเกิน 56px)
  · ซ่อนเองเมื่อคีย์บอร์ดเปิด/เปิดโมดัล (โมดัล z-index สูงกว่า)
- **ปุ่มบันทึกเกาะล่างจอ** class `.m-savebar` (index.css) — ฟอร์ม/รายการยาวที่บันทึกทีเดียวตอนท้าย (ต้นแบบ: เช็คชื่อ & PPE)
  · ในโมดัลที่เลื่อนในกล่องตัวเอง ต้องเป็น **ลูกตรงของเนื้อหาโมดัล** (ห้ามอยู่ในแถวปุ่มเล็กๆ — sticky ขยับได้แค่ในกล่องพ่อ)
    ต้นแบบ: ใบ MO ปุ่ม "ขั้นถัดไป" `.m-actbar` · ฟอร์มขั้น `.m-stepbar` (`MtnRepair.jsx`)
- **บอร์ดแผ่น (OBEYA)** มือถือ = ไม่ใช้โหมดพอดีจอ/แบ่งหน้า/จอเตี้ย · 1 คอลัมน์ สูงคงที่ `MOBILE_SHEET_H` · `<Sheet span>` เป็น 1 อัตโนมัติ
- **หน้าหลัก (Home) บนมือถือ** = ⭐ ใช้บ่อย → หมวดเมนู → ตัวเลขสด · ไม่มีแบนเนอร์/นาฬิกา/วันที่
- **กระดิ่ง 🔔 มุมขวาบน** คงไว้ (คิวงานที่รอเรา)

## 3.1 🔫 ปุ่มสแกนข้างเครื่อง (keyboard-wedge) — ด่านกลาง (2026-10-20 · audit CipherLab RS38)

เครื่องที่แจก (CipherLab RS38) สแกนแบบ "พิมพ์รหัสใส่ช่องที่เคอร์เซอร์อยู่ + Enter" ⇒ ระบบต้องแยกเองว่าตัวอักษรชุดไหนมาจากการสแกน
· ตัวตัดสิน `src/utils/scanWedge.js` (pure · เทส `__tests__/scanWedge.test.mjs`) · ตัวติดตั้ง `components/ScanWedgeGuard.jsx`
  mount ใน `App.jsx` ทั้ง 2 โครง (มีด่านในเทส) · **มือถือเท่านั้น** — จอคอมไม่ติดตั้ง = พฤติกรรมเดิม

| สแกนจบตอนเคอร์เซอร์อยู่ที่ | ระบบทำ |
|---|---|
| ช่องตัวเลข (`type=number` / `inputMode` numeric·decimal) | **คืนค่าเดิมของช่อง + กลืน Enter** + toast เตือน (เดิม: PROD.NO 8 หลักกลายเป็นยอดผลิต) |
| `<select>` | คืนค่าเดิม (ตัวอักษรที่ยิงเข้า select = กระโดดไปตัวเลือกอื่น) |
| ปุ่ม / ไม่มีช่องไหนโฟกัส | กลืน Enter (เดิม: Enter ไปกดปุ่ม "บันทึก" ที่โฟกัสค้าง) → ยิง `esm:scan` ให้หน้าที่อยากรับ (`e.preventDefault()` = รับแล้ว) · ไม่มีใครรับ = toast บอก **ห้ามหายเงียบ** |
| ช่องข้อความ | ปล่อยผ่าน (ช่องสแกนปกติ) + แปะ `__esmScan` บน event — **`SearchSelect` เลือกได้เฉพาะตัวที่รหัสตรงเป๊ะ** (`exactScanMatch`) ไม่ตรง/ตรงหลายตัว = ไม่เลือก |
| Enter ตัวที่ 2 ของ CR+LF (≤200ms) | กลืนเสมอ |

กติกาสำหรับคนทำหน้าใหม่:
- **ช่องตัวเลขที่ตั้งใจรับรหัสจากการสแกน** (หายาก — รหัสส่วนใหญ่ใช้ช่องข้อความ) ต้องใส่ `data-scan-ok` ไม่งั้นถูกคืนค่า
- 🔴 **Shift ห้ามตัดชุดสแกน** — เครื่องกด Shift ให้ตัวพิมพ์ใหญ่ทุกตัว (เคยพลาดตอนทำ · มีเทส)
- ตัวเลือก "นอกทะเบียน" (`history`) ไม่นับใน exact match (เป็นเงาของคำที่เพิ่งสแกนเอง)
- ช่องรอสแกนใน `ScanModal` = `inputMode="none"` บนมือถือ (ไม่เด้งคีย์บอร์ด) + ปุ่ม **⌨️ พิมพ์เอง** สำหรับป้ายเลอะ
- ⚠️ ด่านนี้สมมติว่าเครื่องตั้ง **Keyboard Emulation + ต่อท้าย Enter** (ค่าใน ReaderConfig) — ถ้าเปลี่ยนเป็นส่ง Intent ต้องออกแบบตัวรับใหม่
- กันแตะเบิ้ล (ถุงมือ) ด้วย **ref guard** ในฟังก์ชันบันทึก (ไม่เปลี่ยนหน้าตาปุ่ม = จอคอมเหมือนเดิม) · ปุ่ม "แตะซ้ำ = ล้างคำตอบ" บนมือถือต้อง `confirm` ก่อน (BBS · ใบตรวจ PM)

## 3.3 👆 ขนาดของที่ต้องกด/กรอก (2026-10-22 · audit handheld ข้อ 5)
- **ช่องกรอก 16px บังคับทับ inline** (`index.css` ≤768 · `!important`) — เดิม `style={{ fontSize: 13 }}` ในหน้าชนะกฎธีม
- **พื้นที่กดล่องหน 44px** (`button:not(:has(*))::before` · `.tbtn`) — **ไม่ใช่ 48** เพราะพื้นที่ล่องหนล้นออกนอกตัวปุ่ม ปุ่มเล็กที่วางชิดกันจะทับกันมากขึ้น ⇒ ปุ่มคำตอบหลักที่ต้องกดด้วยถุงมือให้ขยาย "ตัวปุ่ม" ในหน้า (ต้นแบบ: OK/NG ใบตรวจ PM `minHeight 44 · minWidth 58` บนมือถือ)
- **แถวปุ่มท้ายโมดัลเกาะล่างจอ** `.m-modalfoot` (ลูกตรงของกล่องโมดัลแบบ `.overlay` · ใส่ class เฉพาะ `isMobile`) — Daily Report: เปิดกะ · ปิดกะ · Scan เปิด/ปิด Order · งานเสีย · Downtime
- **หัวพับตัวกรองมือถือ** `.mfold-head { max-width: 100% }` — คลาสเดียวกับ `.trb-row` (column+stretch ⇒ เส้น = max-content ของลูก) · เดิม /order-trace ปุ่ม 📷 ตกขอบขวา 22px
