## 0. หลักการที่ใช้ตัดสิน (อ้างอิงภายนอก)

| หลักการ | ใช้ตัดสินเรื่องอะไรในระบบนี้ |
|---|---|
| **Nielsen #4 Consistency & Standards** — ผู้ใช้ไม่ควรต้องสงสัยว่าคำ/สถานการณ์/การกระทำที่ต่างกัน มีความหมายเดียวกันหรือไม่ · แยก *internal consistency* (ในระบบเดียวกัน) กับ *external* (ตามธรรมเนียมเว็บทั่วไป) | ทุกข้อด้านล่าง — ตำแหน่งหัวเพจ, คำว่า "ทุก…", ขนาดช่องกรอง |
| **Design tokens** (W3C Design Tokens Community Group — spec เสถียรตัวแรก 2025.10) — ค่าการออกแบบ (ระยะ/ขนาด/มุม/สี) เก็บเป็นชื่อกลาง ไม่ใช่เลขดิบกระจายในโค้ด | `--ctl-h` `--ctl-r` `--r-*` `.page-content` — แก้ที่เดียวมีผลทั้งระบบ |

## 1. กรอบหน้า — `<Page>` (`src/components/Page.jsx`)

**ปัญหาที่วัดได้ (23/09):** ระยะขอบรากหน้า 20+ แบบ · ความกว้างสูงสุด 12 ค่า · ชื่อหน้าเริ่มที่ x = 0…78 px
⇒ กดเปลี่ยนหน้าแล้วหัวเพจ/แท็บ **กระโดดซ้าย-ขวา** · OBEYA/WorkforceInsight ชิดขอบ sidebar

- ทุกหน้าขึ้นด้วย `<Page>` (= `.page-content` ใน `index.css`) — **ห้ามตั้ง padding / maxWidth / margin:auto ที่รากหน้าเอง**
- ความกว้าง 4 แบบเท่านั้น: `wide` (ค่าตั้งต้น 1800) · `form` (960 — ฟอร์ม/ตั้งค่าคอลัมน์เดียว) · `narrow` (640) · `full` (ผัง/บอร์ด)
  · `form`/`narrow` **ชิดซ้าย ไม่จัดกลาง** — ชื่อหน้าต้องเริ่มที่ x เดียวกันทุกหน้า
- ระยะขอบตามจอมาจาก CSS ที่เดียว: มือถือ 14 · แท็บเล็ต 18/20 · PC 24/28 · 1600+ 28/36 · TV 36/48
- **Page ซ้อน Page ไม่เพิ่มขอบ** (`.page-content .page-content`) ⇒ หน้าที่ถูกฝังในแท็บของ hub ใช้ `<Page>` ได้ตามปกติ
- ยกเว้น (บอร์ดจอ TV · มีเหตุผลใน UI-CONVENTIONS §6.8): `Login` · `Dashboard` · `Management` · `LineOeeBoard` · `TvBoard` · `LineSetup` · `DeptHub` (หน้าแรก hero)

## 2. หัวเพจ — `PageHeader` + `<Hub>`

- ทุกหน้าใช้ `PageHeader` (UI-CONVENTIONS §6.8) — ลำดับตายตัว: breadcrumb → ชื่อหน้า+คำอธิบาย | ปุ่ม → แท็บ
  **แท็บอยู่ใต้ชื่อหน้าเสมอ** (ProductMaster เคยวางแท็บเหนือชื่อ)
- **1 หน้า = 1 หัวเรื่องหลัก** — hub (PmHub · DailyChecker · EquipmentHub · LayoutSetup) ครอบหน้าลูกด้วย `<Hub>`
  ⇒ `PageHeader` ของหน้าลูกไม่วาดชื่อหน้า/breadcrumb ซ้ำ เหลือคำอธิบาย+ปุ่ม+แท็บย่อย
  (เดิมหัวซ้อน 2 ชั้น และหัวชั้นในขนาด 15/22/23/26px ต่างกันทุกแท็บ)
- **🚫 แท็บโชว์ครบทุกตัว ห้ามพับเข้า dropdown** (01/10 · user: *"ถ้าเป็นดรอปดาว จะทำให้ user ไม่รู้"*)
  — รอบ 24/09 เคยพับแท็บที่เกิน 7 เข้า "⋯ เพิ่มเติม" ⇒ ProductMaster 4 แท็บ (ลูกค้า/Supplier/ทบทวน CT/Export) หายจากสายตา
  · เดสก์ท็อปตัดบรรทัด · มือถือเลื่อนแนวนอน · เรียงแท็บที่ใช้บ่อยไว้หน้า · แท็บตั้งค่าท้ายสุด (§6.8 ข้อ 4)
  · **แท็บเยอะจนรก = แก้ที่ต้นเหตุ** (ของซ้ำ 2 ทาง · ของที่ควรเป็นหน้าแยก — NAVIGATION-REVIEW §2.3) **ไม่ใช่ซ่อน** · มีด่าน `tabs-folded-into-dropdown`

### 2.1 🔴 ลำดับแนวตั้งตายตัวทุกหน้า (2026-09-24 · user: *"ลำดับยังโดดไปมา เดี๋ยวแท็บมาก่อนช่องค้นหา บางหน้าค้นหาอยู่บนสุด"*)

```
breadcrumb
ชื่อหน้า + คำอธิบาย ................ [ปุ่มคำสั่ง: บันทึก/เพิ่ม/พิมพ์/โหมด TV]   ← actions
[แท็บ 1] [แท็บ 2] [แท็บ 3]
[แถบกรอง: ขอบเขต · ช่วงเวลา · ตัวกรอง · ค้นหา ........ จำนวน/export]          ← filters (หรือ TimeRangeBar)
เนื้อหา
```
- **`actions` = ปุ่มคำสั่งเท่านั้น** — ห้ามมี select / ช่องวันที่ / OrgScopePicker / LineSelect / Segmented / ค้นหา / เลื่อนเดือน-ปี
  (เคยอยู่ใน actions ⇒ ขึ้นแถวชื่อหน้า **เหนือแท็บ** · OBEYA 4 แท็บวางไม่เหมือนกันเอง)
- **ตัวกรองส่งผ่าน `<PageHeader filters={…}>`** ⇒ วาดเป็น `.filter-bar` **ใต้แถบแท็บเสมอ** — หน้าไม่ต้องจัดตำแหน่งเอง
  · ตัวกรองที่เปลี่ยนตามแท็บ (เฉพาะแท็บนั้น) วาด `<FilterBar>`/`<TimeRangeBar>` เป็นบรรทัดแรกของเนื้อหาแท็บ = ตำแหน่งเดียวกัน
- **ในหน้าลูกของ hub**: หน้าแม่แสดงชื่อ+คำอธิบายแท็บแล้ว ⇒ PageHeader ของหน้าลูก **ไม่แสดง `sub`** และ **ปุ่มคำสั่งย้ายไปท้ายแถบกรอง**
  ⇒ ใต้แท็บของแม่ = [แท็บย่อยของลูก] → [แถบกรอง … ปุ่ม] → เนื้อหา (เดิมคำอธิบาย/แถวปุ่มของลูกแทรก 48–67px)
- **ห้ามมีอะไรคั่นระหว่างแท็บกับแถบกรอง** (คำอธิบาย/การ์ดสรุป/หัวข้อซ้ำชื่อแท็บ) — วางใต้แถบกรองแทน · ข้อยกเว้น: แท็บย่อย + ReadOnlyNote
- ระยะ แท็บ→แถบกรอง = **16px ทุกหน้า** · หน้าที่ตั้ง `gap` ที่ `<Page>` ไม่ต้องทำอะไร — Page ปิด marginBottom ของ PageHeader ให้เอง (`--ph-mb`)
- ด่าน build `ตัวกรองห้ามอยู่ใน actions ของ PageHeader` (ตามชื่อตัวแปรที่ห่อ JSX ด้วย) · `stdsweep` ตรวจ
  "ช่องกรองในปุ่มหัวเพจ" + "ช่องกรองเหนือแถบแท็บ" บนจอจริงทุกแท็บ

## 3. ตัวกรอง — `<FilterBar>` · `<Segmented>` · `ALL`

**ปัญหาที่วัดได้:** ช่องกรอง 71 ทรง (สูง 20–39 · มุม 4/6/7/8/10 · ตัว 11–16) · dropdown ยืดเต็มแถว 1444px
(`select{width:100%}` ของธีม) · คำว่า "ทั้งหมด" 30+ แบบ · เรื่องเดียวกัน (กะ) ใช้ dropdown ในแท็บหนึ่ง ปุ่มในอีกแท็บ

1. **แถบกรอง = `<FilterBar>`** (`className="filter-bar"`) — การ์ด 1 แถบ · ช่องไฟ 8 · wrap ได้
   ลำดับ: **ขอบเขต (ส่วนงาน/แผนก/ไลน์/ทีม) → ช่วงเวลา → ตัวกรองอื่น → ค้นหา → `spacer` → จำนวน/ปุ่ม export/ปุ่มหลัก**
   หน้าที่มี `<TimeRangeBar>` ⇒ **ตัวกรองของหน้าเป็น children ของมัน** (TimeRangeBar ก็คือ filter-bar) — ห้ามแยก 2 ชั้น
   (ในแถบเวลา ลำดับเป็น เวลา → ตัวกรองของหน้า เพราะ children ต่อท้ายช่วงเวลา — ยอมรับเป็นมาตรฐาน)
2. **ช่องในแถบกรองสูง 34 · ตัว 13 · มุม 8 จาก token** (`--ctl-h` `--ctl-fs` `--ctl-r`) —
   **ห้ามใส่ width/height/padding/fontSize/borderRadius inline ที่ select/input ในแถบ** (inline ชนะ class = เพี้ยนกลับ)
   · อยากให้ช่องยืดใส่ `className="grow"` · select ในแถบ `width:auto` (สูงสุด 280) ให้เอง
   · ฟอร์มบันทึก (modal/ตาราง) **ไม่อยู่ใต้กฎนี้** — ใช้ขนาดตั้งต้นของธีม (~39px = Carbon medium)
3. **เลือกชนิดตัวควบคุมตามจำนวนตัวเลือก:** 2–5 ตัวเท่ากัน → `<Segmented>` · มากกว่านั้น → dropdown ·
   ทะเบียนยาว → picker กลาง (`LineSelect`/`SearchSelect`… UI-CONVENTIONS §5.1.2) · **กะ = `<Segmented options={SHIFT_OPTIONS}>` ทุกหน้า**
   · **ลำดับในรายการไลน์ = ส่วนงาน → ไลน์แม่ → ไลน์ลูก เรียงธรรมชาติ ทุกหน้า** (2026-10-01 · UI-CONVENTIONS §5.3 ข้อ 9)
     — ลำดับที่คาดเดาได้คือส่วนหนึ่งของ Consistency (Nielsen #4) · หัวกลุ่ม `<optgroup>` = "chunking" ให้สแกนลิสต์ยาวได้เร็ว
4. **ป้าย "ทั้งหมด" จาก `src/utils/filterLabels.js` เท่านั้น** (`ALL.line` = "ทุกไลน์" …)
   - ตัวกรอง = `ทุก<คำนาม>` ไม่มีขีด ไม่มีวงเล็บจำนวน ภาษาไทย (`ALL SHIFT`/`ทุก Team`/`ทุก Section` ❌)
   - ช่องในฟอร์ม = `— เลือก —` / `— ไม่ระบุ —` (มีขีด = "ยังไม่ได้ตอบ") — **คนละความหมาย ห้ามปน**
   - ตัว "ทุก…" อยู่ **ตัวแรก/ซ้ายสุดเสมอ** ทั้งใน dropdown และ Segmented/ชิป
5. **ช่องที่เป็นพารามิเตอร์ของปุ่ม export (เช่นเดือนของใบ Changing Point) ไม่ใช่ตัวกรองมุมมอง** ⇒
   วางหลัง `spacer` ชิดปุ่มของมัน + มี `filter-label` บอกว่าเป็นของปุ่มไหน

## 4. ช่องค้นหา — `<SearchInput>`

**ปัญหาที่วัดได้:** placeholder ~60 แบบ (🔍/🔎/ไม่มี · ค้นหา/ค้น/หา/พิมพ์ · …/.../— —)
- ช่องที่ "กรองรายการบนจอ" = `<SearchInput value onChange fields="MAT / ชื่อพาร์ท" />`
  → ไอคอน 🔍 ในกรอบ · placeholder `ค้นหา <ช่องที่ค้นได้>` · `type="search"` · ปุ่ม ✕ ล้าง
- ช่องที่ "เลือก 1 ค่าจากทะเบียน" ไม่ใช่ช่องค้นหา → picker กลาง (UI-CONVENTIONS §5.1.2)
- 🔴 **พิมพ์แล้วต้องกรอง — 2 บั๊กที่ build/lint/crashsweep ผ่านหมด** (01/10 · user: *"พิมไปแล้ว ไม่เห็นกรองให้"* · *"ทับตัวหนังสือ แทบทุกหน้า"*)
  · picker กลาง: พาเรนต์เก็บคำที่พิมพ์ → `appendHistoryOptions(current)` แปลงเป็น option "⚠ นอกทะเบียน" → ช่องคิดว่า "เลือกแล้ว"
    → ทิ้งคำค้น ⇒ **`SearchSelect` แยกสถานะ `typing` (คำค้น = สิ่งที่พิมพ์เสมอ) · ซ่อน option ที่เป็นเงาของคำค้น ·
    ปิดลิสต์โดยไม่เลือก = ล้าง (allowFree=false)** · คลิกช่องที่โฟกัสอยู่แล้วต้องเปิดลิสต์ได้
  · `<SearchInput>` ในแถบกรอง: กฎขนาด `.filter-bar :is(input:not(…)×5)` specificity (0,6,1) ชนะ `.search-input input`
    ⇒ padding ซ้ายเหลือ 10px 🔍 ทับคำ 17 หน้า ⇒ **ที่ว่างของไอคอนเขียน inline ในตัว component** (ห้ามย้ายกลับไปพึ่ง class)
  · ตรวจ `node audit/searchsweep.mjs` (พิมพ์คำที่ไม่มีทางเจอทุกช่อง × ทุกแท็บ · ไอคอนทับ · lab picker `audit/searchlab.html`)

## 4.5 🧭 "คุณอยู่ตรงนี้" — รูปแบบเดียวกันทุกชั้นของเมนู (2026-09-24 · user ทัก)

> *"highlight ที่บอกว่าตอนนี้อยู่ tab ไหน ทำไม sidebar นอกสุดไม่มี มีชั้นใน แต่คนละรูปแบบ"*

เมนูมี 3 ชั้น (รางไอคอน → แผงลอย/drawer → รายการเมนู) — ทั้ง 3 ชั้นต้องตอบคำถามเดียวกัน
ว่า *"ตอนนี้ฉันอยู่ไหน"* ด้วย**หน้าตาชุดเดียว**:

| สถานะ | หน้าตา | เหตุผล |
|---|---|---|
| **อยู่ที่นี่** (ข้อเท็จจริงถาวร) | พื้น `--accent-dim` + **แถบ accent ขอบซ้าย** + ตัวอักษร accent + `aria-current` | เป็นข้อมูลที่ต้องอ่านได้ตลอดเวลา |
| **แผงที่กดเปิดอยู่** (ชั่วคราว) | เส้นขอบ `--border2` บางๆ เท่านั้น | ปิดแผงแล้วก็หาย — ไม่ควรเด่นกว่าข้อเท็จจริง |
| **แถวทางลัดข้ามหมวด** (`alsoIn`) | ไอคอนจาง `opacity .7` + ป้าย `↗ <หมวดบ้าน>` ท้ายแถว + `title` บอกบ้านจริง | บอกว่า "กดจากที่นี่ได้ แต่บ้านมันอยู่ที่อื่น" |
| **ทางลัดที่เป็นหน้าที่เปิดอยู่** | **ตัวอักษร accent เท่านั้น** (ไม่มีพื้น ไม่มีแถบซ้าย) | พื้น+แถบซ้ายสงวนให้บ้านจริง — ไม่งั้นจะดูเป็นบ้านที่สอง |

### 🔴 กฎที่ละเมิดไม่ได้
1. **สัญญาณของ "สถานะชั่วคราว" ห้ามแรงกว่า "ข้อเท็จจริงถาวร"**
   เคสจริงที่ทำให้ต้องเขียนกฎนี้: รางไอคอนให้ *แผงที่กดเปิด* ทั้งกรอบเขียว + พื้นเขียวจาง
   แต่ให้ *หมวดของหน้าที่เปิดอยู่จริง* แค่**สีตัวหนังสือ 11px** ⇒ พอไม่เปิดแผง รางก็เหมือนไม่มีไฮไลต์
2. **`alsoIn` = "ทางลัด" ไม่ใช่ "บ้านที่สอง" ⇒ "อยู่ตรงนี้" มีคำตอบเดียวเสมอ** (แก้ 24/09 ตามคำสั่ง user)
   `วางแผนการผลิต` บ้านจริง = ฝ่ายผลิต · ไปโผล่เป็นทางลัดในหมวด แผนงาน ·
   `เฝ้าระวังสต๊อก` บ้านจริง = สโตร์ · ทางลัดในหมวด จัดส่ง
   🔴 **เดิมมาร์คทั้ง 2 หมวดด้วยหน้าตาเหมือนกันเป๊ะ** ⇒ user ทักว่าเมนูซ้ำ
   (*"ไม่ซ้ำยังไง วางแผนผลิต อยู่ทั้ง sidebar หมวดผลิต กับ วางแผน"*) และคำถามตำแหน่งมี 2 คำตอบ
   · ตัดสินบ้านจริงด้วย `item.group` ตัวเดียว → `items.some(i => i.to === pathname && !isNavGuest(i, group))`
   · แถวเป็นทางลัดไหม = `isNavGuest(item, group)` · "หน้านี้โชว์ในหมวดนี้ไหม (นับทางลัด)" = `inNavGroup()`
     — **2 คำถามนี้คนละเรื่อง ห้ามปน** (มีด่าน `nav-alsoin-*` ใน `regressionGuards`)
   🔴 **ห้ามเช็คด้วยค่าเดียวอย่าง `activeGroup === group`** — มันคืนแค่หมวดแรก
   🔴 **แถวเมนูต้องวาดจาก `navRow()` ตัวเดียว** ทั้งแผงลอย (desktop) และ drawer (มือถือ) —
     เคยก๊อปแยก 2 ที่แล้วหน้าตา 2 ชั้นเพี้ยนกันเอง · `DeptHub` ชิปเมนูต้องมาร์คทางลัดแบบเดียวกัน
3. **แถบซ้ายบนปุ่มที่จัดกลางแนวตั้ง (ราง 56px) ให้วาดเป็น element ลอย ไม่ใช้ `borderLeft`**
   — `box-sizing: border-box` ทำให้เนื้อหาเลื่อน 3px เฉพาะปุ่มที่ active แล้วคอลัมน์ไอคอนดูไม่ตรงกัน
   (แถวเต็มความกว้างใน drawer/แผงไม่มีปัญหานี้ ใช้ `borderLeft` ได้ตามเดิม)

### 🕳️ รอบ 2 (20/10 · ตัวตรวจเองรายงานเกินจริง) — "ระยะห่าง" เป็น proxy ที่อ่อน
รอบแรกรายงาน **19 มุมมอง** แต่เกินครึ่งไม่ใช่ลำดับผิด: วัดจาก `h1` ⇒ นับ **คำอธิบายใต้ชื่อหน้า (`sub=`)
และปุ่ม/ตัวกรองของหัวเพจเอง** เป็น "ของแทรก" · อีกกองเป็น **padding ของการ์ดที่ครอบแถบกรอง**
สิ่งที่แก้ที่ตัวตรวจ (ห้ามถอด — ถอดแล้วกลับไปร้องหมาป่า):
1. `PageHeader` ติด **`data-ph-root`** · ไม่มีแถบแท็บ ⇒ วัดจาก **ก้นของก้อนหัวเพจทั้งก้อน** ไม่ใช่ก้น `h1`
2. รายงาน **เฉพาะเมื่อชี้ตัวได้ว่า "อะไร" แทรกอยู่** (`gapWhat`) — ชี้ไม่ได้ = เป็น margin/padding ไม่ใช่ลำดับผิด
3. ของที่อนุญาตถูกตัดออก **รายตัว** (เดิมใช้ธงเดียว: เจอป้ายที่อนุญาต 1 ตัว = ปล่อยทุกอย่างในช่องนั้น
   ⇒ การ์ดสถิติแอบอยู่หลังแถบเตือนได้)
4. มีของที่อนุญาตคั่น ⇒ วัดระยะจาก **ก้นของตัวล่างสุด** (ไม่งั้นความสูงของแถบเตือนกลายเป็น "ระยะผิดมาตรฐาน")
5. ป้าย "ทั้งหมด": ยอมรับ `ทุก… (n)` **เฉพาะลิสต์ที่ตัวเลือกอื่นก็มีตัวนับ** + ตัวย่อโรมันในคำนาม
