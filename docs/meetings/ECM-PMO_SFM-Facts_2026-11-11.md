# ข้อเท็จจริงระบบ SFM (ESM) สำหรับการพิจารณา ECM — Build vs Buy

> เอกสารประกอบการประชุม EVP เรื่อง "แนวทางระบบ Automation & Paperless (ECM)"
> จัดทำ 11/11/2569 · **ทุกตัวเลขมีที่มา + วันที่วัด** · อะไรที่ยังไม่รู้เขียนว่า "ยังไม่ทราบ" ไม่เดา
>
> ⚠️ **สมมติฐานของเอกสารนี้:** "ระบบ SFM ที่ TSAT P4 พัฒนา" ในบันทึกเชิญประชุม = ระบบ **ESM
> (Enterprise Shopfloor Management)** ในรีโปนี้ — ถ้าไม่ใช่ตัวเดียวกัน เอกสารนี้ใช้ไม่ได้

---

## 1. ประกาศผลประโยชน์ทับซ้อน (ต้องอ่านก่อน)

ผู้จัดทำเอกสารนี้ **เป็นทั้งผู้พัฒนา SFM และถูกเสนอให้เป็น PMO** ของโครงการที่ต้องตัดสินว่าจะ
"ต่อยอด SFM หรือไม่" ⇒ ข้อมูลในเอกสารนี้จำกัดอยู่ที่ **ข้อเท็จจริงที่ตรวจสอบได้** ไม่มีข้อสรุปเชิงแนะนำ
· ข้อเสนอให้ **การให้คะแนนทางเลือกทำโดยคณะกรรมการ** (IT + IA + ผู้ใช้) ไม่ใช่ PMO ฝ่ายเดียว

---

## 2. SFM คืออะไร — ขอบเขตวันนี้

ระบบบริหารหน้างานโรงงานบนเว็บ (PC · มือถือ · จอ TV) ใช้งานจริงที่ TSAT4

| ด้าน | มีแล้วในระบบ (ตัวอย่าง) |
|---|---|
| ผลิต | Daily Production Report · OEE · แผนผลิต · คัมบัง · ปิดกะ · เวลาหยุดเครื่อง |
| คุณภาพ | 4M Change (อนุมัติ 2 ชั้น) · CQI-15 · ใบรายงานปัญหา + ถังเหลือง/แดง · LPA · 8D · PFMEA/Control Plan · NPI/PPAP |
| ซ่อมบำรุง | ใบแจ้งซ่อม MO (ลำดับขั้นอนุมัติ) · PM/AM · ทะเบียนเครื่อง/แม่พิมพ์/อะไหล่ |
| คน | เช็คชื่อ + PPE · จัดกะ/OT · Skills Matrix · Manpower Board |
| บริหาร | OBEYA / KPI · Morning Meeting · คิวงานของฉัน |
| เอกสาร | ทะเบียนแบบฟอร์ม `/doc-forms` (เลขฟอร์ม/Rev/ช่องลายเซ็น ปรับได้โดยไม่แก้โค้ด) · ใบที่ออกแล้วเก็บเป็น snapshot · audit log |

**สิ่งที่ SFM ไม่ใช่ / ไม่มี** (ตรวจจากรีโป 11/11):
- ไม่ใช่ระบบ ECM ทั่วองค์กร — ไม่มีคลังเอกสารกลาง (repository) สำหรับ HR / บัญชี / การตลาด
- ไม่มี SSO — login ด้วยบัญชี+รหัสผ่านของระบบเอง (`signInWithPassword`)
- ไม่มีการส่งอีเมลเลย (แจ้งเตือนในแอป + Telegram)
- ไม่มี retention policy ของ audit log (บันทึกไว้เป็นงานค้าง)
- ยังไม่เก็บ lot no. ทั้งระบบ

## 5. ทีมพัฒนา — ความเสี่ยงที่ต้องพูดตรงๆ

- พัฒนาโดย **1 คน + เครื่องมือ AI (Claude)** ตั้งแต่ พ.ค. 2569 — ไม่ใช่ทีม developer
- ความรู้ระบบบันทึกเป็นเอกสารในรีโป (`CLAUDE.md` + `docs/modules/*` + ด่านทดสอบอัตโนมัติ)
  แต่ **key-person risk ยังสูง** ถ้าจะใช้เป็นฐานของโครงการระดับองค์กร ต้องมีแผนรองรับ
