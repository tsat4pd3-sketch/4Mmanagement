THAI SUMMIT GROUPTSAT · Enterprise Shopfloor Management
หลักฐาน 3 แบบ — แยกคอลัมน์ในรายงานเสมอ
วัดจากระบบดึงจากฐานข้อมูล ตัวเลขแน่น
เทียบก่อน/หลังต้องจับเวลา/สัมภาษณ์ยุคกระดาษ
ความเห็นผู้ใช้แบบสอบถาม 5 ข้อ แยกตำแหน่ง
1ใช้งานจริงแค่ไหนระบบ
  • กะที่เปิดในระบบ ÷ กะที่ผลิตจริง
  • ยอดจากใบงานที่สแกน เทียบยอด SAP
  • ผู้ใช้ active ต่อสัปดาห์ แยกแผนก
  • ตรวจ AM ครบ + ทันเวลา (%) · ใบซ่อมปิดในระบบ (%)
ต้องผ่านข้อนี้ก่อน ข้ออื่นถึงมีความหมาย
2ข้อมูลเร็วขึ้นแค่ไหนระบบก่อน/หลัง
  • เครื่องหยุด → ลงระบบห่างกี่นาที
  • ปิดกะได้ตัวเลขกี่โมง (เดิมได้วันถัดไป)
  • ประชุมเช้าใช้ตัวเลขจากไหน เตรียมกี่นาที
ตอบ "ตัดสินใจได้เร็วขึ้นไหม"
3ประหยัดเวลาคนก่อน/หลัง
  • ชั่วโมงทำเอกสาร/คน/กะ แยกตำแหน่ง
  • หัวหน้ากลุ่มเขียนรายงาน · คีย์ Excel · หาเอกสาร
  • จับเวลาตำแหน่งละ 3–5 คน → ชั่วโมงคน/เดือน
ข้อเดียวที่แปลงเป็น "เงิน" ได้ (+ ค่ากระดาษ)
4ผลการผลิตระบบ
  • แนวโน้ม OEE รายสัปดาห์
  • เวลาซ่อมเฉลี่ย · เวลาระหว่างเสีย · ใบซ่อมค้าง
  • ของเสีย / PPM
ดูแนวโน้มประกอบ — 1–2 เดือนสั้นเกินอ้างผล
5สอบกลับ + เอกสารระบบก่อน/หลัง
  • สุ่ม 5 เคส "ล็อตนี้ใครตรวจ เครื่องไหน วันไหน" จับเวลาหา
  • ฟอร์มกระดาษที่เลิกใช้ × แผ่นต่อเดือน
  • ใบที่มีลายเซ็นครบในระบบ (%)
ตอบลูกค้า / ผู้ตรวจประเมินได้เร็วแค่ไหน
6ความเห็นผู้ใช้ผู้ใช้ระบบ
  • แบบสอบถาม 5 ข้อ คะแนน 1–5 แยกตำแหน่ง
  • เรื่องในกล่อง feedback · แก้แล้วกี่เรื่อง
  • จุดที่ยังติด / อยากให้เพิ่ม
ใช้วางแผนรอบถัดไป ไม่ใช่แค่ให้คะแนน

⚠ กับดักที่ต้องเขียนกำกับในรายงาน

  1. ตัวเลขอาจดู "แย่ลง" ทั้งที่ดีขึ้น — นาทีเครื่องหยุด/ของเสียที่บันทึกได้เพิ่ม เพราะเดิมไม่ได้จด = มองเห็นมากขึ้น
  2. OEE ใน 1–2 เดือน มีปัจจัยอื่นปน (ยอดสั่ง · รุ่นใหม่ · คน) — รายงานเป็นแนวโน้ม ห้ามอ้างว่าระบบทำให้ขึ้น X%
  3. โชว์ความน่าเชื่อถือคู่กันเสมอ — ใบงานไม่เคยปิด · downtime "อื่นๆ/ไม่ระบุ" · ใบลงเวลาย้อนหลัง
  4. ตัวเลขเงิน = ประมาณการ จากชั่วโมงคน + กระดาษเท่านั้น และบอกวิธีคิดทุกครั้ง
