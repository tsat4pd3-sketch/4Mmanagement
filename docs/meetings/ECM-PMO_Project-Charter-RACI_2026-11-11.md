## 1. วัตถุประสงค์

กำหนดแนวทางและบริหารโครงการระบบ Automation & Paperless (ECM) ระดับองค์กร ให้ได้ข้อสรุป:
1. แนวทางพัฒนา (In-house / Outsource / Hybrid / ต่อยอด SFM)
2. โครงสร้างโครงการและบทบาท (Governance)
3. เจ้าของโครงการและทีม
4. Roadmap และกรอบเวลาเบื้องต้น

## 2. ขอบเขต

| ในขอบเขต | นอกขอบเขต (ร่างนี้) |
|---|---|
| Workflow อนุมัติเอกสาร · คลังเอกสาร (ECM) · หน่วยงาน: การตลาด (Qnex), IEC, Maintenance, HR, Finance & Accounting, QSM ฯลฯ | การเปลี่ยนระบบ ERP |
| การเชื่อมต่อกับ OT · OM · โครงสร้างพื้นฐาน IT · ข้อมูลข้ามหน่วยงาน | **[รอยืนยัน]** ขอบเขตของ "OT" และ "OM" |
| การตัดสินว่าส่วนโรงงานต่อยอดจาก SFM หรือไม่ | — |

### 3.1 การจัดการผลประโยชน์ทับซ้อน (เสนอ)

PM/PMO เป็นผู้พัฒนาระบบ SFM ซึ่งเป็นหนึ่งในทางเลือก ⇒ เสนอให้:
- **PMO จัดเตรียมข้อมูล แต่ไม่ให้คะแนนทางเลือก** — คะแนนมาจากคณะกรรมการประเมิน
- Head of IA ทบทวนข้อมูลเปรียบเทียบก่อนเข้า EVP
- ข้อมูล SFM ใช้มาตรฐานเดียวกับ vendor (ต้นทุนรวมค่าแรง · ความเสี่ยง · SLA)

## 4. RACI

R = ลงมือทำ · A = รับผิดชอบสุดท้าย (1 ราย/แถว) · C = ให้ความเห็น · I = รับทราบ

| กิจกรรม | EVP | Steering | PMO | Head of IA | IT | Business Users | Vendor | คกก. ประเมิน |
|---|---|---|---|---|---|---|---|---|
| อนุมัติแนวทาง (Build/Buy/Hybrid) | **A** | R | C | C | C | C | — | C |
| อนุมัติงบประมาณ | **A** | R | C | C | C | I | — | I |
| Project Charter / แผนโครงการ | I | A | **R** | C | C | C | — | — |
| เก็บ Business Requirements | I | I | A | C | C | **R** | C | — |
| ออก RFI / RFP + รวบรวมใบเสนอราคา | I | I | **R/A** | C | C | C | — | — |
| ทำ TCO 5 ปี | I | I | R | C | **R** (ตัวเลข infra) | C (ตัวเลขคน) | C | A |
| ให้คะแนน Decision Matrix | I | A | C | C | R | R | — | **R** |
| Architecture / Infrastructure | I | I | C | C | **R/A** | I | C | — |
| Security & Compliance | I | I | C | C | **R/A** | I | C | — |
| Integration OT / OM / HR / ERP | I | I | A | C | **R** | C | R | — |
| พัฒนา / ตั้งค่าระบบ | I | I | A | C | C | C | **R** | — |
| UAT | I | I | A | C | C | **R** | C | — |
| Go-live / Cutover | I | A | **R** | C | R | R | R | — |
| ดูแลระบบหลัง go-live | I | I | C | — | **R/A** | C | R | — |
| ติดตามความคืบหน้า / รายงาน | I | I | **R/A** | C | C | C | C | — |

> แถว "Vendor" ใช้เมื่อเลือก Outsource/Hybrid · ถ้าเลือก In-house ให้ย้าย R ไปที่ทีมพัฒนาภายใน **[รอยืนยันว่าทีมไหน]**

## 5. เกณฑ์ตัดสินใจ (เสนอให้ตกลงก่อนดูราคา)

ตกลง **น้ำหนักของเกณฑ์ก่อนเห็นใบเสนอราคา** เพื่อไม่ให้เลือกเกณฑ์ตามผลที่อยากได้
— ใช้ชีท "Decision Matrix" ในไฟล์ TCO (น้ำหนักรวม 100% · คะแนน 1–5)

## 6. Roadmap เบื้องต้น (ระยะเวลาให้คณะทำงานยืนยัน)

| ขั้น | งาน | ผลลัพธ์ / ด่านผ่าน |
|---|---|---|
| 0 ตั้งโครงการ | อนุมัติ Charter · ตั้ง Steering + คกก. ประเมิน · ตกลงเกณฑ์/น้ำหนัก | Charter ลงนาม |
| 1 Discovery | เก็บ BR รายหน่วยงาน · ระบุขอบเขต OT/OM · ทำผังระบบปัจจุบัน | BR + ผังระบบ |
| 2 RFI/RFP | ส่ง RFP ชุดเดียวกันให้ทุกราย (Bendix · OutSystems · VR · ฯลฯ) + ประเมิน In-house/SFM ด้วยเกณฑ์เดียวกัน | ใบเสนอราคา + TCO 5 ปี |
| 3 ตัดสินใจ | ให้คะแนน · นำเสนอ EVP | ข้อสรุปแนวทาง + งบ |
| 4 นำร่อง | 1 หน่วยงาน / 1 กระบวนการ | ผล UAT + บทเรียน |
| 5 ขยายผล | ทีละหน่วยงาน | — |

ระยะเวลาต่อทางเลือกในบันทึกเชิญประชุม (In-house 12–18 · Outsource 4–8 · Hybrid 6–12 เดือน)
= **ค่าประมาณตั้งต้น** ต้องยืนยันด้วยแผนจาก vendor/ทีมจริงในขั้น 2

## 7. สิ่งที่ขอจาก EVP ในการประชุม

1. อนุมัติโครงสร้าง Governance + PMO
2. อนุมัติให้ทำขั้น 0–2 (RFI/RFP + TCO) ก่อนตัดสิน Build/Buy
3. ตั้งคณะกรรมการประเมินทางเลือก (แยกจาก PMO)
4. ให้เจ้าของระบบ OT / OM ระบุขอบเขตและผู้แทน
