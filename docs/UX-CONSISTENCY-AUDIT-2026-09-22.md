## 2. ภาพ 3 ใบที่ user ส่งมา — วิเคราะห์ต้นเหตุ

`/equipment` (ทำ 2026-09-22 ใน session เดียวกัน) ยุบ 5 ทะเบียนเป็นหน้าเดียวโดย **embed หน้าเดิมทั้งดุ้น**
แต่หน้าเดิมแต่ละตัว "วาดหัวเรื่องไม่เหมือนกัน" ⇒ **หน้าเดียวให้ผล 3 หน้าตา**

| แท็บ | ที่เห็นบนจอ | ต้นเหตุ |
|---|---|---|
| 🏭 เครื่องจักร | หัวเรื่อง **2 ชั้น · ไม่มี breadcrumb** | `MachineDatabase` ไม่ใช้ `PageHeader` → วาด `<h2>` เอง |
| 🔨 แม่พิมพ์ | หัวเรื่อง **3 ชั้น** (hub → breadcrumb → หัวหน้าลูก) + แท็บลูกทรงทึบ | `DieRegistry` ใช้ `PageHeader` → วาด breadcrumb ของ **หน้าแม่** ซ้ำอีกรอบ |
| 📐 JIG/Fixture | เหมือนแม่พิมพ์ แต่แท็บลูกทรงโปร่ง + เนื้อหาว่าง ~600px | `FixtureRegistry` ใช้ `PageHeader` + empty state เป็นข้อความเปล่า ไม่มีกล่อง/คำแนะนำ |

> **🔴 นี่คือข้อบกพร่องที่เกิดจากงาน `/equipment` เอง ไม่ใช่หนี้เก่า** — hub ทั้ง 3 ตัว
> (`/equipment` · `/pm` · `/daily-checker`) วาดหัวเองหมด ทั้งที่ `PageHeader` รองรับแท็บอยู่แล้ว
> **กติกา hub ที่ขาดไป:** *หน้าแม่ถือ `PageHeader` · หน้าลูกที่ถูก embed ต้องปิด (`breadcrumb={false}`)
> หรือไม่วาดหัวเลย* — ตอนนี้ไม่มีเขียนไว้ที่ไหน จึงพลาดซ้ำได้ทุก hub ที่ทำใหม่

## 3. คำแนะนำ — **อย่า remodel ระบบดีไซน์ใหม่**

### เหตุผลที่ big-bang redesign แย่กว่า

1. **blast radius มหาศาล** — 75 หน้า · **ไม่มี staging environment** (เอกสารระบุ: merge เข้า main = ทดสอบจริงบนของที่ทั้งโรงงานใช้)
2. **rollback ไม่ได้จริง** — คอมมิทเดียวแตะ 75 ไฟล์ พังตรงไหนแยกไม่ออก ต้อง revert ทั้งก้อน
3. **ไม่ได้แก้ต้นเหตุ** — ทำใหม่สวยแล้วอีก 3 เดือน drift กลับ เพราะ**ไม่มีด่านกัน** (พิสูจน์แล้ว: กฎ §6.8 มีมา 6 สัปดาห์ adoption ยัง 29%)

### สิ่งที่ควรทำแทน — 3 ก้าว

| ก้าว | ทำอะไร | blast radius | ได้อะไร |
|---|---|---|---|
| **1. แก้ hub + เขียนกติกา hub** | `/equipment` `/pm` `/daily-checker` ใช้ `PageHeader` · หน้าลูกที่ถูก embed ปิด breadcrumb · เขียนกติกาลง UI-CONVENTIONS §6.8 | 3 hub + ~12 หน้าลูก | **จบปัญหาที่เห็นในภาพทั้ง 3 ใบ** |
| **2. ตั้ง token กลาง** (ตามที่ user เลือก) | เพิ่ม `--radius-sm/md/lg/pill` + `--btn-pad-sm/md` ใน `index.css` · หน้าที่แตะอยู่แล้วค่อยเปลี่ยนไปใช้ token · **ไม่ sweep ทั้งระบบทีเดียว** | ต่อหน้าที่แตะ | ของใหม่ตรงกันเอง · ไม่เสี่ยงพังจุดที่ตั้งใจใช้ค่าพิเศษ (เช่น marker วงกลมบนผัง) |
| **3. ด่าน `regressionGuards`** | เพิ่มกฎ: ไฟล์ใน `src/pages` ที่ไม่อยู่ allow-list **ห้ามมี `<h2>` หัวเพจโดยไม่ import `PageHeader`** · allow-list = 7 หน้ายกเว้น + 35 หน้าหนี้เก่า แล้ว**ตัด allow-list ลงทุกครั้งที่ย้ายได้ 1 หน้า** | 0 (เทสอย่างเดียว) | **drift กลับไม่ได้อีก** · หนี้เก่าลดลงอย่างเดียว ไม่มีทางเพิ่ม |

> หลักเดียวกับที่ใช้ได้ผลแล้วกับ `fetchAllRows` / `setSearchParams` / `scoreDef` —
> **แก้บั๊ก + ใส่ด่านในคอมมิทเดียวกัน** ไม่งั้นบั๊กคลาสเดิมกลับมาเสมอ

## 5. สิ่งที่ audit นี้ **ไม่ได้** ตรวจ (ช่องว่างที่เหลือ)

- **สี/คอนทราสต์ต่อองค์ประกอบ** — ตรวจแค่ว่าใช้ CSS variable หรือ hardcode ยังไม่ได้วัดคอนทราสต์จริง
- **ความหนาแน่นข้อมูลต่อหน้าจอ** (จอ TV 43" vs มือถือ 390px) — `mobilesweep` จับแค่ "พัง" ไม่จับ "อ่านยาก"
- **empty state** — พบ 22 หน้าที่ใช้ข้อความเปล่าเป็น empty state (เช่นภาพ JIG) ยังไม่ได้ไล่ทีละจุดว่าควรมีคำแนะนำ/ปุ่มถัดไปมั้ย
- **ลำดับ/ตำแหน่งปุ่ม action** (ซ้าย-ขวา, ปุ่มหลัก-รอง) — ยังไม่มีกติกาในเอกสารเลย
