## 3) ผลวัดที่ทำไว้แล้ว — ไม่ต้องนับซ้ำ (23/09/2026)

### 3.1 🔴 ตัวกรองเพี้ยน — ต้นเหตุเดียว กระจายทั้งระบบ
`src/index.css` ตั้ง **`input, select, textarea { width: 100% }`** เป็นค่าเริ่มต้นทั้งแอป
⇒ `<select>` ในแถบกรองแนวนอนที่**ไม่สั่งความกว้างเอง จะยืดเต็มบรรทัด แล้วดันตัวอื่นตกบรรทัด**

**เคสพิสูจน์ (user ส่งภาพมาเอง) — `/report` แท็บ 🧬 4M Changes:**

| ช่อง | `src/pages/Report.jsx` | ผลบนจอ |
|---|---|---|
| ทุกส่วนงาน | `select value={fourMSection}` (~บรรทัด 1929) — ไม่กำหนด width | ยืดเต็มจอ |
| ทุกไลน์ | `LineSelect lines={fourMVisibleLines}` (~1934) — `width:'auto'` | **แคบพอดี (ถูกต้อง)** |
| ทุกประเภท | `select value={cat}` (~1937) — ไม่กำหนด width | ยืดเต็มจอ |
| ทุกสถานะ | `select value={statusFilter}` (~1941) — ไม่กำหนด width | ยืดเต็มจอ |

> เลขบรรทัดขยับได้ (มีหลาย session แก้ไฟล์นี้) — **ค้นด้วยชื่อตัวแปรในคอลัมน์กลางแทน**

**จุดที่ต้องเรียนรู้:** แท็บ "รายวัน" ของ**ไฟล์เดียวกัน**ไม่เพี้ยน เพราะใช้สไตล์กลาง `selSt`
(ค้น `const selSt` — ~`Report.jsx:2292`) ที่มีคอมเมนต์กำกับว่า *"width:auto กัน index.css select{width:100%} ยืดเต็ม toolbar"*
⇒ **เคยมีคนเจอปัญหานี้ แก้เฉพาะแท็บตัวเอง แล้วไม่ได้ทำเป็นของกลาง** แท็บอื่นเลยพังต่อ
— นี่คือเหตุผลว่าทำไมการไล่ใส่ `width` ทีละจุด **ไม่ใช่ทางแก้** (เดี๋ยวก็หลุดอีก)

**สเกลทั้งระบบ:** `<select>` ที่ไม่กำหนดความกว้าง = **260 จุด · 72 ไฟล์** (ที่กำหนดแล้ว 134 จุด)
หนักสุด: `Report.jsx` 18 · `MtnRepair.jsx` 17 · `DailyReport.jsx` 15 · `operator.jsx` 15 ·
`QualityControl.jsx` 9 · `NpiPartPanel.jsx` 8 · `NpiDrawingsEci.jsx` 8 · `PEDocs.jsx` 8

> ⚠️ **ไม่ใช่บั๊กทั้ง 260** — select ที่อยู่ในฟอร์มแนวตั้ง *ควร* เต็มความกว้างอยู่แล้ว
> ตัวที่พังคือตัวที่อยู่ใน**แถบกรอง/toolbar แนวนอน** เท่านั้น **ต้องแยกทีละจุด ห้ามไล่แก้เหมา**

สคริปต์นับซ้ำได้ (ตัวแยกแท็กแบบนับวงเล็บปีกกา — regex ธรรมดาใช้ไม่ได้ เพราะ `=>` ในพร็อพมี `>`):
```python
def open_tags(src, tag='<select'):
    i = 0
    while True:
        i = src.find(tag, i)
        if i < 0: return
        j, depth = i + len(tag), 0
        while j < len(src):
            c = src[j]
            if c == '{': depth += 1
            elif c == '}': depth -= 1
            elif c == '>' and depth == 0: break
            j += 1
        yield i, src[i:j+1]
        i = j + 1
# แท็กที่ไม่มีคำว่า width เลย = ผู้ต้องสงสัย
```

**ทิศทางที่เสนอ (ยังไม่ทำ):** ทำ component แถบกรองกลาง + คลาส CSS เดียว แล้ว**ใส่ด่านใน
`src/utils/__tests__/regressionGuards.test.mjs`** ให้ build ล่มถ้ามี select ใน toolbar ที่ไม่กำหนดความกว้าง
(pattern เดียวกับกฎอื่นที่ล็อกไว้แล้ว)

## 5) กับดักที่รู้แล้ว — อย่าเสียเวลาซ้ำ

- **ห้ามใช้ `color-mix()`** และ CSS ที่ต้องการ Chromium > 94 — จอหน้างานเป็นทีวี webOS = Cr 94
  (ตรวจก่อน merge: `grep -oF "color-mix(" dist/assets/*` ต้องได้ 0)
- **`position: sticky` พึ่ง `<main>` ใน `App.jsx` ที่เป็น `overflowX:'clip'`** — ห้ามเปลี่ยนเป็น `hidden`/`auto`
- **grid ที่อาจสูงกว่าเนื้อหา ต้องใส่ `alignContent:'start'`** ไม่งั้นการ์ดถูกยืด
- **ฟอนต์ขั้นต่ำ 11–12px** (จอ TV) — อย่าใช้ 8–9px แม้พื้นที่จะแน่น
