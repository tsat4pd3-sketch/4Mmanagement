## 1. สูตรจริงใน Excel (ถอดจาก formula ไม่ใช่เดาจากตัวเลข)

แถวข้อมูล = 1 แถว/กะ (row 13-74) ทุกแถวใช้สูตรชุดเดียวกัน:

```
BY = IF(B>0, SUM(AY:BX), "")        ← รวม "เวลาสูญเสียในแผน"
CX = IF(B>0, SUM(BZ:CW), "")        ← รวม "เวลาสูญเสียนอกแผน"
CY = IF(B>0, (T*60+U) - BY, "0")    ← เวลารับภาระ = ช่วงผลิต − ในแผน
DD = 1 - (CX/CY)                    ← %A
DE = Z / ((CY-CX)/AF)               ← %P    (AF = STD TIME นาที/ชิ้น)
DF = AA/Z                           ← %Q
DG = DD*DE*DF                       ← %OEE
AG = 60/AH                          ← STD TIME = 60 / JPH เป้าหมาย
DR = AVERAGEIF($D:$D,"<ชื่อหัวหน้า>",$DD:$DD)   ← สรุปรายหัวหน้า = เฉลี่ยธรรมดา
```

คอลัมน์ `AY..BX` (ในแผน) มี **ประชุมแถว+PPM 08:00-08:30 (30) · พัก 10 · พักเที่ยง 50 · พัก 10 ·
5ส · พัก OT 30 · ประชุมแถว OT · พักดึก 50 ฯลฯ** รวมอยู่ครบ

> ### ⚠️ แก้คำพูดที่เคยบอก user ผิด (2026-09-08)
> เคยสรุปว่า **"Excel ไม่หักเบรค"** จากการถอดย้อนจากตัวเลข — **ผิด**
> อ่าน formula จริงแล้ว `CY = (T*60+U) − BY` และ `BY` รวมพักทุกช่วง ⇒ **Excel หักเบรคเหมือนระบบ**

## 3.4 📊 แก้ CT แล้ว "ตรงแค่ไหน" — จำลองรายกะทั้งเดือน (2026-09-10)

user ถามตรงๆ ว่า *"สรุป OEE จะตรงกันรึ แค่แก้ CT ใช่มั้ย"* → จำลองว่าถ้าปิดกะใหม่ด้วย CT 54 วิ
(+ การจับกลุ่ม product ที่แก้แล้ว) ระบบจะ stamp เท่าไหร่ แล้วเทียบ Excel รายกะ:

| | FG297 (Assy GOR) | FG306 (Assy LWR) |
|---|---|---|
| OEE ทั้งเดือน Excel | 70.88 | 71.44 |
| OEE ทั้งเดือน **ระบบหลังแก้ CT** | 69.22 | 70.59 |
| **Δ ทั้งเดือน** | **−1.67 จุด** | **−0.85 จุด** |
| \|Δ\| รายกะเฉลี่ย | 1.97 จุด | 1.61 จุด |
| กะที่อยู่ในกรอบ ±2 จุด | 26/41 | 31/38 |
| ยังชนเพดาน P = 100% | 3 กะ | 0 กะ |

⇒ **CT คือตัวหลักจริง แต่ไม่ได้ทำให้ "ตรงเป๊ะ"** — เหลือต่างราว **1 จุดที่ระดับเดือน**
ตัวที่เหลือคือ **ฐานเวลา (loading) ต่างกัน ~8-10 นาที/กะ** จากนิยามพักที่ต่างกัน (§2.1)
ไม่ใช่ความผิดพลาดของฝั่งไหน — และแก้ให้เท่า Excel แล้ว **A จะต่ำกว่า Excel แทน** (over-correct)

> ### ⚠️ อย่าอ่านตัวเลข "0.10 / 0.65 จุด" ใน §3.1 ผิด
> ตัวเลขนั้นคำนวณ %P ของระบบโดยใช้ **run time ของ Excel เป็นตัวหาร** — ตอบคำถามว่า
> *"ในสูตร P มีอะไรต่างนอกจาก CT ไหม"* (คำตอบ: ไม่มี) **ไม่ใช่** ตัวเลขที่จะเห็นจริงบนจอ
> พอใช้ run time ของระบบเอง (ฐานเวลาต่างกัน ~8-10 นาที/กะ) %P จะต่างจาก Excel ~2-3 จุด
> **บทเรียน: ตอบ "แม่นแค่ไหน" ต้องจำลองทั้งสูตรด้วยอินพุตของระบบเอง ห้ามยืมตัวหารของอีกฝั่งมา**

> ### ⚠️ กับดักตัวเลข — ห้าม back-solve `loading` จาก %A ที่ stamp ไว้
> `loading = unplanDT / (1 − A)` **ระเบิดเมื่อ A เข้าใกล้ 100%** (A = 99.09 กับ DT 10 นาที
> ให้ฐาน 1,099 นาทีบนกะ 570 นาที) ทำให้จำลอง %P ได้ 35% ทั้งที่จริง ~99%
> ให้คำนวณตรงเหมือนโค้ด: **`loading = shift_min − พักตามนโยบาย − DT ในแผน`** เสมอ
> (โมเดลนี้ reproduce %A ที่ stamp ไว้ได้คลาดเฉลี่ย 1.3 / 1.8 จุด — ใช้ประเมินได้ แต่ไม่ใช่ค่าเป๊ะ)
